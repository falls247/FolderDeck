# FolderDeck

登録したフォルダをカードで並べ、マウスを乗せていくだけでサブフォルダの中身を何階層でもたどれる Windows ネイティブアプリです。表示されたファイルはクリックで開けます。

- タブ：「登録フォルダ」「最近の履歴」「よく使う項目」（どれも同じカード表示）
- カードにホバー → サムネイル部分に第1階層の一覧（オーバーレイ）→ フォルダ行に止まると横にフライアウト → さらに次の階層…
- フォルダはアプリ内で移動、ファイルは既定のアプリで開く。右クリックで「エクスプローラーで表示」「パスをコピー」「ピン留め」、フォルダの中の項目は「削除（ごみ箱へ移動）」など
- 一覧の行に止まると、画像・PowerPoint・Word・Excel・テキストなどを横にプレビュー
- カードはタブごとに並べ替え（手動／名前／更新日）。各タブの最上位ではドラッグで順番を入れ替えられる。ピン留めしたカードには左下に 📌（クリックで解除）
- カードの形は縦長（サムネイル 3:4）と正方形（サムネイル 1:1）をツールバーのボタンで切り替え（全タブ共通）
- カード・一覧の行・プレビューは、ほかのアプリへドラッグ＆ドロップで渡せる（PowerPoint に画像を落とすと図として挿入、エクスプローラーに落とすとコピー）

## 必要な環境

- Windows 10 22H2 / Windows 11（x64）
- 開発：.NET SDK 10（`dotnet --list-sdks` で 10.0.x が出ること）
- 配布物（single-file exe）を動かすだけなら .NET のインストールは不要です（self-contained）

## よく使う操作（BAT・ダブルクリック可）

リポジトリのフォルダにある BAT を、エクスプローラーからダブルクリックするか、ターミナルから実行します。

| BAT | 内容 |
|---|---|
| `build.bat [Debug\|Release]` | ソリューションをビルド（既定 Debug） |
| `test.bat [追加の引数]` | Core のテスト（例：`test.bat --filter Ranking`） |
| `run.bat [アプリへの引数]` | Debug ビルドして起動（例：`run.bat --data-dir E:\tmp\data`） |
| `build-test-run.bat [アプリへの引数]` | ソリューションを Debug ビルド → Core のテスト → 起動 を続けて実行。失敗した段階で止まる（引数は `run.bat` と同じ。例：`build-test-run.bat --data-dir E:\tmp\data`） |
| `publish.bat` | 配布用の single-file exe を作り、`dist\FolderDeck.exe` にコピー |

- ダブルクリックしたときは、最後に「Enter キーで閉じます」で止まるので結果を読めます（`run.bat` / `build-test-run.bat` が成功したときはアプリが出るので止まりません）。ターミナルから実行したときは止まりません。
- 終了コードを返すので、ほかのスクリプトからも呼べます（成功 0、失敗 1、引数の誤り 2）。
- これから上書きするフォルダ（`bin\Debug`、`bin\Release`、`publish`、`dist`）から FolderDeck が起動していると exe がロックされてビルドできないため、「閉じて続けますか？ [Y/n]」と聞いてから普通に閉じます（閉じるときに状態は保存されます）。ほかの場所から起動している FolderDeck には触れません。
  - 入力できない実行（ほかのツールから呼んだときなど）では、閉じずに中止します。確認なしで閉じてよいときは、環境変数 `FOLDERDECK_AUTOCLOSE=1` を設定してください。
- FolderDeck は1つしか起動できません。ほかの場所（`dist\` など）の FolderDeck が起動していると、`run.bat` / `build-test-run.bat` は新しいビルドを起動できない（既存のウィンドウが前に出るだけで `--data-dir` も効かない）ため、ビルドせずにその旨を表示して終了します。そちらを閉じてから実行してください。
- `test.bat` などへの追加の引数は、`-tl:off` や `-p:Name=Value` のような形もそのまま dotnet に渡ります。
- `build-test-run.bat` は、ビルド（Debug・ソリューション全体）→ テスト（1 でビルド済みのものを `--no-build` で実行）→ 起動（`run.bat` と同じ）を一度に行います。途中で失敗するとそこで止まり、「テストで失敗しました。起動はしません。」のように、どの段階で失敗したかを表示します。引数はすべてアプリに渡されます（テストを絞り込みたいときは `test.bat --filter ...` を使ってください）。`tools\dev.ps1` では `all`（別名 `build-test-run`）というタスクです。
- 中身は `tools\dev.ps1` にまとめてあります（BAT はそれを呼ぶだけ）。BAT を英数字だけにしてあるのは、文字コード（コードページ 932 / 65001）が違う環境でも文字化けせずに動かすためです。`tools\dev.ps1` を編集したら UTF-8（BOM 付き）で保存してください。

## ビルド・テスト・起動（コマンドで直接）

リポジトリのフォルダ（このファイルがある場所）で実行します。

```powershell
dotnet build FolderDeck.sln -c Debug
```

```powershell
dotnet test tests/FolderDeck.Core.Tests -c Debug
```

```powershell
dotnet run --project src/FolderDeck.App
```

### 配布用の exe を作る

```powershell
dotnet publish src/FolderDeck.App -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
```

出力は `src\FolderDeck.App\bin\Release\net10.0-windows\win-x64\publish\FolderDeck.exe` の **1ファイルだけ**です（約 150 MB）。`publish.bat` を使うと、同じものが `dist\FolderDeck.exe` にもコピーされます。
ReadyToRun（事前コンパイル）を有効にしてあり、起動を速くしています。

> 新しくビルドした exe を初めて起動するときは、ウイルス対策ソフトのスキャンで 30 秒ほどかかることがあります（この環境で計測）。2回目からは約 1.4 秒で最初の画面が出ます。

## データの置き場所

`%LOCALAPPDATA%\FolderDeck\`

| ファイル | 内容 |
|---|---|
| `registered_folders.json` | 登録フォルダ（imgtool と同じ形式）。`folders` 配列の順番が登録フォルダの「手動」の並び |
| `history.json` | 利用記録（最近の履歴・よく使う項目の元データ） |
| `pins.json` | ピン留め |
| `excluded.json` | 最近の履歴から外した項目 |
| `card_order.json` | 最近の履歴・よく使う項目をドラッグで並べた順（`{ "version": 1, "recent": [パス…], "frequent": [パス…] }`、各 1000 件まで） |
| `settings.json` | 設定、ウィンドウ位置、各タブの現在地、カードサイズ、カードの形（`card_shape`：`portrait`／`square`）、タブごとの並び方（`sort_modes`） |
| `logs\app.log` | ログ（5 MB で `app.log.1` に切り替え） |
| `logs\session.json` | 起動中だけある記録（1 分ごとに更新）。次の起動時に残っていれば「前回は正常に終わらなかった」と判断する |

- 書き込みは一時ファイル経由で置き換えます。壊れた JSON は `<名前>.broken-<UNIX秒>.json` に退避し、空のデータで続けます。
- このアプリがファイルやフォルダを消すのは、右クリックの「削除（ごみ箱へ移動）」を確認ダイアログで承認したときだけです（ごみ箱へ移すだけで、完全には削除しません。下の「削除（ごみ箱へ移動）」）。それ以外でファイルの削除・移動・上書きはしません。

### 勝手に終了したときの調べ方

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\analyze-log.ps1 -Events
```

ログを起動ごとに分けて、いつ起動してどう終わったかを表示します（`-Last 30` で件数、`-LogDir` で `--data-dir` のログも見られます）。
アプリは開始・終了と閉じた理由を `lifecycle:` で始まる行に書きます。

| 終わり方の表示 | 意味 |
|---|---|
| ユーザーが閉じた | × ボタン、Alt+F4、タスクバーから閉じた |
| 別のプログラムが閉じた（WM_CLOSE） | ほかのプログラムがウィンドウを閉じさせた（ビルドスクリプトの `CloseMainWindow`、`/F` なしの `taskkill`、インストーラーなど） |
| Windows のセッション終了で閉じた | サインアウト・シャットダウン・更新（Restart Manager） |
| クラッシュ（未処理の例外） | 例外の内容がログに残っています |
| 異常終了 | 終了処理が走っていない。次の起動時に、イベントログ（Application）の FolderDeck.exe のクラッシュ記録も調べて書き出します。記録がなければ強制終了（`taskkill /F`、タスクマネージャー）か電源断 |

## 操作

| 操作 | 動作 |
|---|---|
| カードをクリック | フォルダなら中へ移動、ファイルなら開く |
| カードにホバー（0.3 秒） | 子項目の一覧（オーバーレイ） |
| フォルダ行に止まる（0.15 秒） | 横に次の階層（フライアウト）。何階層でも続く |
| 画像・Office・テキストなどの行に止まる（0.15 秒） | 横にプレビュー（下の「プレビューできるファイル」）。クリックで開く。↑ ↓ で選んでも出る |
| ↑ / Backspace | 1つ上へ |
| マウスの戻る・進む / Alt + ← → | 移動の履歴 |
| F5 | 更新（キャッシュも読み直す） |
| Ctrl + ホイール | カードの大きさ（120〜400） |
| カスケード表示中の ↑ ↓ → ← Enter Esc | 行の選択、子を開く、閉じる、開く、いちばん深い階層を閉じる |
| エクスプローラーからフォルダをドロップ | 登録（登録フォルダの最上位で） |
| 各タブの最上位でカードをドラッグ | 一覧の中で離すと順番の入れ替え（下の「並べ替えとピン留め」）。ウィンドウの外のアプリで離すと、そのアプリにファイル・フォルダを渡す |
| カード（フォルダの中）・一覧の行・プレビューをドラッグ | ほかのアプリにファイル・フォルダを渡す（下の「ほかのアプリへドラッグで渡す」） |
| ツールバーの並べ替えボタン | 手動／名前（昇順・降順）／更新日（昇順・降順）をタブごとに切り替え |
| ツールバーのカードの形ボタン（並べ替えボタンの右） | 縦長（サムネイル 3:4）／正方形（サムネイル 1:1）を切り替え。全タブ共通で、`settings.json` に保存 |
| カードの 📌 をクリック | ピン留めを外す |
| フォルダの中のカード・一覧の行を右クリック →「削除（ごみ箱へ移動）」 | 確認のうえ、ごみ箱へ移動（下の「削除（ごみ箱へ移動）」） |

実行形式（`.exe .bat .ps1` など）を開く前には確認が出ます（設定で OFF にできます）。

### 削除（ごみ箱へ移動）

- 右クリックメニューの「削除（ごみ箱へ移動）」は、フォルダの中の項目にだけ出ます：タブの最上位から開いたフォルダの中のカード、オーバーレイ・フライアウトの行、行のプレビュー。各タブの最上位のカード（登録フォルダそのもの、履歴の項目）と、フライアウトの見出しには出ません。見つからない・応答がない項目では選べません。
- 選ぶと必ず確認ダイアログが出ます（既定のボタンは「キャンセル」で、Enter だけでは削除されません）。フォルダは中のファイル・フォルダごとごみ箱へ移します。
- エクスプローラーの Delete と同じ仕組み（`IFileOperation`）でごみ箱へ移すので、ごみ箱から元に戻せます。大きなフォルダでは Windows の進行状況の画面が、使用中のファイルなどでは Windows のダイアログが出ます。
- **完全な削除はしません**。ごみ箱に入れられない項目（ネットワーク上のフォルダ、WSL のフォルダなど、Windows がごみ箱に入れずに完全に削除しようとする項目）は、何も消さずに中止し、「ごみ箱に移動できない場所にあるため、削除しませんでした。」と表示します。
- 終わったら、表示中の一覧を読み直します（スクロール位置はそのまま）。ほかのタブは次に開いたときに読み直します。ピン留めや利用記録は消しません（存在しない項目として扱われ、同じ場所にまた現れれば再び表示されます）。

### 並べ替えとピン留め

- ピン留めした項目のカードには、どのタブでも（フォルダの中のカードも）左下に 📌 が出ます。サムネイルに重なる一覧（オーバーレイ）とは重ならないので、ホバー中も表示されたままです。📌 をクリックするとピン留めを外せます（右クリックの「ピン留めを外す」と同じ。見つからない・応答がない項目は除く）。
- ツールバーの並べ替えボタン（カードの形ボタンの左）で、「手動（ドラッグで並べた順）」「名前（昇順）」「名前（降順）」「更新日（昇順）」「更新日（降順）」を選べます。
  - 並び方はタブごとに保存され、そのタブの最上位と、そのタブで開いたフォルダの中の両方に効きます。
  - 名前はエクスプローラーと同じ自然順（2 が 10 より前）。更新日が分からない項目（応答がないものなど）は、どちらの向きでも最後です。
  - 「手動」のとき、最上位はドラッグで並べた順、フォルダの中は今まで通りの順（フォルダ→ファイル、名前順）です。フォルダの中では、どの並び方でもフォルダがファイルより先に来ます。
  - 登録フォルダの「更新日」順は、存在確認（最大 2 秒）が終わってから並び替わります。
- **ピン留めした項目は位置が動きません**。名前順・更新日順にしても、ピン留めしたカードは「手動」の並び（フォルダの中では既定の並び）での位置にとどまり、ピン留めしていないカードだけが空いている位置に順に入ります。
  - 例：手動の並びが [A, B📌, C, D📌, E] のとき「名前（降順）」にすると [E, B📌, C, D📌, A]。
  - 名前順・更新日順の最上位でピン留めすると、カードは表示中の位置のまま固定されます（「手動」の並びの中でそのカードだけを表示中の位置へ移し、ほかのピン留めカードの位置やほかのカードの順は変えません）。登録フォルダではこの移動を `registered_folders.json` に保存します。最近の履歴・よく使う項目では、ドラッグで並べたことがある（`card_order.json` に並びがある）ときだけ保存し、そうでなければ次に読み込み直したとき（タブの切り替え、F5 など）にそのカードは元の並びでの位置（よく使う項目では先頭のピン留めの並び）へ移ります。
  - ピン留めを外すと、そのカードは並べ替えた位置へ移ります。
- **ドラッグで並べ替え**：3 つのタブの最上位でだけ、カードをドラッグして順番を入れ替えられます（フォルダの中と読み込み中はできません）。
  - 入る位置にアクセント色の縦線が出ます（カードの左半分＝その前、右半分＝その後ろ、カードの間の隙間＝縦線の位置、最後のカードより後ろの空き＝末尾）。上端・下端に近づけると自動でスクロールします。Esc か、ウィンドウの中の一覧の外（ツールバーなど）で離すと取り消しです。
  - 同じドラッグでウィンドウの外（エクスプローラー、PowerPoint、デスクトップなど）まで運んで離すと、並びは変わらず、そのアプリにファイル・フォルダを渡します（下の「ほかのアプリへドラッグで渡す」）。
  - 名前順・更新日順のときにドラッグすると、その時点の表示順のまま「手動」に切り替わり、「並び順を「手動」に切り替えました。」と表示されます。
  - 最近の履歴・よく使う項目で並べたあとに新しく加わった項目は、元の並び（新しい順・よく使う順）で直前にある項目のすぐ後ろに入ります（前に何もなければ先頭）。並べた項目は、開き直しても先頭には移りません。
  - 元の並び（新しい順・よく使う順）に戻したいときは、並べ替えメニューの最後の「手動の並びをリセット」を選びます（最近の履歴・よく使う項目だけ。ドラッグで並べたことがあるときに選べます。確認なしで `card_order.json` からそのタブの並びを消します）。登録フォルダには出ません（手動の並びが登録の順そのもののため）。

### ほかのアプリへドラッグで渡す

カード、一覧（オーバーレイ・フライアウト）の行、プレビューをドラッグして、ほかのアプリに落とせます。エクスプローラーからドラッグしたときと同じ形式（ファイルのパスの一覧）で渡します。

- 例：PowerPoint で編集中のスライドに画像のカードや行を落とすと、図として挿入されます。エクスプローラーのフォルダに落とすとコピーされます。
- **コピーかショートカットだけで、移動にはなりません**（同じドライブのエクスプローラーに落としても、Shift を押しながら落としても移動しません。Shift のときは受け付けられません）。ドラッグで元のファイルやフォルダを動かさないためです。ショートカットの作成（リンク）は許可しているので、受け取る側が対応していれば作れます（エクスプローラーでは Alt を押しながら落とす）。
- フォルダもドラッグできます。どう扱うか（コピーする、開く、受け付けない）は受け取る側しだいです。フォルダごとコピーされるので、大きなフォルダをデスクトップなどに落とすとコピーが始まります（エクスプローラーのコピー画面で取り消せます）。
- 見つからない・応答がないカードはドラッグできません。
- ボタンを押したまま、システムのドラッグ距離（既定 4 ピクセル）より動かすとドラッグになります。ドラッグしたあとはクリックとして扱わない（ファイルを開かない・フォルダに移動しない）ので、手がぶれて少し動いたときはそのまま離しても何も起きません。
- ドラッグを始めると、開いていた一覧（オーバーレイ・フライアウト）とプレビューは消えます（落とす先を隠さないため）。
- FolderDeck のウィンドウの上で離しても何も起きません（フォルダの登録にもなりません）。最上位のカードを一覧の中で離したときだけ並べ替えになります。

### プレビューできるファイル

一覧（オーバーレイ・フライアウト）の行に 0.15 秒止まるか ↑ ↓ で選ぶと、横にプレビューが出ます。クリックで開きます。

| 種類 | 表示 |
|---|---|
| 画像 | これまでどおり |
| PowerPoint（.pptx .pptm .ppsx .ppsm .potx .potm） | 表紙（シェルのサムネイル、なければファイルに保存された縮小版） |
| Word（.docx .docm .dotx .dotm） | 本文の先頭（最大 40 段落・4,000 文字）。見出し・表題は太字。変更履歴で削除された文字、フィールドコード、テキストボックス、ヘッダー・フッター・脚注・コメントは出しません |
| Excel（.xlsx .xlsm .xltx .xltm） | ブックの並び順で最初の表示中のシートの、左上 30 行 × 12 列（列の A B C… と行番号つき）。数値は一般形式、日付・時刻の書式のセルは yyyy/MM/dd などで表示。通貨・桁区切り・色・罫線・セル結合は再現しません |
| テキスト（.txt .log .md .csv .json .xml .yaml .ini .cs .py .js .ts .ps1 .bat .sql .html .css .xaml など） | 先頭 60 行（最大 64 KB）を等幅フォントで。文字コードは BOM（UTF-8 / UTF-16）→ UTF-8 → Shift_JIS の順に判定。中身がバイナリなら文字では出しません |
| そのほか Windows がサムネイルを作れる形式 | シェルのサムネイル。動画（.mp4 .mov .wmv .avi .mkv .webm など）は常に対象。PDF・SVG・PSD・音楽ファイルなどは、サムネイルを作るアプリが入っていれば対象。画像を作れなかったとき（ジャケット画像のない音楽ファイルなど）は何も出しません |

- 続きがあるときや枠に入りきらないときは、下に「（以下省略）」が出ます。プレビューの中はスクロールしません。
- Word・Excel は本文を読めなかったとき（本文がない、パスワード付きなど）、シェルのサムネイルかファイルに保存された縮小版を出します。旧形式の .doc / .xls / .ppt と .xlsb は中身を読みません。
- 実行ファイル・ショートカット（.exe .dll .lnk .url .msi など）は対象外です。
- OneDrive の「オンラインのみ」のファイルなど、開くとダウンロードが始まるファイルは、Word・Excel・テキストの中身もファイルに保存された縮小版も読みません（ファイル属性だけで判定するので、プレビューのためにダウンロードされることはありません）。ダウンロード済みのファイルは普通にプレビューされます。
- カードのサムネイルも、Word・Excel は PowerPoint と同じく、シェルのサムネイルがなければファイルに保存された縮小版を使います（Word / Excel で「縮小版を保存する」をオンにして保存したファイルだけにあります）。

### 設定

| 項目 | 内容 |
|---|---|
| エクスプローラーで表示するとき、開いているエクスプローラーに新しいタブで開く（Windows 11） | 既定はオフ。オンにすると、右クリックの「エクスプローラーで表示」が、いちばん手前のエクスプローラーのウィンドウに新しいタブを追加して開きます（親フォルダを開いて項目を選択）。エクスプローラーが開いていない、別の仮想デスクトップにしかない、Windows 11 22H2（ビルド 22621）より前、などのときは新しいウィンドウで開きます |

- 新しいタブを開くには、エクスプローラーの公開されていないコマンド（`WM_COMMAND 0xA21B`）を使っています。今後の Windows Update で動かなくなった場合は、約 2 秒待ってから新しいウィンドウで開く動作に戻ります。どちらで開いたかとその理由は `logs\app.log` に記録されます。
- 1 回のクリックでタブとウィンドウの両方が開くことはありません。新しいタブを頼んだのに確認できず、エクスプローラーが応答しない（あとから遅れてタブができるかもしれない）ときは、新しいウィンドウは開かずに「エクスプローラーの新しいタブでフォルダを開けませんでした。」と表示します（このときタブがホームのまま遅れて現れることがあります）。
- 「データフォルダを開く」は設定に関係なく新しいウィンドウで開きます。
- 以前あった「imgtool の登録フォルダを取り込む」は削除しました（`registered_folders.json` の形式は imgtool と同じままです）。

## 実装メモ

- **カードグリッド**：`VirtualizingWrapPanel`（MIT、net10.0-windows 対応を確認済み）は使わず、カードを「列数ぶんの行」にまとめて `VirtualizingStackPanel` で仮想化しています。列数（`max(1, floor((幅 + 12) / (サイズ + 12)))`）とカード幅（`(幅 − 12 × (列数 − 1)) / 列数`）の式をそのまま再現するためです。
- **フライアウトの位置**：WPF の `Popup` を使い、位置は行が載っているモニターの作業領域と拡大率から物理ピクセルで計算して、ウィンドウを直接その位置へ動かしています（拡大率の違うモニターでもずれないようにするため。`CustomPopupPlacementCallback` の代わり）。
- **フォルダのサムネイル**：シェルのフォルダサムネイルの一部は「非乗算済みアルファ」の画像として返るため、色とアルファから判定して正しく透過表示しています。四隅が不透明な（四角い背景つきの）画像はアイコン表示に切り替えます。
- **シェル画像の上下**：シェルが返すビットマップは、サムネイルは上から、アイコンは下から並んでいるのに、どちらも「下から」と報告されます。そのため `GetDIBits` に上から並べ直させて読みます（報告を信じて反転すると、サムネイルが上下逆になる）。
- **PowerPoint の表紙**：シェルのサムネイル（Office が入っていれば出る）がなければ、ファイルの中に保存されている表紙のサムネイル（`docProps/thumbnail.jpeg`、PowerPoint は既定で保存する）を使います。これがないファイル（ほかのツールで作ったものなど）はアイコンのままです。横長なので、カードでは切り抜かずに全体を収めます。
- **メッセージ行**：壊れたデータファイルを退避したときの通知用に「警告」（エラーと同じく次の操作まで残る）を追加しました。
- **長いパス**：シェル API で開けないときは 8.3 形式の短いパスでも試します。
- **キーボード**：カスケードが開いているあいだの ↑ ↓ → ← Enter Esc に対応しています。カードにフォーカスを置いてキーボードだけでオーバーレイを開く機能（任意）は未対応です。
- **Office・テキストのプレビュー**：Office をインストールしていなくても読めるよう、ファイル（zip）の中の XML を必要な部分だけ読んで文字や表にしています。共有モードで開くので Office で編集中でも読めます。展開は 1 回 32 MB まで（zip 爆弾対策）、DTD は禁止、シートは 30 行目を読んだら止め、共有文字列は必要な番号までしか読みません。読み取りは裏のスレッドで行い 5 秒で打ち切り、直近 32 件は覚えておきます。「Windows がサムネイルを作れるか」は拡張子ごとに一度だけ問い合わせます（`AssocQueryString` で IThumbnailProvider の登録を確認）。
- **並べ替え**：「ピン留めは位置を固定」「新しく加わった項目は元の並びで直前の項目の後ろ」の規則は Core（`Ordering/`）の純粋な関数にしてテストしています。最上位の更新日は、存在確認と同じ 1 回の呼び出しで取得しています（タイムアウトも同じ）。
- **ほかのアプリへのドラッグ**：`DragDrop.DoDragDrop` で `DataFormats.FileDrop`（パスの配列。エクスプローラーと同じ CF_HDROP）を渡し、許可する効果は Copy | Link だけです（Move は渡さない）。260 文字以上のパスは 8.3 形式の短いパスにして渡します（短いパスが作れないボリュームでは長いまま）。
  - 最上位のカードは、1 回のドラッグに並べ替え用の内部形式（`FolderDeck.CardReorder`）と FileDrop の両方を載せます。グリッドの上では並べ替えとして Copy を返し、カーソルは普通の矢印に差し替えます（コピーの「＋」を出さないため）。
  - アプリ自身が始めたドラッグには内部形式 `FolderDeck.DragSource` を載せ、ドラッグ中のフラグも立てます。ウィンドウのフォルダ登録（`MainViewModel.RegisterDroppedAsync`）はそのどちらかがあれば受け付けません。
  - クリックとの区別は `SystemParameters.MinimumHorizontalDragDistance` / `MinimumVerticalDragDistance` を「超えたら」ドラッグ（カード・行・プレビュー共通、Core の `FileDrag.IsDragGesture`）。ドラッグを始めたら押下の記録を消すので、離してもクリックになりません。ダブルクリックの 2 回目の押下を無視する既存の処理はそのままです。
  - **カスケードは「開始時に消す」**：開いていた一覧とプレビューはドラッグ開始と同時に見えなくし、ホバーのタイマー（open / exit / grace / preview など）はすべて止めます。理由は、(1) フライアウトとプレビューは最前面のポップアップなので、残すと落とす先（スライドやフォルダ）を隠す、(2) タイマーは DoDragDrop のモーダルループの中でも動くのに、判定に使うポインター位置（IsMouseOver、ホバー中の行）は更新されないため、ドラッグ中に勝手に開閉してしまう、の 2 点です。ただしポップアップのウィンドウは中身を非表示にする（透明になり、ポインターもドロップも通り抜ける）だけで、破棄はドラッグが終わってからです。ボタンを押したポップアップをボタンを押したまま破棄すると、DoDragDrop がボタンを離したことに気づかず、次にクリックするまでドラッグが続いてしまうことを実機で確認したためです。同じ理由で、ドラッグ中に届いた「全部閉じる」（ウィンドウの非アクティブ化、自動スクロールなど）は無視し、終わったときにまとめて閉じます。ドラッグ元（DoDragDrop に渡す要素）はメインウィンドウか、並べ替えのときはカードグリッドで、どちらもドラッグ中に破棄されません。渡すパスは開始前に取り出しておきます。
  - ドラッグ中のサムネイル表示（`IDragSourceHelper`）は見送りました。ドラッグ画像はヘルパーがデータオブジェクトに独自の形式を書き込む（COM の `SetData`）仕組みで、アプリが作った WPF の `DataObject` はこれを受け付けない見込みのため（未検証）、独自の COM `IDataObject` の実装（HGLOBAL の複製・解放の管理を含む）が必要になり、受け渡しの形式や自分のウィンドウでの判定（並べ替え・登録の除外）も作り直しになるためです。今はシステムの標準カーソル（コピー・リンク・禁止）だけが出ます。
  - **既知の制約**：権限レベルが違うアプリの間（UIPI。例：管理者として実行したアプリと通常の FolderDeck）ではドロップできません。画像以外のファイルを PowerPoint などに落としたときの扱い（オブジェクトとして埋め込む、リンクする、受け付けないなど）は受け取る側しだいです。
  - ドラッグの結果は `logs\app.log` に `drag-out: <ドラッグ元>, effect <効果> (<ミリ秒> ms)` として記録します（パスは書きません）。
- **未対応（P2・任意）**：フォルダの中でのドラッグによる並べ替え、フォルダへのショートカットの展開、安全三角形、「プログラムから開く」ダイアログ、Recent フォルダの監視。
