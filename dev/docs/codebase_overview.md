## 1. 全体像

- WPF + .NET 10（`net10.0-windows`、x64）、C#（`LangVersion latest`、`Nullable enable`、`ImplicitUsings enable`。共通設定は `Directory.Build.props`）
- パッケージ：CommunityToolkit.Mvvm 8.4.2（`[ObservableProperty]` / `[RelayCommand]` のソース生成）、Microsoft.Windows.CsWin32 0.3.371（各プロジェクトの `NativeMethods.txt` から P/Invoke を生成）、テストは xUnit 2.9.3
- 配布：single-file exe（ReadyToRun）。`publish.bat` → `dist\FolderDeck.exe`（self-contained・圧縮 `EnableCompressionInSingleFile`、約 65 MB）、`publish.bat uncompressed` → `dist\uncompressed\FolderDeck.exe`（self-contained・圧縮なし、約 145 MB）、`publish.bat framework` → `dist\framework-dependent\FolderDeck.exe`（.NET 10 デスクトップ ランタイムが必要、約 3.5 MB）。`publish-all.bat` はこの 3 つを続けて作る。圧縮は csproj で `SelfContained == true` のときだけ有効（uncompressed は引数で切る）。self-contained の ReadyToRun は SDK の既定で composite（`FolderDeck.r2r.dll` に .NET ごとまとめる）、framework-dependent は非 composite で、中間出力のフォルダを共有するため csproj の `FolderDeckInvalidateR2ROnModeChange` が切り替え時に作り直させる（[§7](#7-守ること落とし穴)）。WPF はトリミング非対応のため使わない

### 1.1 プロジェクトと依存方向

```
src/FolderDeck.App   WPF（exe 名 FolderDeck、名前空間 FolderDeck.*）
   │  参照
   ▼
src/FolderDeck.Core  UI 非依存のロジック（名前空間 FolderDeck.Core.*）。WPF を参照しない
   ▲  参照（InternalsVisibleTo あり）
tests/FolderDeck.Core.Tests  xUnit。Core のみ。App 層の自動テストはない
```

- ロジックは Core に置き、純粋関数にしてテストする方針（並べ替え・ランキング・パス・保存・プレビュー用の読み取りなど）。App は WPF とシェル連携に限る。
- 大きいファイル（全文を読まず `// ---- 見出し ----` の区切りで目的の節だけ読む）：`Views/CascadeController.cs`（約 1,560 行）、`ViewModels/MainViewModel.cs`（約 1,430 行）、`Core/Listing/SheetReader.cs`（約 820 行）、`Shell/ExplorerTabs.cs`（約 750 行）、`ViewModels/TabViewModel.cs`（約 630 行）、`Views/CardGrid.xaml.cs`（約 590 行）

### 1.2 起動と終了（`App.xaml.cs`）

1. `SingleInstance.Acquire()`：2 つ目の起動は既存ウィンドウを前面に出す合図を送って終了（名前付き Mutex + イベント）
2. `--data-dir` を解析（既定 `%LOCALAPPDATA%\FolderDeck`）→ `AppLog.Initialize` → `SessionMonitor.Start`（前回の異常終了を報告）→ `UiWatchdog.Start`（UI スレッドの応答なしをログへ）
3. `ThemeManager.Apply`（ストアを読んだあと、ウィンドウを作る前に設定のテーマで再適用し、続けて `TextScale.Apply`（文字の大きさ）。[§3.9](#39-テーマと文字の大きさ)）
4. `DataStores.LoadAll` を `Task.Run` で実行（UI スレッドで JSON を読まない）
5. `AppServices` → `MainViewModel` → `MainWindow` → `RestorePlacement` → `Show`
6. 各ストアの `SaveFailed` をメッセージ行のエラーに接続、`ReportLoadProblems`（`Recovered` は警告、`Failed` はエラー）
7. `MainViewModel.InitializeAsync`：タブ列（`open_tabs`：各タブの種類と現在地を並び順どおりに）とサイドバーの登録フォルダ（`RefreshRegistered`）を復元し、表示していたタブ（`selected_tab`）を読み込む。タブが 1 つも無ければ何も読み込まない（`NoTab`）。旧形式（version 1）の `settings.json` はストアの読み込み時に移行済み（[§3.8](#38-永続化)）。サイドバーの幅（`sidebar_width`）は `MainWindow` のコンストラクタが表示前に列へ設定する

終了（`OnExit`）：`Stores.FlushAll` → 各サービスの `Dispose` → `UiWatchdog.Dispose` → `SessionMonitor.MarkCleanExit`。
未処理例外：UI スレッドと未監視タスクはログ＋ダイアログ（5 秒に 1 回まで）で継続、`AppDomain` の例外はログを書いて終了。

### 1.3 オブジェクトの所有関係

```
App
├─ AppServices（合成ルート。全 ViewModel で共有）
│   ├─ Stores: DataStores ─ Registered / History / Pins / Excluded / Settings / CardOrders
│   ├─ Listings: FolderListingCache（TTL 60 秒・1,500 件・項目の合計 200,000 件・期限切れは TTL に 1 回掃除・VolumeThrottle）
│   ├─ Covers: TtlCache<フォルダ, カバー画像パス>（"" = なし）
│   ├─ Thumbnails: ThumbnailService（シェル用 STA ワーカー 4 本 + 画像デコード用ワーカー（コア数 − 1 本）・1 回 5 秒・LRU 512 件 / 192 MB）
│   │   └─ ThumbDiskCache（データフォルダの thumbs。書き込み用ワーカー 1 本）
│   ├─ Icons: IconCache（一覧の行のアイコン）
│   ├─ TypeNames: TypeNameCache（詳細表示の「種類」の名前。専用の STA ワーカー 1 本）
│   ├─ Shell: StaWorkerPool(1)（.lnk の読み取りなど、その他のシェル呼び出し）
│   └─ DetailGate: SemaphoreSlim(8)（カード詳細の同時読み込み数）
├─ MainViewModel
│   ├─ RecentTab / FrequentTab: TabViewModel（固定タブ。セッション中ずっと同じインスタンスで、Tabs にある間だけ開いている）→ Cards: CardViewModel[]、Selection: SelectionModel（タブごと。キーはパス）
│   ├─ Tabs: ObservableCollection<TabViewModel>（タブ列。開いているタブ全部を左から順に：固定タブと、フォルダのタブ Kind = Folder）→ Cards
│   ├─ NoTab: TabViewModel（Kind = None。タブが 1 つも無いときの SelectedTab。Tabs には入らない）
│   ├─ SelectedTab（表示中のタブ。null にならない：タブなしは NoTab で、HasTab が false）
│   ├─ QuickSection / RegisteredSection / PcSection: SidebarSectionViewModel（サイドバーの節「クイック アクセス」「登録フォルダ」「PC」。見出しと開閉の状態だけを持ち、行は持たない）
│   ├─ IsSidebarCollapsed（サイドバー全体を隠しているか）
│   ├─ Registered: ObservableCollection<SidebarItemViewModel>（サイドバーの登録フォルダ）
│   ├─ DriveList: DriveListViewModel → Drives: ObservableCollection<SidebarItemViewModel>（PC の節の行。ドライブ 1 つが 1 行で、登録フォルダの行と同じ型）
│   └─ Message: MessageBarViewModel
└─ MainWindow（IMainView, ICardHost を実装）
    ├─ SidebarView（サイドバー全体：節の見出し、クイック アクセスの行（RecentTab / FrequentTab にバインド）、登録フォルダの行、PC の行）
    ├─ MainWindowHook（ウィンドウ メッセージの受け口。ドライブの着脱 → DriveList.RefreshAsync、クリップボードの変更 → MainViewModel.OnClipboardChanged、画面構成の変化 → MainWindow.OnDisplayChanged、アクティブ化 → MainWindow.OnHookActivated）
    ├─ FolderTabStrip（タブ列。Tabs を並べる）
    ├─ CardGrid（IItemsView。MainWindow は ActiveList 経由で使う）→ CardRow（列数ぶんのカード）→ CardView（DataContext = CardViewModel。ポインター操作は ItemPointerTracker）
    ├─ DetailsListView（IItemsView。詳細表示。CardGrid とどちらか一方だけが項目を持ち、もう一方は隠れて空）→ DetailsRowView（DataContext = 同じ CardViewModel。ポインター操作は ItemPointerTracker。Realize しない）
    ├─ ContextMenuFactory
    ├─ RenameEditor（名前の入力欄。開いている間だけ、項目のビューの名前の Adorner に TextBox）
    └─ CascadeController
        ├─ Level 0: カードから開いたとき OverlayView（サムネイル部分に重ねる）、アンカー（ICascadeAnchor：サイドバーの行、詳細表示の行の名前の列、アドレス欄のパンくず）から開いたとき Popup + FlyoutView（起点の右。パンくずは下）。どちらも EntryListViewModel
        ├─ Level 1…: Popup + FlyoutView + EntryListViewModel
        └─ Preview（最大 1 つ）: Popup + PreviewView + PreviewViewModel
```

- ViewModel から View への依存は `IMainView`（ダイアログ、スクロール位置、カスケードを閉じる、テーマの切り替え `ApplyTheme`、シェルのダイアログの親にするウィンドウハンドル `WindowHandle`）だけ。View からの通知は `ICardHost` と、`SidebarView` / `FolderTabStrip` のイベントを `MainWindow` が受ける。`ICardHost` は、ホバーだけ要素で受け（`CardMouseEnter(CardView)`、詳細表示の行の `RowMouseEnter` / `RowMouseMove` / `RowMouseLeave`（名前の列）：カスケードは要素にぶら下がるため）、クリック・右クリック・× ・📌（`ItemUnpin`）・ドラッグ・右ボタンを押したままの左クリック（`ItemShowInExplorer`）は項目（`CardViewModel`）で受ける。項目で受けるのは、同じ項目をどのビュー（カード、詳細表示の行）が出しても `MainWindow` 側を変えずに済ませるため。
- `ICascadeAnchor`（`Views/`）は ViewModel（`SidebarItemViewModel`）が実装するが、WPF の要素は含まない（要素は `AnchorMouseEnter` の引数で別に渡す）。ViewModel に View の型を持たせないための分け方なので、このインターフェイスに要素を足さない。タブの中の項目（`CardViewModel`）は自分では実装せず、`CardAnchor`（同じファイル）が包む：カードはオーバーレイを使うので起点にならず、起点になるのは詳細表示の行だけのため。

## 3. 主要な処理の流れ

### 3.1 タブの読み込み

`MainViewModel.NavigateAsync(target, mode)`（表示中のタブの中の移動）/ `ShowTabAsync(tab)`（タブの切り替え）→ `LoadTabAsync` → `TabViewModel.LoadAsync`

- 前回の読み込みを `_loadCts` でキャンセルしてから始める。5 秒を超えると `IsSlow`。
- 最上位（`Location.IsTop`。固定タブだけにある）は `LoadTopAsync` でタブごとに分岐：
  - **最近の履歴** `LoadRecentAsync`：`WindowsRecent.Read`（`AppServices.Shell`、20 秒）+ `RecentMerger.Merge` → `Existence.FilterProbedAsync`（1 秒、`RecentLimit` 件）→ `ManualOrder.Apply`（`CardOrderList.Recent`）
  - **よく使う項目** `LoadFrequentAsync`：`FrequentRanker.Rank` → ピン留め・ランキングをそれぞれ存在確認 → `ManualOrder.Apply`（`CardOrderList.Frequent`）
- フォルダの中は `LoadFolderAsync`：`Listings.GetAsync` → `ItemContext.InnerCard` のカードを作る。フォルダのタブ（`TabKind.Folder`）は常にこれ（最上位がない）。表示した一覧はタブが `_shownListing` として持つので、`FolderListingCache` が上限・期限切れで手放しても（[§2.1](#21-coresrcfolderdeckcore)）タブの表示は変わらない（戻ってきたフォルダのカードの件数などを列挙し直すだけ）
- 最上位のカードは、存在確認の結果（`ExistProbe`）から更新日時とファイルのサイズをもらう（`MakeTopCard`）。詳細表示の行はディスクを見に行かないので（[§3.2](#32-カードの段階読み込み741)）、ここで入れないとサイズの列が空のままになり、サイズ順も効かない。フォルダの中のカードは列挙の結果から同じものをもらう
- 自動更新（設定 `auto_refresh` / `auto_refresh_seconds`）：`MainViewModel.ApplyAutoRefreshSetting`（起動時の `InitializeAsync` と設定の OK）が 1 秒ごとのタイマーを動かす → `AutoRefreshTickAsync`：表示中のタブの `AutoRefreshPath`（`TransferTargetPath` があり、フォルダを列挙して表示しているとき）が、`LastListedAt` から間隔を過ぎていて、失敗による保留中でなく、`CanAutoRefresh`（ファイル操作・切り取りの確認・アプリのドラッグがなく、`IMainView.IsAutoRefreshBlocked` が false）なら → `Listings.Invalidate` → `Listings.GetAsync`（`_autoRefreshFlight`。終わるまで次を始めない。15 秒でキャンセル。失敗の結果はキャッシュから消す）→ await の後に判定し直す（タブ、`LoadGeneration`、パス、隠しファイルの設定、`CanAutoRefresh`）→ `TabViewModel.ApplyPolledListing`（`ListingChanges.Compare`。差がなければ `LastListedAt` を更新するだけ。差があれば変わっていないカードを使い回して `ShowCards`、件数の文言）→ 差し替えたらスクロール位置を戻す。同じフォルダで NotFound が 2 回続いたら `LoadAsync`（バナー。ネットワーク上のフォルダは `IsOnNetwork` で待つだけ）、ほかの失敗は `HoldAutoRefresh`（倍々で 5 分まで）。`LoadAsync` は `LoadGeneration` を進め、`_shownListing` を消す。読み込み・F5・ファイル操作の後の読み直しも `LastListedAt` を進めるので、自動更新と二重に読まない
- `ShowCards(baseOrder, isTop)` → `Ordered`：`CardOrdering.ComparerFor(SortMode)`（サイズはフォルダを「なし」、種類は拡張子で渡す）→（フォルダの中は `CardOrdering.InsideFolder`：更新日時順はフォルダとファイルを混ぜ、それ以外は `FoldersFirst`）→ `SortKeepingPinned` → `Show`：フィルター（`ItemFilters.Apply`、固定タブの最上位だけ `FilterApplies`）→ `UpdateTopSummary`（件数と空のときの文言）
- **`_baseCards`（並べ替え前の基準順）、`_orderedCards`（並べ替え後・フィルター前の全カード、`OrderedCards`）、`Cards`（表示するカード）の 3 本立て**。表示順を直接いじらず、`SetBaseOrder` / `ApplyOrder` / `PlaceInBase` / `RemoveCard` / `ApplyPins` を通す。「ピン留めは基準順と同じ位置」という前提が成り立つのは `OrderedCards` に対して（`Cards` はフィルターで詰まる）。

現在地 `NavLocation(Tab, Root, Rel)`：`Tab` はタブの種類（`Recent` / `Frequent` / `Folder`。`None` はタブなしの代役 `NoTab` 専用で、移動先にはならない）、`Root` は正規化したパス。`Root == ""` が固定タブの最上位（フォルダのタブは必ず `Root` を持つ）。`Rel` はルートからの相対パスで、`ResolvePath` が `PathTools.IsSafeRel` で検証してから結合する。フォルダのタブの `Root` は開いたときの登録フォルダのパス（登録 ID ではないので、登録を解除してもタブは生きる）。

### 3.2 カードの段階読み込み（§7.4.1）

`CardView` が表示されると（`Loaded`）`Attach`（VM の購読）→ `UpdateAll`（読み込まれていない間の変更を取り戻す）→ `CardViewModel.Realize(thumbPx, iconPx)`、外れると（`Unloaded`）`Unrealize`（CTS をキャンセルし、画像と一覧を手放す）→ `Detach`。`EnsureListingAsync`（オーバーレイが一覧を求める）は、待つ間に `Unrealize` されたら件数だけ反映し、`Listing` は持たない。

`CardViewModel.LoadAsync`：
1. 無効（見つからない・応答なし）なら終わり
2. フォルダ：`DetailGate`（同時 8 件）の中で `Listings.GetAsync` → `ApplyListing`（件数バッジ、`DetailsLoaded` を発火）→ `CoverFinder.Find`（結果は `Covers` に保存）
3. 画像：カバー画像があれば `ThumbnailService.GetAsync(CoverImage)`、なければ `GetAsync(Folder)`。ファイルは `GetEntry` で大きさと日時を取ってから `GetAsync(File)`

`ThumbnailService.GetAsync`：メモリの LRU → 画像ファイル（`ImageDecoder.CanDecode`：jpg / jpeg / jpe / jfif / png / bmp / gif / tif / tiff / webp。フォルダ自身は対象外）なら `DecodePicture` → 画像が得られなければ `Produce`（ここまでが `ProduceAsync`）→ `File` で `Image` が得られず、「オンラインのみ」の画像（`PreviewKind.Image` かつ `FileContent.IsDownloadable`）なら `FromCloudAsync`：シェルが「作成中」（WTS_E_EXTRACTIONPENDING。`GetShellImage` の `pending`）と答えていれば 1.5 秒後にシェルのサムネイルをもう一度 → だめなら `DownloadAsync`（100 MB 以下）でダウンロードしてから `ProduceAsync(downloaded: true)`。
- `DownloadAsync`：シェル・デコード用のワーカーの外（非同期 I/O）で、`_downloads`（カード。同時 2 件）か `_previewDownloads`（`urgent` = プレビュー。1 件）の順番を待ってから読む。トークンが取り消されると（カードの `Unrealize`、プレビューを閉じる）読むのをやめる（同期アプリには不要になったことが伝わる。実際に通信を止めるかは同期アプリ次第で、OneDrive は未確認）。1 件 2 分で打ち切る。始まるときに `downloading`（`IProgress<ThumbResult>`。UI スレッドで作れば UI スレッドで呼ばれる）へアイコンを渡す：カードはアイコンを出し、プレビューは「ダウンロード中…」。結果（`DownloadResult`。`FileContent.DownloadFailureOf` が同期アプリのエラーから分類）が `Refused`（ブロック・通知での取り消し）なら `_downloadsRefused` でそのセッションはもうダウンロードしない、`Unreachable`（オフライン・同期アプリ停止）なら 2 分止める（`DownloadsPaused`）、失敗・時間切れは `_failedDownloads` に記録してカードからは試さない（`urgent` のプレビューは試す。`Clear` = F5 で消える）。自分で取り消した読み取りは、同期アプリがどのエラーで終えても `OperationCanceledException`（`FileContent.DownloadAsync` がトークンを先に確かめる）なので、拒否と取り違えない。アプリが自分で読まない形式（HEIC など）はダウンロード後に絵が出なかった回数を `_extensionMisses` で数え、2 件続けば以後その形式はダウンロードしない。`DownloadAsync` の結果（`Fetch`）が `Never`（拒否・大きすぎ・その形式は無理）ならアイコンをメモリにキャッシュする（`Remember`）。`NotNow` ならしない（あとで絵が出るように）。フォルダの表紙（`CoverImage`）はダウンロードしない。
- `DecodePicture`（デコード用ワーカー上）：`ThumbDiskCache.TryRead`（データフォルダの `thumbs`）→ なければ `ImageDecoder.Decode` → 作るのに 4 ms 以上かかったもの、またはダウンロードしたもの（`downloaded`）は `ThumbDiskCache.Save`（書き込み用ワーカーで JPEG、透過があれば PNG に保存）。「オンラインのみ」のファイルは、ディスクキャッシュにあればそれを返し（キーは属性と同じくメタデータだけで作れる）、なければ開かず `Produce` へ回す。
- `ImageDecoder.Decode`：WIC で直接サムネイルの大きさ（`ThumbSizing.Fit`：短い辺 = 要求サイズ）にデコードする。JPEG などの不透明な形式は縮小をコーデックに直結する（JPEG は 1/2・1/4・1/8 でデコードされ、シェルより数倍速い）。パレット・透過つきは先に Pbgra32 に変換してから縮小。EXIF の向き（`System.Photo.Orientation`）を反映。結果は Bgr32（透過が本当にあるときだけ Pbgra32）で `Freeze` 済み。失敗は null（→ シェル）。
- `Produce`（シェル用 STA ワーカー上）：シェルのサムネイル → Open XML なら `OfficeCover`（ファイル内の縮小版）→ アイコン（拡張子ごとにキャッシュ）。呼び出しのタイムアウト（5 秒）ならシステムイメージリストのアイコン（それも時間切れなら何もしない）。60 秒たっても始まらなかった `QueueTimeoutException` ではアイコンも取らず、呼び出し元へ返す（カードは警告を出さず、表示中の絵を残す。[§4](#4-スレッドと非同期の規約)）。動画・Office・フォルダ・HEIC / AVIF・.ico などはこちら（ディスクキャッシュは Windows のサムネイルキャッシュ）。
- `ShrinkPicture`（同じシェル用ワーカーの上、`Produce` の後と `FromCloudAsync` の再試行の後）：シェルは SIIGBF_BIGGERSIZEOK で自分のキャッシュの大きさ（要求以上の段）を返し、`OfficeCover` は埋め込みの大きさのままなので、要る大きさまで `ImageDecoder.Shrink` で縮める。基準は要求サイズ × 4/3（要求サイズはカードの幅だけから決まり、縦長のカードの絵の高さは幅の 4/3 のため。下回ると表示で拡大されてぼやける）。`Image`（切り抜き）は `ThumbSizing.Fit`（短い辺 = 基準）、`Shell`（全体を収める。フォルダのシェルのサムネイル、スライド・表計算）は長い辺 = 基準以下。アイコンは縮めない。面積が 1.2 倍以下なら縮めない。非乗算アルファは先に Pbgra32 にする。フォルダの `HasOpaqueCorners` は `Produce` の中（縮める前）で判定する。シェルの絵はディスクキャッシュに入らないので、`ThumbDiskCache.Version` とは関係ない。
- `ThumbDiskCache`：キーは版（`Version`）・パス・ファイルの更新日時・サイズ・要求サイズ → `DiskCacheRules.RelativePathOf` でファイル名にする。起動 20 秒後と、上限の 1/8 を書くごとに `Trim`（上限超過なら使っていない順に 8 割まで削除。3 日以上前のファイルは読んだときに日時を更新）。**保存する画像の作り方（大きさ・品質）を変えたら `Version` を上げる。**

`ThumbMode`：`Image`（枠いっぱいに切り抜き）/ `Shell`（全体を収める）/ `Icon`（中央に原寸）。キャッシュのキーはパス・更新日時・大きさ・要求サイズ（256 / 512 に丸める）・種類。

**詳細表示の行（`DetailsRowView`）は `Realize` を呼ばない**。行が使うのは、一覧を作った時点で分かっている名前・更新日時・サイズと、拡張子ごとにキャッシュされる 16 px のアイコン（`IconCache`）・種類の名前（`TypeNameCache`）だけで、サムネイル・カバー探索・中身の件数（`DetailGate`）は動かない。数千件のフォルダでも行ごとの I/O が無い、というのが詳細表示の前提なので、行に「フォルダの中身の数」のような列を足すときは、この前提を崩さない取り方を先に決める。

### 3.3 カスケード（`CascadeController`、§9）

- 状態：`_levels`（0 = カードのオーバーレイ、またはアンカーの横のフライアウト。1 以降 = フライアウト）、起点（`_card`：カード、`_anchor` / `_anchorPlacement` / `_anchorItem`：アンカー = カード以外の起点。サイドバーの行、詳細表示の行の名前、アドレス欄のパンくず。カードとアンカーはどちらか一方）、`_preview`（最大 1 つ、常にいちばん深い位置。ファイルのアンカーでは階層なしで単独に出る：`ParentIndex` が -1）。`IsOpen` は「階層がある**か**プレビューがある」で、アンカーの経路の判断（`AnchorMouseEnter` / `AnchorMouseMove`、`OnOverlayTimer` のアンカーの枝、`CloseForSelectionKeys`、`OnForegroundTimer`）はこれで見る（`_levels.Count` で見ると、プレビューだけが出ている間に開き直す・再武装する）。タイマー 7 つ（`HoverTimings`：overlay 300（非アクティブ時 500）/ open 150 / grace 300 / exit 300 / preview 150 ms、プレビューを閉じるタイマーは grace と同じ、前面ウィンドウの監視 250 ms）
- 開く（カード）：`MainWindow.CardMouseEnter` → `CardMouseEnter` → overlay タイマー → `OpenOverlayAsync`（`CardViewModel.EnsureListingAsync`）。行に止まる → `OnRowHovered` → open タイマー → `OpenChild` → `OpenFlyout` → `OpenOn`（行の要素を PlacementTarget にして開き、すぐ外す。Popup の DPI を行のモニターに合わせるため。[§7](#7-守ること落とし穴)）→ `LoadLevelAsync` → `Position` / `Place`（行のモニター（`MonitorOf`）の作業領域で物理ピクセルの位置を決め、Popup のウィンドウを直接動かす。寸法と offset は Popup 自身の DPI（`TransformToDevice`）で換算する）。第 2 階層はカード全体の横（オーバーレイの行の横ではない）、それより深い階層は親のフライアウトの横で、どれも `FlyoutGap`（4 DIP）離す。カードの横は旧仕様 §9.5 の 8 px だったが、オーバーレイから子へ移る距離を縮めるため 4 にそろえた。Popup のウィンドウはカードの `ShadowMargin`（16 DIP）だけ外へ広がり、影の画素（透明でない）はポインターを受けるので、隙間に「どちらでもない」帯はない
- メニュー エイム（旧仕様 §9.6 規則 9、以前は未対応）：子（下の階層のフライアウト、またはその階層から出たプレビュー）へ向かってポインターが動いている間は、横切った行で子を開かない・子を閉じない・外に出ても閉じない・ほかのカードやアンカーへ切り替えない。
  - 判定は `IsHeadingForChildOf(index)`（`index` の階層の子。-1 はアンカーの横の階層 0 またはアンカーのファイルのプレビュー）と `IsHeadingForAnyChild()`。中身は Core の `MenuAim`。移動は `TrackPointer` が `PreviewMouseMove`（`handledEventsToo`）で、メイン ウィンドウとフライアウト・プレビューのそれぞれ（Popup は別のウィンドウ）から受け、`IsOpen` の間だけ `GetCursorPos`（物理ピクセル）で記録する。判定のときにも 1 回取る（ポインターがほかのウィンドウの上でも数える）。`CloseAll` で捨てる。
  - **判定はタイマーの tick の中だけ**：open / grace / exit / preview（キーボードで選んだときは除く）/ previewClose / overlay（切り替えの保留があるとき）の tick が、行動する前に問い、向かっている間は保留の状態（`_pendingOpen`、`_graceLevel`、`_pendingPreview`、`_pendingCard`、`_pendingAnchor`）を残したまま自分のタイマーをやり直す（間隔がそのまま確かめ直しの間隔）。専用のタイマーはない。止まる（`HoverTimings.AimMoving` = 100 ms 動かない）か向きを変えると、次の tick で今までどおりに決まる。`_suspended` の間は false。
  - カードの切り替え（規則 4）：別のカードに入ったとき、子へ向かっていれば `CloseAll` せず `_pendingCard` に置いて overlay タイマーを回す（低い行から斜めに動くと、カードの下端から下のカードに入るため）。`OnOverlayTimer` が、まだ向かっていればやり直し、そうでなければそのカードの上にいるときだけ `CloseAll` して、そのカードを起点にオーバーレイを開く。`_pendingCard` を捨てるのは、そのカードを出たとき（`CardMouseLeave`。exit タイマーを回す）、フライアウト・プレビューに入ったとき（`OnFlyoutEnter`、プレビューの `MouseEnter`）、元のカードに戻ったとき、`StopTimers`
  - 判定に使う子の矩形は、見えているフライアウトの `CardElement` と `DirectionLeft`、または表示済み（`IsRevealed`）のプレビューの `CardElement` と `Preview.DirectionLeft`（`PositionPreview` が入れる）。上下に `AimSlack`（4 DIP）広げる
- アンカー：カード以外の起点は `AnchorMouseEnter(hover, placement, item)` の 3 つで渡す。`hover` はポインターが載る要素で、一覧はその高さに出る（配置の「行」）。`placement` は一覧を横に置く要素（配置の「親カード」）。`item`（`ICascadeAnchor`）は開くフォルダと、起点ごとの違い（`OpensInNewTab`：タブの外の起点か。`YieldsToModifiers`：Ctrl / Shift を押している間は開かない起点か。詳細表示の行が true、サイドバーの行とパンくずは false。既定値付きの 3 つ：`OpensBelow`＝階層 0 を要素の右ではなく下に出す、`FoldersOnly`＝階層 0 の一覧だけフォルダだけ（階層 1 以降はファイルも出す）、`OutlivesContent`＝タブの中身の都合で閉じない（既定は `OpensInNewTab` と同じ））。起点の同一性は `hover` の参照で見るので、同じ起点の `AnchorMouseMove` / `AnchorMouseLeave` には同じ要素を渡す。
- 開く（サイドバー）：`SidebarView.ItemEntered` → `AnchorMouseEnter(row, row, item)` → overlay タイマー → `OpenRoot` → `OpenFlyout(0, …)`（行そのものが `hover` と `placement` の両方なので、行の右に出る）。一覧を開いている間に別の行へ入ったときは、すぐには切り替えず `_pendingAnchor` に置いて overlay タイマーを回し、そこで止まったときだけ切り替える（行が縦に並んでいて、一覧へ斜めに移動すると隣の行を横切るため。一覧に入れば `OnFlyoutEnter` が取り消す）
- 非アクティブなウィンドウでも開く（旧仕様 §9.6 規則 7「非アクティブの間は開かない」はやめた。横に並べて使うと「行に載せても出ず、どこかをクリックすると出る」不具合に見えたため）。旧規則が守っていたことは別の仕組みで守る：通過しただけでは開かない → `RestartOverlay`（非アクティブ時は `HoverTimings.OverlayInactive` = 500 ms）、最前面の Popup がほかのアプリの上に残らない → `WatchForeground`（非アクティブで階層 0 を開いたら前面ウィンドウを 250 ms ごとに見て、替わったら `CloseAll`。`Deactivated` は来ないため）、操作はアクティブなウィンドウで行う → `ActivateWindow`（一覧のクリック・右クリックの前に `Window.Activate`。Popup は `WS_EX_NOACTIVATE` でクリックしてもアクティブにならない。メニューは必ず `ShowMenu` 経由で出す）。ホバーだけではウィンドウを前面に出さない
- 再武装（サイドバー）：ホバーの起点は `MouseEnter` の 1 回だけなので、ポインターが行に載ったまま `CloseAll` されると（非アクティブ化、ドラッグ終了、前面ウィンドウの交代）出入りするまで開かない。`SidebarView.ItemMoved` → `AnchorMouseMove` が、最初に見た位置からシステムのドラッグ距離以上動いたときだけ `AnchorMouseEnter` をやり直す（位置は、起点と一緒に動かない座標系で渡す。サイドバーの行は `SidebarView` の座標）。クリック・右クリック・ドラッグした行は、出るまで再武装しない（`SidebarView._noRearm`。タブを開いた直後に同じ行の一覧が出直さないため）
- PC の行（ドライブ）も登録フォルダの行と同じ `SidebarItemViewModel` で、同じイベント（`ItemEntered` / `ItemMoved` / `ItemLeft`）から同じ経路に入る：開き方・切り替えの保留・再武装・`_noRearm` はどちらの行でも同じ。違いは行が**操作なしで消える**こと（USB を抜く、メディアを取り出す）。消えた要素は `MouseLeave` を出さないので、`DriveListViewModel.RowRemoved` → `AnchorRemoved` が、その行を起点にした一覧を閉じ、その行への切り替えの保留を取り消す。行が増減して起点の行が上下に動いたときは `MainWindow` が `Drives.CollectionChanged` で閉じる（ドライブの行から開いた一覧があるときだけ）。
- 開く（詳細表示の行）：`DetailsRowView` の名前の列（`NameColumn`）の `MouseEnter` → `ICardHost.RowMouseEnter(nameColumn, vm)` → `MainWindow` が `CardAnchor.For(vm, Services.Icons)`（フォルダとプレビューできるファイル以外は null で、何もしない）→ `AnchorMouseEnter(nameColumn, nameColumn, anchor)`。以降はサイドバーの行と同じ経路（行が縦に並ぶので、切り替えの保留も同じように効く）。`OpenRoot` が `item.File` を見て、フォルダなら `OpenFlyout(0, …)`、ファイルなら下のプレビュー。
  - 起点は行全体ではなく**名前の列**（列 0 全体：アイコン・名前・📌・補足・右の余白）。hover と placement に同じ要素を渡すので、一覧は名前の列の右端（更新日時の列の上）に出る。更新日時などの列に載せても開かない（一覧が右の列を覆うので、起点を行全体に広げると、行のどこに載せても列が読めなくなるため）。placement を名前の内容（アイコン + 名前 + 📌 の部分）にしない：名前の右の余白で止まると、ポインターの真下に一覧が開く。
  - 名前の列は背景を Transparent にしてヒットテストに当てる（null だと名前の右の余白で `MouseEnter` が来ない）。行で押下があったあとの `_noRearm` は、名前の列を出るまで再武装しない。
  - `OpensInNewTab` が false なので、一覧の中のフォルダは表示中のタブの中で移動し（最近の履歴・よく使う項目の最上位の行（`CardAnchor.IsTopLevel`）だけは新しいタブ）、タブの中身の都合（`Details.Scrolled`、`Cards` の差し替え）では `CloseCardCascade` で閉じる。
  - 行のコンテナーはスクロールで再利用される（要素は同じまま項目が替わる）。起点の同一性は要素で見ているので、`DetailsRowView.OnDataContextChanged` が `RowMouseLeave` を呼んで、前の項目の一覧・待機を手放す。
  - 再武装は `RowMouseMove` → `AnchorMouseMove`（位置はウィンドウの座標）。ボタンを押した行は、ポインターが名前を出るまで再武装しない（`DetailsRowView._noRearm`。クリックで開いた直後やメニューの表示中に一覧が出直さないため）
  - ファイルの行（`ICascadeAnchor.File` が null でない）：`OpenRoot` → `OpenPreviewAt(-1, file.Row, file.Card.ToItemRef(), …)`。一覧と同じく名前の列の右端に出る。待ち時間は overlay タイマー（300 ms、非アクティブ時 500 ms）で、一覧の中の行のプレビュー（150 ms）より長い。対象は `CardAnchor.For` が決める：見つからない・応答なしでないファイルで、サイズが分かっていて（プレビューのキャッシュがサイズをキーに使うため）、`ShellPreviewSupport.IsPreviewable`。プレビューの元の行（`EntryRowViewModel`）は `CardAnchor.File` を最初に読んだときに 1 回だけ作る（`For` はポインターが動くたびに呼ばれる。`LoadPreviewAsync` の `wanted` は `_anchorItem.File.Row` と参照で比べる）。
  - 階層なしのプレビュー（`ParentIndex` -1）の約束：開くとき `WatchForeground`（非アクティブなウィンドウの上でも開くため、階層 0 と同じ）。プレビューの `MouseEnter` で保留中のアンカーの切り替えを取り消す（`OnFlyoutEnter` と同じ）。強調は `MarkSource`（行の `IsActive` と、アンカーの `IsHoverHeld`。ポインターがプレビューに入っても詳細表示の行は強調されたまま）。クリックは `OnPreviewClicked`（`Item.Card` があれば `ActivateCardAsync` で、行のクリックと同じ。実行形式の確認なども同じ）、右クリックは `ShowMenu(preview.Item)`（1 項目のメニュー。選択中でも選択全部にはならない）、ドラッグは一覧の行のプレビューと同じ `DragOut`。キーは `HandleKey` が階層なしなら Esc だけを受けて `CloseDeepest`（ほかのキーはビューへ）。Ctrl / Shift で閉じるのも一覧と同じ（`YieldsToModifiers`）
- 開く（パンくず）：`BreadcrumbItem` が `ICascadeAnchor`（`ObservableObject`。`OpensInNewTab` false・`YieldsToModifiers` false・`OutlivesContent` / `OpensBelow` / `FoldersOnly` true。`IsDisabled` は `ToolTip`（フォルダのパス）が null のとき＝固定タブの一覧名と「（不明）」）。`MainWindow.xaml` のパンくずの Button の `MouseEnter` / `MouseMove` / `MouseLeave` → `OnCrumbMouseEnter` / `Move` / `Leave` → `AnchorMouseEnter(button, button, crumb)` などで、以降はサイドバーと同じ経路（切り替えの保留・再武装も同じ）。
  - `OpenRoot` が `item.OpensBelow` を `OpenFlyout(below)` に渡し、`Level.Below` に残す。`Place` の下に置く分岐：x は要素の左端（作業領域へ clamp）、y は要素の下端 + `FlyoutGap`、下に入らなければ要素の上、それも無理なら作業領域へ clamp。左右は決めず（`DirectionLeft` false）、実際のウィンドウ矩形から左右を判断し直す処理も飛ばす（階層 1 以降は従来どおり親の右）。`CardMaxHeight` は要素の下端から作業領域の下端まで（それが 120 DIP に足りず上の方が広ければ、要素の上端から作業領域の上端まで。そのとき `Place` が上に置く）。
  - `FoldersOnly` は `OpenFlyout` が `_anchorItem` を見て `EntryListViewModel(foldersOnly)` に渡す（`index == 0` のときだけ。階層 1 以降は通常の一覧でファイルも出す）。絞るのは `Apply` の中だけ（`FolderListing` とキャッシュは他の一覧と共有なので変えない）。見出しの件数はフォルダ全体のまま、ファイルだけのフォルダは「サブフォルダはありません」。
  - メニュー エイム：`IsHeadingForChildOf(-1)` は `OpensBelow` のとき false（`MenuAim` は縦の辺しか扱わない。下の一覧は要素の真下にあり、途中でほかの起点を横切らない）。
  - クリックした直後は `_crumbQuiet`（`OnCrumbMouseDown` で立てて `CloseAll`、パンくずを出たら下ろす）：移動するとポインターの下に新しいパンくずの要素ができて `MouseEnter` が来るので、一覧が出直さないように。強調は `IsHoverHeld` の DataTrigger（ホバーと同じ背景、ツールチップを止める）。
  - パンくずは操作なしで差し替わる（場所の変更・タブの切り替え）。`MainWindow.WatchCrumbs`（起動時と `SelectedTab` の変更。古いタブの購読は外す）が `Breadcrumbs` の変更を見て、`DropCrumbs` が古い項目ごとに `AnchorRemoved` を呼ぶ（ドライブの行と同じ片づけ方）。`UpdateBreadcrumbs` は同じパスなら（`BreadcrumbItem.SameAs`）項目を作り直さないので、読み込みの開始（F5・自動更新）では一覧は消えない。
  - 一覧のフォルダのクリックは表示中のタブの中で移動（`OpensInNewTab` false）。根より上のパンくずの一覧の行は `NavLocation(Tab, そのパンくずのフォルダ, 名前)` なので、パンくずのクリックと同じく根が替わる（`AddressLocation` のような「根の中なら根を保つ」変換はしない）。最後のパンくずの一覧の見出し（表示中のフォルダ）は `OpenItemAsync` が何もしない（`NavigateCrumb` と同じ。履歴が重複しない）。
- 閉じる：**開閉はすべてここで決める**（Popup は `StaysOpen=True`）。`CloseAll` / `CloseFrom(index)` / `CloseDeepest`（Esc）。右クリックメニュー表示中は閉じない（`ContextMenuFactory.MenuOpened` / `MenuClosed`）。項目のビュー（カードグリッド・詳細表示）の都合（スクロール、項目の作り直し = 表示中タブの `Cards` 差し替え）で閉じるときは `CloseCardCascade`（`IMainView.CloseCardCascade`）：タブの中身にぶら下がらない起点（`OutlivesContent` が true のアンカー = サイドバーの行とパンくず）の一覧は閉じない（タブの読み込み完了が、利用者が見ている一覧を消していた）。カードと、タブの中の項目を表すアンカー（詳細表示の行）の一覧は閉じる。画面構成の変化（`MainWindowHook.DisplayChanged` → `MainWindow.OnDisplayChanged`）でも `CloseAll`：メイン ウィンドウが動かない変化（ほかのモニターだけ・解像度だけ）では `LocationChanged` などが来ず、最前面の Popup が古い配置の物理座標のまま残るため
- クリック：`OnRowClicked` / `OnHeaderClicked` → `MainViewModel.OpenItemAsync`。`ItemOf` / `HeaderOf` は `FoldersOpenInNewTab` を `ItemRef.NewTab` に写すので、サイドバー起点（`ICascadeAnchor.OpensInNewTab`）と、最近の履歴・よく使う項目の最上位のカード・行（`CardAnchor.IsTopLevel`、オーバーレイのカードの `IsTopLevel`）を起点にしたカスケードではフォルダは新しいフォルダのタブで開く（それ以外のカード起点は表示中のタブの中で移動）。開き先だけの判定で、カスケードの寿命（`CloseCardCascade`）は `OutlivesContent` だけで決まる
- Ctrl / Shift（選択の操作）に道を譲る：一覧の項目にぶら下がる一覧（カードのオーバーレイと、`YieldsToModifiers` が true のアンカー = 詳細表示の行）は、Ctrl か Shift を押している間は overlay タイマーが来ても開かず（`OnOverlayTimer` / `OnDetailsLoaded` の `SelectionKeysDown`、切り替えの保留も同じ）、開いていれば Ctrl / Shift を押した瞬間に閉じる（`MainWindow.OnPreviewKeyDown` → `CloseForSelectionKeys`）。Ctrl + クリックで隣の項目を選ぶとき、一覧が次の項目を覆わないため。サイドバーの行の一覧は項目を覆わないので影響を受けない。閉じたあとはポインターが項目を出入りするまで開かない（カードには再武装がない）
- キーボード：`MainWindow.OnPreviewKeyDown` が、カスケード表示中は先に `HandleKey`（↑ ↓ → ← Enter Esc）へ渡す。`HandleKey` の Enter は ↑ ↓ で選んだ行（`KeyRow`）があるときだけ使い（`OnRowClicked`）、ないとき（ポインターで開いただけ）は false を返して選択の Enter（`HandleSelectionKey`）に回す
- ドラッグ：`BeginDrag` で全階層を非表示にしてタイマーを止め、`EndDrag` で本当に閉じる。ドラッグ中の `CloseAll` は無視する（理由は `BeginDrag` の XML コメント）
- エクスプローラーのメニュー（「その他のメニュー（Windows）」）：`ContextMenuFactory.NativeMenuChanged` → `SetNativeMenuOpen`。
  - `true` は「その他のメニュー（Windows）」の Click の中で、設定が「Windows のメニュー」なら右クリック（`ContextMenuFactory.Show`）の中で、**同期的に**（`ShowAsync` より前に）来る。メニューのスレッドが前面を取ると `Deactivated` → `CloseAll` が来るので、その前に凍結しておく。凍結 = `_nativeMenu` と `_suspended` を立てて `StopTimers`。**隠さない**（メニューは一覧の行から出したもので、閉じたらそこへ戻る）。`CloseAll` は何もせず（`_dragging` と同じ）、タイマーの Tick（overlay / open / grace / exit / preview / previewClose / foreground）は先頭で戻る。`_suspended` が要る理由：`CardMouseEnter` / `AnchorMouseEnter` は `CloseAll`（凍結中は何もしない）のあと `_card` / `_anchor` を差し替えるので、開いた階層が別の起点の下に残る。
  - `false` は結果がどれでも（表示しなかった・時間切れも）来る。選ばれたアプリの項目を実行する前、代わりの WPF のメニューを開く前に来る（項目の `BeforeNavigate` の `CloseAll` が凍結で無視されないため。開いた WPF のメニューの間は `MenuOpened` / `MenuClosed` が一覧を保つ）。ウィンドウがアクティブなら `Restart(_exitTimer)`（規則 3 に戻る）。非アクティブなら、メニューのスレッドが前面を返す（前面がまだオーナーのときだけ返す）のを 300 ms 待ってから決める（`AfterNativeMenuAsync`）：アクティブ → `Restart(_exitTimer)`、まだ非アクティブ（ほかのウィンドウをクリックして閉じた、コマンドがウィンドウを開いた）→ `CloseAll`。待つ間に閉じた・別の一覧になった（`_generation` が変わった）ときは何もしない。
  - WPF のメニューの `MenuClosed` は凍結中は exit タイマーを始めない（解除のときに始める）。
- 非同期の結果は、完了時に対象（`_preview` や階層）が差し替わっていないかを確かめてから反映する

### 3.4 プレビュー

`EntryRowViewModel.IsPreviewable` = `ShellPreviewSupport.IsPreviewable`（Core の `PreviewKinds` で対象か、またはシェルがサムネイルを作れる拡張子か）。
起点は 2 つで、どちらも `OpenPreviewAt(parentIndex, row, item, …)` で開く（`item` はクリックとメニューの対象の `ItemRef`。`Preview.Item`）：カスケードの行（`OnRowHovered` → preview タイマー → `OpenPreview` → `OpenPreviewAt(parent.Index, row, ItemOf(row), …)`。階層の横）と、詳細表示のファイルの行の名前の列（`OpenRoot` → `OpenPreviewAt(-1, …)`。階層なし、[§3.3](#33-カスケードcascadecontroller9)）。中身の読み込みは同じ：
`OpenPreviewAt` → `LoadPreviewAsync`：
1. Word / Excel / テキスト：`PreviewTextCache.GetAsync` →（`OfficeText.ReadWord` / `ReadSheet` / `TextPreview.Read`）→ `ShowExcerpt`
2. 抜粋がない・ほかの種類：`ThumbnailService.GetAsync(File)`。`Image` / `Shell` なら表示、アイコンしかなければ「プレビューできない」扱い（「オンラインのみ」の画像は `CloudNoteAsync` が理由を出す：取り消し・ブロック / 大きすぎる / 一時停止中 / ダウンロードできなかった）。「オンラインのみ」の画像はダウンロードを待つ間 `PreviewViewModel.ShowDownloading`（`downloading` の `Progress`）。プレビューは `urgent` でカードのダウンロードの後ろに並ばない
3. レイアウト（シートのグリッド、「（以下省略）」）は `PreviewView.xaml.cs`

`ParentIndex` が -1 のとき：`LoadPreviewAsync` の `wanted`（絵が届いたとき、ポインターがまだ元の行にあるか）はアンカー（`_anchor.IsMouseOver` と `_anchorItem.File.Row`）を見る。`OnPreviewCloseTimer` は階層の行を見ず、ポインターがプレビューの上になければ閉じる。`_levels[ParentIndex]` を引く前には必ず `ParentIndex >= 0` を確かめる。

### 3.5 開く・移動する

- 項目のポインター操作：`CardView` と `DetailsRowView`（詳細表示の行。行のどこを押しても同じ）はマウスのボタンのイベントを `ItemPointerTracker` へ渡すだけで、判定はトラッカーが持つ。押下（1 回目だけを数える：ダブルクリックで 2 回開かない。設定「ダブルクリックで開く」のときは 2 回目も数える：下の「ダブルクリックで開く」）→ ボタンを**離したとき**にクリックと決める（要素の上で離したときだけ。`ICardHost.ItemClick(vm, element, modifiers, doubleClick)`。修飾キーは離したときの `Keyboard.Modifiers`）→ 押したままシステムのドラッグ距離を越えるか要素を出たらドラッグ（`CanDragItem` が false なら押下はクリックのまま → `ItemDrag`）。右ボタンを離すとメニュー（`ItemContextMenu`）。× と 📌 はボタンなので、押下はクリックにもドラッグにもならない。
  - 処理済みにするのは、右ボタンを押したままの左クリックの押下と離し、クリックになった離し、右ボタンの離しだけ。**普通の左押下は処理済みにしない**（上へ届く）。ドラッグ開始・フォーカス・右ボタンの組み合わせへの影響が読めないので変えない。祖先で左押下に反応する処理は `e.OriginalSource` を見て、項目の上の押下かどうかを分ける。
- カードのクリック → `MainWindow.ItemClick` →（Ctrl / Shift つきなら選択だけ：`ClickSelect`。普通のクリックは選択を外して。設定「ダブルクリックで開く」では普通のクリックは `SelectOnly`、ダブルクリックだけが開く）`MainViewModel.ActivateCardAsync`、行のクリック → `OpenItemAsync`、サイドバーの行のクリック → `OpenRegisteredAsync`（ドライブの行は `OpenDriveAsync`）
- フォルダ：`ItemRef.NewTab`（サイドバーの行と、そこから出したカスケード。最近の履歴・よく使う項目の最上位のカード（`CardViewModel.ToItemRef` が `IsTopLevel` で立てる）と、そのカード・行から出したカスケード（`CascadeController.FoldersOpenInNewTab`：`CardAnchor.IsTopLevel` か、オーバーレイのカードの `IsTopLevel`）も）なら `OpenFolderTabAsync`（新しいフォルダのタブ）、それ以外は `NavigateAsync(Target, NavMode.New, recordPath: …)`（表示中のタブの中で移動）。どちらも利用として `RecordUse`。例外はドライブの行そのもの（`ItemContext.Drive`：クリック、メニューの「開く」「エクスプローラーで表示」）で、利用として記録しない（PC の節にいつも出ているので、履歴に `C:\` が並んでも役に立たない）。ドライブの行から出した一覧の行・見出しは、ほかのフォルダと同じく記録する
- ファイル：`OpenFileAsync`：実行形式の確認（`ConfirmExecutables` && `ShellActions.IsExecutable`）→ `Task.Run(ShellActions.Open)` → `RecordUse`（`History.Record` → 最近の履歴・よく使う項目を更新）→ 設定によって `SHAddToRecentDocs`
- 右クリック：`ContextMenuFactory.Show(ItemRef, target)` → `MainViewModel` の `ShowInExplorerAsync`（`ItemRef.IsFolder` ならフォルダ自体を開く `OpenInExplorer` / `ExplorerTabs.OpenAsync`、ファイルなら親フォルダで選択 `ShowInExplorer` / `ExplorerTabs.ShowAsync`。どのタブ・どの位置の項目でも同じ。設定で `ExplorerTabs`）/ `CopyPath` / `TogglePin` / `AddToRegisteredAsync`（未登録のフォルダ → サイドバーに追加）/ `DeleteAsync` / `Unregister`（サイドバーの行）/ `ExcludeFromRecent` / `RemoveFromFrequent`。PC の節の見出しは `ContextMenuFactory.ShowPcSection` → `OpenPcInExplorerAsync`（[§3.10](#310-タブ列とサイドバー)）

  - `NativeMenuChanged(false)` を `OnShellMenuClosedAsync` より先に出す：読み直しの `CloseCascade` は凍結中だと無視される。
  - 複数の選択は 1 つのメニュー（エクスプローラーで複数選んだときと同じ）。親が違う項目（最近の履歴の一覧）は item array で、取れなければ `Unavailable`。
- 名前の変更：入口は F2（`MainWindow.HandleSelectionKey`。**選択だけ**が対象で、1 つのときだけ：`RenameCandidate`。`e.IsRepeat` は無視）と、1 項目のメニューの「名前の変更」（`ContextMenuFactory.ItemEntries`。`CanRename`：タブの中のカード（`ItemContext.InnerCard`）で使えて `IsBusy` でなく、ルートでない。カスケードの行には入力欄がないので出さない）→ `RenameRequested` → `MainWindow.BeginRename(card)`。
  - `BeginRename`：カードをパスで引き直す（`ShownCard`。メニューを開いた時点・読み直し前のカードは別のインスタンスに替わっている）→ `CanStartRename`（できない理由はメッセージ行。読み込み中・`_fileOpBusy` も断る）→ `CloseAll` → `ActiveList.BringItemIntoView(card)`（この中でスクロールし `Scrolled` が出るので、入力欄はその後）→ `RenameEditor.Begin(view, card, text)` → `CascadeController.SetEditing(true)`（ホバーで何も開かない。Esc がカスケードに取られない）。フォーカスと選択は `DispatcherPriority.Loaded` で（測られる前の `TextBox` はフォーカスを取らない）。ウィンドウがアクティブでなければ（「Windows のメニュー」の `RunEntry` から）`Activate` し、取れなければ次の `Activated` で。
  - 入力中：`MainWindow.OnPreviewKeyDown` は何もしない（F5・Ctrl + W・Alt + ← などで一覧が替わらない）。使えない文字は入力のときに断る（`PreviewTextInput`、メッセージ行）。入力欄はリストの `ScrollContentPresenter` の Adorner 層にあり、項目のビューの子ではない：マウスの入力は `CardView` / `DetailsRowView` を通らない（項目のクリック・ドラッグ・メニューにならない）が、`ContentHost` には届くので `IsOnItemOrControl` が `TextBoxBase` を項目と同じに扱う（左押下で選択を外さない、右クリックを空白のメニューにしない。`TextBox` 自身のメニューが出る）。
  - 入力中のウィンドウのアクティブ化：`OnActivatedAsync`（切り取りの確認・エクスプローラーのコマンドの後の読み直し）は、入力欄が開いている間・新しいフォルダーを作っている間（`_creatingFolder`）・確定した名前を処理している間（`_committingRename`：`Committed` で立て、`CommitRenameAsync` の finally で下ろす。拡張子の確認を閉じるとウィンドウがアクティブになり、その読み直しが開き直した入力欄を確定してしまうため）は後に回す（`IsNameBusy` → `_activationPending`）。`RunPendingActivation`（`Ended(false)`、`CommitRenameAsync` と `CreateFolderAndRenameAsync` の finally）がまとめて 1 回だけ走らせる。読み直しで項目のビューが作り直されると、入力途中の名前が確定されてしまうため。
  - 終わり方（`RenameEditor.End` が 1 回だけ。最初に session を外してから、ハンドラーを外し、Adorner を外し、フォーカスをウィンドウへ戻し、`Ended(commit)` → `Committed`）：Enter（`ItemNames.Check` に通らなければメッセージを出して開いたまま）、Esc（取り消し）、外の押下（`MainWindow.OnPreviewMouseDown` の先頭で `CommitIfOutside`。項目はフォーカスを取らないので、フォーカスの移動だけでは終わらない）、フォーカスの移動（`TextBox` のメニューへの移動と、ウィンドウが非アクティブになったとき（`NewFocus` が null で `IsActive` が false）は除く：WPF が戻ったときにフォーカスを返す）、項目のビューの `Unloaded` / `DataContextChanged`（スクロールで外れた・読み直し・列数の変化で作り直された）：確定。
  - `Committed` → `Dispatcher.BeginInvoke` で `CommitRenameAsync` → `MainViewModel.RenameAsync(card, text)`：`ItemNames.Clean` → 変わっていない・空なら何もしない → `Check`（通らなければメッセージ）→ ファイルの拡張子が変わるなら `IMainView.Confirm`（「キャンセル」は入力欄に戻す）→ `_fileOpBusy` と `card.IsBusy` → `ShellFileOps.RenameAsync` → `NameTaken` は入力欄に戻す（true を返し、項目がまだ表示されていれば `BeginRename(card, text)`。表示されていなければ「同じ名前…」のメッセージを残して終わる）、`Canceled` / `Failed` はメッセージ → 成功は `ReloadAfterFileChangeAsync` → 選択が空（古いパスは読み直しで外れる）で同じフォルダを表示していれば新しいパスを選択（`SelectInShownFolder`。空でなければ、確定に使ったクリックで利用者が選んだもの：そのまま）。変わっていないかは整形の前の文字列でも比べる（先頭に空白のある名前を、触っていないのに改名しない）。後に回すのは、確認ダイアログをマウス・フォーカスのイベントの中で開かないため。
  - パスで持っているもの（ピン、利用記録、登録フォルダ、ほかのタブの場所、切り取りの印）は付け替えない（エクスプローラーで名前を変えたときと同じく、見つからない項目になる）。
- 新しいフォルダー：Ctrl + Shift + N（`MainWindow.OnPreviewKeyDown`。テキスト ボックスの中では効かない、`e.IsRepeat` は無視）と、空白のメニューの「新しいフォルダー」（`BlankEntries`。表示中のフォルダがあるときだけ、「貼り付け」の次）→ `CreateFolderAndRenameAsync` → `MainViewModel.CreateFolderAsync`：先は `PasteFolderOf(null)`（貼り付けと同じ `TransferTargetPath`）→ 名前は表示中のカードの名前から `ItemNames.NextNewFolderName` → `ShellFileOps.NewFolderAsync`（隠れた項目と重なればシェルが次の番号を付ける。新しいパスはシンクの報告）→ `ReloadAfterFileChangeAsync` → 選択 → カードを返す → `DispatcherPriority.Background` まで待つ（読み直しの `ScrollTo` が Loaded で後から当たるため）→ `BeginRename(card, typeAhead)`。作る前にキーボードのフォーカスをウィンドウ自身へ移し（`RenameEditor.FocusWindowItself`：クリックしたツールバーのボタンにフォーカスが残っていると、Space・矢印がそのボタンに届き、文字の入力も消える）、作っている間（`_creatingFolder`）はキーで何もせず（Backspace で親へ移動しない。文字のキーは処理済みにしない：処理済みにすると文字の入力が来ない）、打った文字を `OnPreviewTextInput` でためて、入力欄の選択の代わりに入れる（エクスプローラーと同じく、Ctrl + Shift + N のすぐ後に打った名前が入る）。
- ダブルクリックで開く（設定 `OpenOnDoubleClick`。`ICardHost.OpensOnDoubleClick` → `MainViewModel.OpensOnDoubleClick`、押下のたびに読むので OK のあと再起動なしで効く）：`ItemPointerTracker.LeftDown` は `ClickCount == 2` の押下も数え、前の普通のクリック（Ctrl / Shift なし）と同じ項目（`_lastClicked`）で、その押下からダブルクリックの時間（`GetDoubleClickTime`）以内のときだけ `doubleClick` にする。WPF の `ClickCount` は時間と距離だけで数え、どの要素かを見ないので、1 回目がオーバーレイの行などトラッカーを通らないところだと、古いクリックと組になってしまうため。`MainWindow.ItemClick`：Ctrl / Shift は今までどおり `ClickSelect`、普通のクリックは `SelectOnly`（`Selection.Replace([path])`。起点もその項目）、ダブルクリックは選択を残したまま `ActivateCardAsync`。カードと詳細表示の行だけで、サイドバー・カスケードの行・パンくずは 1 回のクリックのまま。

### 3.6 並べ替え・ピン留め

- 並び方の変更：並べ替えメニュー（`MainWindow` が `CardSortModes.All` から組み立てる）→ `MainViewModel.SetSortMode` → `SaveSortMode`（`settings.json` の `sort_modes`。キーは `TabKinds.ToSetting`：`recent` / `frequent` / `folder`）→ `TabViewModel.ApplyOrder`。フォルダのタブは 1 つのキーを共有するので、開いているほかのフォルダのタブにも同じ並び方を適用する
  - 詳細表示では列の見出しのクリックでも変わる：`DetailsListView.HeaderClicked` → `MainWindow` → `SetSortMode(CardSortModes.Next(いまの並び方, 列))`。同じ列なら向きを反転、別の列なら名前・種類は昇順、更新日時・サイズは降順から始める。見出しからは「手動」に戻れない（戻すのはツールバーのメニュー）。並び方はタブのもので、表示モードとは独立（カード表示でもサイズ順・種類順を選べる）
  - サイズ順はフォルダとサイズの分からない項目を、どちらの向きでも最後に置く。種類順のキーは**拡張子**で、行に出している種類の名前ではない（名前は `TypeNameCache` から後で届くので、それをキーにすると読み込み中に行が動く）。どちらも同順は名前順で、向きも同じ（降順なら名前も降順）。フォルダの中ではフォルダが先に来て、フォルダどうしはサイズも拡張子もない同順なので、名前を昇順に固定すると見出しを押しても一覧の上のほうが変わらず、並べ替えが効いていないように見える
  - フォルダの中（`_baseIsTop` が false）では `Ordered` が `CardOrdering.InsideFolder` を通す：更新日時順だけはフォルダを先にせず、フォルダ自身の `LastWriteTimeUtc`（列挙の `FsEntry` から `NewEntryCard` が入れる。追加の I/O はない）でファイルと混ぜる。同じ日時は基準の順（フォルダ→ファイル。安定ソート）。名前・サイズ・種類はフォルダが先。最上位はもともとどの並び方でもフォルダを先にしない
- フィルター（固定タブの最上位）：`MainWindow.OnFilterClick`（`ItemFilters.Values` からメニュー）→ `MainViewModel.SetFilter` → `settings.json` の `filter_modes` → `TabViewModel.Filter` → `OnFilterChanged` → `Show`（`_orderedCards` を絞り込んで `Cards` へ）
- ドラッグで並べ替え（固定タブの最上位）：`ItemPointerTracker` → `MainWindow.ItemDrag` → `FileDragOut.CreateData(reorder: true)` → `ActiveList.RunReorderDrag`（`IItemsView`。`CardGrid` はカードの間の縦線、`DetailsListView` は行の間の横線で入る位置を示す）→ `MainViewModel.MoveCard` →（フィルター中は `ItemFilters.MergeShownOrder` で、隠れているカードの位置を保ったまま全体の並びに戻す）→ `TabViewModel.SetBaseOrder` → `SaveManualOrder`（`CardOrderStore.Set`）。「手動」以外の並び方のときは「手動」に切り替える
- サイドバーの並べ替え：`SidebarView.ItemDragRequested` → `MainWindow.OnSidebarDrag` → `SidebarView.RunReorderDrag`（ドロップを受けるのは登録フォルダの行の領域だけ。見出しやクイック アクセスの上では、ウィンドウが自アプリ由来のドラッグとして断る）→ `MainViewModel.MoveRegistered` → `RegisteredFoldersStore.Reorder` → `RefreshRegistered`
- ピン：`TogglePin` → `PinStore.Pin` / `Unpin` → `PinStore.Changed` → `OnPinsChanged` → 各タブ（固定タブとフォルダのタブ全部）の `ApplyPins`。「手動」以外の並び方でピン留めするときは `KeepInPlace` → `PlaceInBase` で表示中の位置（`OrderedCards` での位置）に固定。カード・詳細表示の行の 📌 のクリックは `CardView.OnPinClick` / `DetailsRowView.OnPinClick` → `ICardHost.ItemUnpin`（`MainWindow`：カスケードを閉じて `TogglePin`。見つからない・応答なしのカードでは無効）
- 表示モード（全タブ共通。`CardShape`：縦長 / 正方形 / 詳細）：ツールバーの `RadioButton` → `SetCardShapeCommand` → `MainViewModel.CardShape` → `OnCardShapeChanged`（カスケードを閉じ、`settings.json` の `card_shape` に保存）。カードの形どうしの切り替えは、バインドで `CardGrid.CardShape` → `Rebuild` → `GridMetrics.ThumbHeight`
  - カード ↔ 詳細の切り替えでは項目のビューが入れ替わる：`MainWindow.xaml` のトリガーが `CardGrid` と `DetailsListView` の片方だけを表示し、`Items`（`SelectedTab.Cards`）も片方にだけ渡す（隠れた側は null）。`MainWindow.ActiveList` は `CardShape` から同じ側を返す
  - スクロール位置はビューごとの単位（カードの行の高さと 28 px の行は対応しない）なので、切り替えのとき `OnCardShapeChanged` が全タブの `ResetScrollOffsets`（離れたときの位置と、戻る・進むの履歴の位置）を呼び、表示中のビューを先頭へ戻す。順序に意味がある：`OnCardShapeChanged` は `CardShape` の変更通知より**前**に走るので、`View.ScrollTo(0)` は新しい側（まだ項目なし）に届く
  - 詳細表示ではカードの大きさのスライダーを無効にする（値は保持）。`RadioButton` の `Checked`（`OnViewModeChecked`）でも `CardShape` を入れる：UI オートメーションの「選択」はコマンドを実行せずにチェックだけを入れるため
- 詳細表示の列の幅（エクスプローラーと同じ形）：4 列（名前・更新日時・種類・サイズ）とも保存した幅を持ち、左から並べて、最後の列の右は空き（見出しと行の `Grid` の `*` の列）のまま。見出しのつまみ（4 本、各列の**右端**。`Tag` がキー）をドラッグ → 離したとき `DetailsListView.ColumnResized` → `MainViewModel.SetDetailsColumnWidth`（`Normalize(保存値 + 新しい幅)` を保存）→ `DetailsColumns`（差し替え）と `settings.json` の `details_columns` → バインドで `DetailsListView.Columns` → `UpdateColumns`（`DetailsColumns.Fit` → 見出しの列と `DetailsMetrics`）。
  - つまみは左側の列の幅を変える。左の列は動かないので、つまみはポインターに付いていく。ほかの列は巻き込まない：広げられるのは「開始時の表示幅 + 右の空き」と `MaxOf` の小さい方まで（`OnGripDragStarted` が `ColumnResize.MaxWidth` に入れる）。空きがないときは、先にほかの列（名前など）を狭める（横スクロールはない）。
  - `Fit`：保存した幅が収まればそのまま。収まらなければ名前を先に `NameMin`（120）まで縮め、それでも足りなければ更新日時・種類・サイズを `Min` より上の分に比例して縮める。名前は保存幅より広げない。結果は表示専用で、保存するのは利用者が決めた幅だけ（ウィンドウを広げると保存幅に戻る）。
  - ドラッグ中も保存値を `Fit` に通す：`ColumnResize.Widths` は開始時の保存値（`Normalize(Columns ?? Defaults)` のコピー）で、`OnGripDragDelta` はドラッグ中の列だけを書き換えて `UpdateColumns`。だから途中の見た目と離したあとの見た目は同じ。開始幅 `StartWidth` と上限 `MaxWidth` は表示幅とポインターから計算し、`OnGripDragCompleted` は開始時の保存幅 `StoredWidth` と比べて変わったときだけ報告する（動かさなかったつまみは何も保存しない）。表示幅（`Fit` の結果）を `Widths` に入れない：名前を縮んだ表示幅で保存すると、ウィンドウを広げても名前が戻らなくなる。
  - その帰結：ウィンドウが狭くて名前が保存幅より縮んでいる間にほかの列を狭めると、空いた分はまず名前に戻り、名前が保存幅に戻るまでつまみはその場に留まる。名前が最小まで縮み、ほかの列も比例で縮んでいるほど狭い一覧では、ドラッグの最初の移動でほかの列が比例配分し直されて少し跳ねることがある（途中と結果は一致する）。
  - `Math.Clamp` は下限が上限を超えると例外になるので、上限は `Math.Max(min, MaxWidth)` で守る。名前の保存幅（キー `name`）がない古い `settings.json` は `Normalize` が既定値 360 で埋める
- 規則（ピン留めは位置固定、新規項目の挿入位置）は Core の `Ordering/` にある。App 側で再実装しない

### 3.7 ドラッグ（フォルダへの移動・コピー、他アプリへ）

カード・行・プレビュー・サイドバーの行で、押したまま `FileDrag.IsDragGesture` のしきい値を超えたら開始 → `FileDragOut.CreateData`（`DataFormats.FileDrop` + 内部形式 `FolderDeck.DragSource`、最上位カードは `FolderDeck.CardReorder` も、サイドバーの行は `FolderDeck.SidebarReorder` も。見つからない登録フォルダの行は FileDrop なしで並べ替えだけ）→ `new OutgoingDrag(data, paths, moveAllowed, intoFolders)` → `CascadeController.BeginDrag` → `FileDragOut.Run`（`DoDragDrop`、許可する効果は `EffectsFor`：Copy | Link、全項目が `MainViewModel.CanCut` で実行中のファイル操作がなければ Move も）→ `EndDrag` → `MainViewModel.FinishDrag`。
選択の中の項目をドラッグすると選択全部（表示順。`MainViewModel.SelectionTargets`。無効・処理中の項目は除く）を渡す。並べ替えの形式を付けるのは最上位のカード 1 つのときだけ。カスケードの行は `DragOut(row, item, origin)`（プレビューは `preview.Item` で Move の可否を決める）。
- フォルダへのドロップ：ウィンドウの `OnDragOver` / `OnDrop` → `FolderDropOf`（`FolderTargetAt`：`OriginalSource` から親をたどり、フォルダのカード・詳細表示の行・サイドバーの登録フォルダ / ドライブの行。先は `PasteFolderOf`。処理中のカードは除く。読み込み中の一覧はヒットテストしないので当たらない）→ 元は自アプリなら `OutgoingDrag.Paths`、外からなら FileDrop（`ExternalPaths`、ドラッグごとに 1 回読む）→ `FileDrag.DropEffectFor`（実行中のファイル操作・名前の入力中は None）→ `SetDropMark`（`IsDropTarget`）と `ShowDropHint`（サイドバーの上端の帯。「「X」へ移動 / コピー」「ドロップして登録」）。
  - Drop：受け付けたら `e.Effects = DropResult`（Copy）。自アプリのドラッグは `OutgoingDrag.Dropped` に記録するだけで、`FinishDrag` が `DropAsync(paths, folder, kind, fromOtherApp: false)` を始める。外からのドラッグは `Dispatcher.BeginInvoke` で `DropAsync(..., fromOtherApp: true)`（8.3 形式を長い名前に戻してから）。`DropAsync` は `TransferIntoAsync`（`FolderExistsAsync` → `DescribeAsync` → `Decide(TransferOptions.Drop)` → `FileTransfer.RunAsync` → メッセージ）→ `ReloadAndSelectArrivedAsync`。切り取りの記録には触らない（次のアクティブ化の確認で片付く）。
  - 並べ替えのドラッグ（`CardGrid` / `DetailsListView` / `SidebarView` の `RunReorderDrag`）は自分の上の DragOver / Drop を処理済みにするので、ウィンドウには来ない。登録フォルダの行のドラッグ（`IntoFolders: false`）はフォルダへのドロップにならない。
- 他アプリへ Move で渡したあと（`Dropped` なし、`MoveAllowed`）：`WatchDraggedOut` が 0.5 / 2 / 5 秒後に存在を確かめ、減っていれば `ReloadAfterFileChangeAsync(cardCascadeOnly: true)`。確かめる前と後で、ファイル操作・名前の入力・アプリのドラッグの最中なら読み直さない（`CanReloadForDragOut`。ドラッグ中に読み直すと並べ替えのドロップが失われる）。3 回とも見送った・残っていれば、次の `OnActivatedAsync` か、次のアプリのドラッグが終わったとき（`FinishDrag`）に `CheckDraggedOutAsync` でもう一度だけ確かめる。戻り値は見ない（エクスプローラーの最適化された移動は None か Copy を返し、Esc も None）。
ドラッグ元はメインウィンドウか `CardGrid` / `SidebarView`（ドラッグ中に破棄されない要素）。エクスプローラーからのドロップ登録（`MainWindow.OnDrop` → `MainViewModel.RegisterDroppedAsync`）はフォルダの上以外のウィンドウ全体で受けるが、自アプリ由来のドラッグ（`IsOwnDrag`）は受け付けない。外からのドラッグが入ってきたら（`OnDragEnter`）カスケードを閉じる。

### 3.8 永続化

- `DataStores` が 6 つのファイルを持つ（一覧は [docs/specification.md の「データの置き場所」](../../docs/specification.md#1-データの置き場所)、`settings.json` の全キーとほかの JSON の形は同じ文書の「settings.json」「ほかのデータファイル」）。
- `StoreBase`：変更はメモリ上で `Gate` をロックして行い、`RequestSave` でバックグラウンド保存を予約（連続した変更は 1 回にまとまる）。書き込みは `JsonFile.WriteAtomic`（一時ファイル経由で置き換え）。終了時は `Flush`。
- 読み込み：壊れた JSON は `<名前>.broken-<UNIX秒>.json` に退避して空のデータで続ける（`LoadStatus.Recovered`）。退避もできなければ `Failed` → `IsDisabled` になり、そのファイルには以後書き込まない。
- JSON は snake_case（`JsonNamingPolicy.SnakeCaseLower`）、インデントつき。時刻は `LenientTimeConverter`（読めない値は null）。
- `SettingsStore.Current` は**毎回コピー**を返す。変更は `Settings.Update(s => …)`（→ `Normalize` → `RequestSave`）。
- **`settings.json` の版**：`version` 2 が現在の形（`open_tabs` にタブ列の全タブ、`selected_tab` に表示中のタブの位置）。version 1（常設の固定タブ 2 つ + フォルダのタブ：`last_tab` / `locations` / `selected_folder_tab`）は `AppSettings.Normalize` が `MigrateLegacyTabs` で移す（最近の履歴・よく使う項目・フォルダのタブの順に並べ、表示していたタブを選ぶ）。
  - 移行の条件は「`version` が 2 未満、**または** `last_tab` がある」。旧版の exe は version 2 のファイルを読むと `kind` を落として自分のキーを書き戻すので、そのあと新しい版で開いたときにもう一度移行できる（ダウングレードしてもタブは失われない。フォルダの中にいた固定タブはフォルダのタブになる）。
  - 旧形式のキーは移行後 null にし、**null のときは書き出さない**（`JsonIgnore(WhenWritingNull)`）。旧版は `selected_folder_tab: null` を数値として読めず、ファイル全体を壊れた扱いにするため。
  - `open_tabs` が無い（null）ときだけ初回起動として「最近の履歴」を開く。保存された空の配列は「全部閉じた」なので空のまま（`selected_tab` は −1）。`Normalize` は種類を正規化し（不明・なしは `folder`）、ルートのないフォルダのタブと 2 つ目以降の固定タブを落とし、落とした分だけ `selected_tab` をずらす。
- `details_columns`（詳細表示の列の幅）は `Normalize` が `DetailsColumns.Normalize` に通し、いつも `name` / `modified` / `type` / `size` の 4 つだけにする（無いキーは既定値、範囲外は名前 120〜2000・ほか 48〜600 に収める、知らないキーは捨てる）。
- `registered_folders.json` は imgtool と同じ形式のまま保つ。
- ストア以外に、画像サムネイルのキャッシュ `thumbs\`（`ThumbDiskCache`、[§3.2](#32-カードの段階読み込み741)）がある。消えても作り直すだけのデータで、`DataStores` には入らない。

### 3.9 テーマと文字の大きさ

`ThemeManager` が `App.xaml` の MergedDictionaries の 0 番を `Themes/Light.xaml` ↔ `Dark.xaml` に差し替える。色は `DynamicResource` で参照する。

- どちらを使うかは設定のテーマ（`AppSettings.Theme`：`system` / `light` / `dark`）で決まる：`AppThemes.IsDark(Mode, Windows のモード)`。「システム」のときだけ Windows のアプリモードを使い、`SystemEvents.UserPreferenceChanged` で追従する（固定のテーマでは変わらない）。
- 起動時：`App.OnStartup` がまず `Theme.Apply()`（設定を読む前なので Windows のモード）、ストアを読み込んだあとウィンドウを作る前に `Theme.Apply(AppThemes.FromSetting(settings.Theme))`。
- 設定ダイアログ：`SettingsViewModel.Theme` → OK → `MainViewModel.OpenSettings` が変更を見て `IMainView.ApplyTheme` → `MainWindow` → `ThemeManager.Apply(AppTheme)`（開いているウィンドウのタイトルバーも切り替える）。
- 文字の大きさ（`AppSettings.TextScale`、`text_scale`：100〜150 %、10 刻み）：`Views/TextScale.cs` が 100 % の基準の大きさ（定数）と `Size.*` のリソースのキーを持ち、`Apply(percent)` が計算した値を `Application.Current.Resources` の最上位に書く（マージした `Themes/Styles.xaml` の既定値より優先される）。ビューは `{DynamicResource Size.…}` で読むので、書けばすぐ変わる。対象はサイドバー・カードのフッター（名前と補足）・詳細表示（見出しと行）・カスケードの一覧（オーバーレイとフライアウトの行・見出し・件数）と名前の入力欄。タブ列・ツールバー・メニュー・ダイアログ・メッセージ行・ツールチップ・プレビュー・アイコン・バッジは変えない。
  - 文字は比例で、行の高さは余白を変えずに文字の分だけ伸ばす（`TextScale.RowHeight(base, font)` = `Math.Round(base + (倍率 − 1) × font × 1.35)`）。サイドバーの行と見出し 30（文字 13）、詳細表示の行 28（12.5）と見出し 28（12）、一覧の行 24（12）が 150 % で 39 / 36 / 36 / 32。カードの名前の 2 行の枠とフライアウトの見出しの 3 行の枠は比例。`FlyoutView.CardWidth`（280）と詳細表示の列の幅は変えない（130 % 以上では既定の幅の「更新日時」が省略される）。
  - 起動時：`App.OnStartup` が `Theme.Apply(…)` の直後、ウィンドウを作る前に `TextScale.Apply(settings.TextScale)`。設定ダイアログ：`SettingsViewModel.TextScale`（選択肢 `TextScaleChoices` は `TextScaleChoice` の並びで、`Toggle.Choice` の `RadioButton` を `ItemsControl` で作る。WPF 標準の `ComboBox` はダーク テーマに合わないため）→ OK → `MainViewModel.OpenSettings` が変更を見て `IMainView.ApplyTextScale` → `MainWindow.ApplyTextScale`（カスケードを閉じてから `TextScale.Apply`。開いていた一覧の位置が古い行の高さのままにならないため）。再起動は要らない。

### 3.10 タブ列とサイドバー

- **タブ列は 1 本**：`MainViewModel.Tabs` が開いているタブを左から順に全部持つ（`FolderTabStrip` が表示）。「最近の履歴」「よく使う項目」（固定タブ `RecentTab` / `FrequentTab`）はセッション中ずっと同じインスタンスで、`Tabs` にある間だけ開いている（`TabViewModel.IsOpen`）。フォルダのタブ（`TabKind.Folder`）は何個でも開ける。どの種類も閉じる・並べ替えができる。
- **タブなし**：タブを全部閉じると `SelectedTab` は代役の `NoTab`（`TabKind.None`、`IsPlaceholder`）になる。`SelectedTab` を null にしないための代役で（XAML のバインドと `SelectedTab.…` の参照がそのまま通る）、`Tabs` に入れず、読み込まず、移動先にもしない。表示中のタブを相手にする処理は `HasTab` で弾く（`NavigateAsync` / `BackToTop` / `GoUp` / `SetSortMode` / `SetFilter` / `ClearHistory` / `Refresh` / `ReloadAfterFileChangeAsync`）。`MainWindow` は `HasTab` が false の間ツールバーを隠し、案内文と「最近の履歴を開く」「よく使う項目を開く」のボタンを出す。
- **固定タブを開く** `OpenQuickTabAsync(kind)`（サイドバーの「クイック アクセス」の行、タブなしの画面のボタン）：開いていなければタブ列の右端に足して表示、開いていれば表示、表示中でフォルダの中にいれば一覧（最上位）へ戻る。
- **サイドバーの節**：`SidebarView` が「クイック アクセス」「登録フォルダ」「PC」の 3 つの節を縦に並べる。節の状態は `SidebarSectionViewModel`（`MainViewModel.QuickSection` / `RegisteredSection` / `PcSection`）が持ち、見出しのクリック（`ToggleCommand`）で開閉する。開閉は `MainViewModel.OnSectionChanged` がすぐ保存し（`sidebar_collapsed_sections`：**畳んだ節の ID だけ**を持つので、あとから増えた節は開いた状態で始まる）、`View?.CloseCascade()` を呼ぶ（下の行が動くので、行の横の一覧が置き去りになる）。高さの配分は `SidebarView.ApplyRowHeights`：登録フォルダを開いている間はその行の領域が残りを全部取り（中でスクロール）、PC の行はその下に必要な高さだけ、サイドバーの高さの 4 割まで（超えたら中でスクロール）。登録フォルダを畳んでいる間は PC の行が残りを取り、両方畳んでいる間は末尾の空き行が取る（見出しが上に詰まったままになる）。4 割の上限は行（`RowDefinition`）ではなく `PcScroller` の `MaxHeight` に付ける（Auto の行は中身を高さ無制限で測るので、行に付けても `ScrollViewer` がスクロールしない）。
- **クイック アクセスの行**：`RecentTab` / `FrequentTab` を `DataContext` にしたボタン。`TabViewModel.IsSelected` で塗り、`IsOpen` で右端に点を出す（タブ列と同じ状態を見ているので、別に同期するものはない）。カスケードの起点にはならない。
- **サイドバー全体の表示・非表示**：タブ列の左端のボタン（`ToggleSidebarCommand`）→ `IsSidebarCollapsed` → 保存（`sidebar_collapsed`）と `CloseCascade` → `MainWindow.ApplySidebarLayout` が列の幅・`SidebarPane`・`GridSplitter` を切り替える。隠している間も `SidebarWidth`（`sidebar_width`）は元の幅のまま持ち、戻すときに使う。隠している間のドロップ登録は受けるが、案内（`DropHint`）は出さない。`MainViewModel` はサイドバーの幅と折りたたみを**コンストラクタで**読む（`MainWindow` のコンストラクタが最初のレイアウトに使うため。`InitializeAsync` では遅い）。
- **登録フォルダの行**：`MainViewModel.Registered`（`SidebarItemViewModel`）を `SidebarView` が 1 行ずつ表示。`RefreshRegistered` が `RegisteredFoldersStore.Folders` と同じ順に揃える（残る行のインスタンスと要素は保つ：開いているカスケードがその要素に付いているため、`Clear` して作り直さない）。新しい行は `CheckRegisteredAsync`（`Existence.ProbeAsync`、2 秒）で `SidebarItemState` を決める。F5（`Refresh`）は全部の行を確認し直す。
- **PC の節（ドライブ）**：`MainViewModel.DriveList`（`DriveListViewModel`）の `Drives` を、登録フォルダと同じ行のテンプレートで表示する。
  - `RefreshAsync(recheck)`：`Task.Run(DriveCatalog.Enumerate)`（文字と種類だけ。媒体に触らない）→ ドライブ文字で突き合わせて行を揃える（残る行のインスタンスは保つ。登録フォルダと同じ理由）→ 新しいドライブと、前回使えなかったドライブを `DriveCatalog.Probe` で確認する。`recheck` が true なら全部を確認し直す（ラベルやディスクの入れ替え、ネットワーク ドライブの切断を拾う）。
  - 呼ぶのは 4 か所：起動（`InitializeAsync`。**待たない**：応答しないドライブが最初のタブを遅らせない）、F5（`Refresh`、recheck）、ボリュームの着脱（`MainWindowHook.DrivesChanged`、recheck：カード リーダーは文字が同じままメディアだけ替わる）、ウィンドウのアクティブ化（`OnActivatedReadDrives`、5 秒に 1 回まで、recheck なし：ネットワーク ドライブの割り当て・再接続では Windows がメッセージを送らないため）。
  - 確認は 1 ドライブにつき同時に 1 つ（`Slot.Probing`。走っている間に来た要求は終わってからもう 1 回）。2 秒で答えなければ行を「応答がありません」（`SidebarItemState.NoResponse`）にし、答えは来たときに反映する。古い結果を捨てる仕組みは 2 つ：一覧は `_generation`（あとから始めた読み直しがあれば捨てる。捨てられた側の recheck は `_recheckPending` で引き継ぐ）、確認は「そのドライブの `Slot` がまだ同じものか」（`IsCurrent`）。
  - 出すかどうかは `DriveRules.ShouldShow`：固定ディスクとネットワーク ドライブは確認の前から出す（確認中は `Checking` で、使える行と同じ見た目）。リムーバブルと光学ドライブは、確認でメディアがあると分かってから出す（空のカード リーダーは出さない）。使えないドライブ（接続されていないネットワーク ドライブなど）は `SidebarItemState.Missing` で、登録フォルダの「見つからない」と同じ見た目・同じ扱い（一覧もタブも開かない）。ツールチップの文言だけ違う。
  - クリックは `OpenDriveAsync` → `OpenFolderTabAsync(Target)`（`recordPath` なし）。ドラッグはしない（`SidebarView.TryStartDrag` がドライブの行では何もせず、押下はクリックのまま）。右クリックは `ItemContext.Drive` のメニュー（ピン留め・削除・登録の解除は出さない）。接続されていないドライブでも「エクスプローラーで表示」と右ボタン + 左クリックは通す（エクスプローラーが再接続を案内する）。
  - 見出しの右クリックは「エクスプローラーで開く」だけのメニュー：`SidebarView.OnPcHeaderRightUp` → `PcHeaderContextMenu` → `MainWindow.OnPcHeaderContextMenu`（カスケードを閉じる）→ `ContextMenuFactory.ShowPcSection` → `MainViewModel.OpenPcInExplorerAsync`。PC はパスではなく `ShellActions.ThisPcPath`（`::{20D04FE0-…}`）。設定（`OpenExplorerInNewTab`）がオンなら `ExplorerTabs.OpenAsync`、オフなら `Task.Run` で `ShellActions.OpenInExplorer`（explorer.exe）。利用記録には残さない。行で構えた右ボタン + 左クリック（`RockerGesture`）を見出しの上で離したときは、メニューを出さずにその行をエクスプローラーで表示する（`ItemExplorerRequested`）。
- **登録・解除**：登録フォルダの見出しの右のボタン（`BrowseCommand`。節を畳んでいても押せる）、ウィンドウへのドロップ（`RegisterDroppedAsync`）、右クリックの「登録フォルダに追加」（`AddToRegisteredAsync`）→ どれも `RegisteredChanged` → `RefreshRegistered`。解除は行の右クリック →`Unregister`（確認あり）。
- **フォルダのタブを開く**：行のクリック（`OpenRegisteredAsync`）、サイドバー起点のカスケードの行・見出し、最近の履歴・よく使う項目の最上位のフォルダのカード（`CardViewModel.ToItemRef`）とそこから出したカスケードの行・見出し（どれも `ItemRef.NewTab`）→ `OpenFolderTabAsync(target)`：同じ場所（`SameLocation`）を表示している**フォルダのタブ**があればそれを選び（固定タブが同じフォルダの中にいても別扱い）、なければ `AddFolderTab` で作って `ShowTabAsync`。`Root` が空の移動先では何も開かない。フォルダのタブの中のカード・パンくず・戻る／進むは `NavigateAsync`（そのタブの中で移動。`target.Tab == Folder` で表示中がフォルダのタブならそのタブ、固定タブやタブなしなら `OpenFolderTabAsync` へ回す。移動先が開いていない固定タブなら、タブ列に足してから移動する）。
- **タブの切り替え** `ShowTabAsync`：離れるタブのスクロール位置を `SavedScrollOffset` に保存（`LeaveSelectedTab`。閉じたばかりのタブと `NoTab` では保存しない）→ `SelectedTab` を替える（`OnSelectedTabChanged` が `IsSelected` を更新）→ 固定タブの最上位は毎回読み直し、フォルダは `IsStale` のときだけ読み直す → スクロール位置を戻す。`NoTab` へ替えるときは読み込みもスクロールもしない。
- **閉じる・並べ替え**：`CloseTabCommand`（× ・中クリック・Ctrl + W・エラー表示の「タブを閉じる」= `BackToTopCommand`）はどの種類のタブも閉じ、表示中だったら右隣（なければ左隣、タブが無くなれば `NoTab`）を表示。`RemoveFromStrip` がタブ列から外す：フォルダのタブは監視（`Watch`）ごと捨て、固定タブは `TabViewModel.ResetToTop`（最上位へ戻し、戻る／進むの履歴・カード・スクロール位置を捨てる）で次に開いたとき一覧から始まるようにする。閉じた固定タブもインスタンスは生きているので、監視は外さず、`AllTabs`（固定タブ 2 つ + 開いているフォルダのタブ）経由で `IsStale` も付け続ける。`CloseOtherTabsAsync`、`MoveTab`（`FolderTabStrip` のドラッグ）。
- **収まらないタブ列のスクロール**（`FolderTabStrip`）：`ScrollToHorizontalOffset` は次のレイアウトで効くので、続けて来るホイール（タッチパッドの横スクロールは細かく大量に来る）は `_pendingOffset`（`ScrollChanged` で捨てる）から足す。古い `HorizontalOffset` から足すと動きが消える。◀ / ▶ を出すかは、出している間はその幅を足し戻して判断する（出すと収まる・消すとはみ出す、の往復をしない）。出した直後は表示中のタブが右で切れうるので `RevealSelected` をやり直す。横ホイールのフックはメイン ウィンドウの `HwndSource` に付く（`MainWindowHook` とは別。こちらは `handled` を立てる）。
- **履歴**：戻る・進むはタブごと（`TabViewModel.BackStack` / `ForwardStack`）。タブをまたいでは戻らない。
- **保存**：`SaveState` が `open_tabs`（各タブの種類 + `Root` + `Rel`、タブ列の順）・`selected_tab`（タブなしは −1）・`sidebar_width` を書く（サイドバーの折りたたみは変えたときにその場で保存するので、ここでは書かない）。`open_tabs` / `selected_tab` を書くのは `InitializeAsync` がタブ列を復元し終えたあと（`_tabsRestored`）だけ：起動が途中で失敗したときに、作りかけのタブ列で保存済みの内容を上書きしないため。起動時に復元したフォルダのタブは、フォルダが無くなっていてもタブを残してエラー表示にする（固定タブは最上位へ戻す：`_restoring`）。
- **表示**：`FolderTabStrip` のテンプレートが `Kind` でアイコンと色を分ける（固定タブは `Brush.Accent` / `Brush.AccentSoft`、フォルダのタブは `Brush.Folder` / `Brush.FolderSoft`）。ツールバーのボタンは `SelectedTab` の `ShowFilter` / `ShowClearHistory` / `CanGoUp` / `BackText` で出し分ける（`NoTab` ではどれも出ない）。

### 3.11 アドレス欄と名前の変わったフォルダへの追従

- **アドレス欄**：`MainWindow` のツールバーの `AddressBar`（枠）の中に、パンくず `Crumbs` と入力欄 `AddressEdit` を重ねている。入力欄は使わない間 **`Collapsed`**（レイアウトから外す。[§7](#7-守ること落とし穴)の入力欄と UI オートメーション）、入力中はパンくずが `Hidden`（枠の高さはパンくずが決めるので、入力欄を出しても変わらない）。
  - パンくず：`TabViewModel.UpdateBreadcrumbs`（`Location` が変わるたび）が、表示中のフォルダのパスをドライブ・共有から 1 フォルダずつ並べる（`PathTools.AncestorsAndSelf(ParentOf(根))` → 根 → `Rel` の各部分。固定タブは一覧の名前が先頭）。根より上のフォルダの移動先は `NavLocation(Location.Tab, そのフォルダ, "")`（フォルダのタブの `GoUp` と同じく根が替わる。固定タブも一覧に戻らず、そのタブの中で根が替わる：`GoUp` の固定タブの分岐（一覧へ）とは違う）。区切り（`BreadcrumbItem.Separator`）は `\`、一覧の名前のあとは `›`、`\` で終わる名前（`E:\`）と最後のあとは無し。`UpdateBreadcrumbs` は項目を落とさない（旧版の文字数による中間の「…」は廃止）。狭いときは `TrailPanel` が表示の段階で先頭から外し（外した子は Tab でも止まらない）、「…」（ツールチップは `AddressText` = パス全体）を出し、最後の 1 つだけでも入らなければその名前を省略する（項目のテンプレートが `DockPanel` なのはそのため：`StackPanel` は子を幅無限で測り、省略が効かない）。パンくずに載せると、そのフォルダのサブフォルダの一覧が下に出る（カスケードのアンカー。[§3.3](#33-カスケードcascadecontroller9) の「開く（パンくず）」）。`TrailPanel` が外したパンくずには `MouseEnter` が来ないので出ない。
  - 始め方：枠の空いているところの左クリック（`OnAddressBarClick`。パンくずのボタンは自分のクリックを処理済みにするので通らない）、Ctrl + L / Alt + D / F4（`OnPreviewKeyDown`）→ `BeginAddressEdit`：表示中のタブの `CurrentFolderPath`（一覧では空）を入れて全部選び、枠の色を `Brush.Accent` に。そのタブの `PropertyChanged` を購読する（`Location` が変わったら終わる）。
  - 終わり方：Esc（`OnAddressKeyDown`）、入力欄の外の押下（`OnPreviewMouseDown`：項目はフォーカスを取らないので、フォーカスが外れるのを待つだけでは終わらない）、同じウィンドウの中へのフォーカスの移動（`OnAddressLostFocus`。入力欄のメニュー・ほかのアプリへの切り替えでは終わらない）、タブの切り替え（`SelectedTab` の変更）→ `EndAddressEdit`（フォーカスをウィンドウに戻す：`RenameEditor.FocusWindowItself`）。
  - Ctrl + Shift + C（`OnAddressKeyDown` → `ToggleAddressWslPath`）：入力欄の文字全体を `WslPath.Toggle` で置き換えて全部選ぶ（選択範囲ではなく全体）。変換できなければメッセージ行だけ。TextBox の既定のコピーは Ctrl + C だけなので Shift 付きはぶつからない。
  - 入力中のキー：`OnPreviewKeyDown` の `inTextBox` で、Backspace（1 つ上へ）・選択のキー（`HandleSelectionKey`：Ctrl + A / C / X / V、Delete、F2、Enter、Esc）・Ctrl + Shift + N は一覧に効かない。Ctrl + W・Alt + ← → は効く（移動すると入力欄は閉じる）。F5 は `EndAddressEdit` してから読み直す。

## 4. スレッドと非同期の規約

- **UI スレッドでブロッキング I/O をしない**。列挙・存在確認・JSON 読み込みは `Task.Run` か `FolderListingCache` の中で行う。
- 自動更新の確認は UI スレッドのタイマー（`DispatcherTimer`、1 秒）で判定し、列挙は `FolderListingCache` の作業スレッドだけ。確認は一度に 1 本で、15 秒で待つのをやめる（待つ側は自動更新だけなので、やめると列挙もキャンセルされる。固まった共有は `HoldAutoRefresh` で間隔を延ばす）。`FolderListingCache.Clear` / `Invalidate` は実行中の列挙も切り離す（`Detached`：後から来た要求は相乗りせず新しく列挙し、古い結果はキャッシュに入らない。F5・ファイル操作の後の読み込みが、操作前に始まった自動更新の列挙を拾わないため）。await の後は必ず条件を判定し直す（ShowDialog やドラッグのモーダルループの中でもタイマーは発火する）。
- シェル / COM の呼び出しは `StaWorkerPool` 上でタイムアウトつき（`ThumbnailService` は 4 本・5 秒、`AppServices.Shell` は 1 本、詳細表示の種類の名前 `TypeNameCache` は専用の 1 本・5 秒）。タイムアウトしたワーカーは放棄して作り直す（最大 16 本）。タイムアウトは**呼び出しが始まってから**数える（キューで待つ時間は含めない。画像の多いフォルダで待ち行列が長いだけの要求を打ち切らないため）。60 秒たっても始まらない要求は `QueueTimeoutException`（`TimeoutException` の派生。ワーカーが全部止まっている印なので、同じプールに代わりの処理を並べない：並べるともう 60 秒待ち、カードごとに WARN を UI スレッドで書いていた。WARN はプールごとに 1 回）。
  - 画像のデコード（`ImageDecoder`）は COM の STA を必要としないが、同じ `StaWorkerPool` を使う：`ThumbnailService` のデコード用ワーカー（コア数 − 1 本を 2〜8 本に丸める、優先度 BelowNormal、5 秒）。ディスクキャッシュの書き込み・刈り込みは `ThumbDiskCache` の 1 本（優先度 Lowest、タイムアウトなし）。
  - 例外：ごみ箱への移動（`RecycleBin`）とコピー・移動（`FileTransfer`、`StaThread.Run`）、名前の変更・新しいフォルダー（`ShellFileOps`、`StaThread.Run`）は操作ごとに専用の STA スレッドを作り、タイムアウトをつけない（シェルの進行状況・名前の衝突・「使用中」などのダイアログが利用者の操作を待つため）。UI スレッドは `await` で待つだけで止まらない。このスレッドはバックグラウンド スレッドなので、実行中にウィンドウを閉じると途中で切れる（`MainWindow.OnClosing` が確認する）。
  - エクスプローラーのメニュー（`ShellContextMenu`）は 1 回ごとに専用の STA スレッド（`StaThread.RunPumped`：Dispatcher を回す）と、そのスレッドのオーナー ウィンドウ（メイン ウィンドウに所有させない：スレッドをまたぐ所有は入力キューをつなぎ、応答しない拡張機能が UI の入力まで止める）。オーナーは WPF の `HwndSource` ではなく素の Win32 ウィンドウ（`Session.CreateOwner`：クラス `FolderDeckShellMenuOwner` をプロセスで 1 回 `RegisterClassEx`、`WS_EX_TOOLWINDOW` + `WS_POPUP` の 0×0、所有者なし。ウィンドウ プロシージャ `OwnerProc` は static の delegate（`OwnerProcDelegate`、GC させない）で、`[ThreadStatic]` の `_current` から Session を引き、メニューのメッセージを `Hook` → `IContextMenu3/2` へ、ほかは `DefWindowProc`。`Run` の finally で `GiveForegroundBack` → `DestroyWindow`）。理由：新しいスレッドの `HwndSource` は WPF のスタイラス入力（UI スレッドと共有のペン スレッド。カスケードの Popup の作成・破棄、クリックの `CloseAll` と同じ瞬間に重なる）への登録と描画の初期化をし、それが 5 秒の用意の中に入っていた（カスケード表示中のクリック直後の右クリックで時間切れ。推定）。Dispatcher（`RunPumped`）はコマンドの後に回すために残す。用意（`QueryContextMenu`）は 5 秒まで（呼び出し側のタイマーが止める旗を立て、表示の直前に見る。時間切れのメニューは出ない）、表示後とコマンドは無制限。用意は段階（`thread` → `owner` → `bind` → `query` → `verbs`。`EnterPhase` / `EndBuild`）を記録し、時間切れの WARN に段階・経過 ms・生きているメニューのスレッドの数（`_liveThreads`：`Start` で増やし、`RunPumped` の Task の継続で減らす。放棄されたスレッドは数えたまま）を、1 秒以上かかった用意は段階ごとの ms を INFO で書く（§8）。コマンドが 1 秒以上戻らなければ先に `Invoked` を返す。コマンドの後も 2 秒以上と、そのスレッドのウィンドウが見えている間はメッセージを回し続ける。一度に 1 つ（2 つ目は `Unavailable`）。応答しない拡張機能はスレッド 1 本を捨てるだけで済むが、異常終了する拡張機能はプロセスごと落とす。アプリの項目（「Windows のメニュー」）はこのスレッドで実行せず、`AppCommand` で返して UI スレッドで実行する。「Windows のメニュー」では右クリックのたびにこのスレッドを作るので、時間切れになった項目は 5 分間ネイティブのメニューを使わない（`ContextMenuFactory.TimedOutRecently`。毎回 5 秒待たされ、応答しないスレッドが 1 本ずつ溜まるため）。空白の右クリックの背景メニュー（`ShowBackgroundAsync`）も同じスレッド・同じ時間切れで、記憶だけ別（`_timedOutBackground`）。
  - クリップボード：書き込み（`ShellClipboard.TryWrite`）は UI スレッドで、ほかのアプリが開いていれば 100 ms で諦める。読み取り（`ReadWithSequenceAsync`）は専用スレッドで 2 秒まで（エクスプローラーは読まれたときに一覧を作るので、応答しない持ち主に読み手が止められる）。待つのをやめた読み取りが終わるまで、次の読み取りは即 null。
  - 貼り付けの元と先の確認（`SourceProbe`）はワーカーでタイムアウト付き（先 2 秒、元 5 秒）。元の確認が間に合わなかった項目は「削除できない」扱いになり、切り取りでもコピーになる。
  - ドラッグ＆ドロップ：DragOver では I/O をしない（効果は `FileDrag.DropEffectFor` の文字列の判定だけ）。Drop の中では待たず、転送も始めない：`e.Effects` を決めて返し、アプリ内のドラッグは `DoDragDrop` が戻ってから（`FinishDrag`）、エクスプローラーからのドラッグは `Dispatcher.BeginInvoke` で始める（エクスプローラーは Drop が戻るまで待っている。DoDragDrop のモーダルループの中でシェルのダイアログを出さない）。エクスプローラーからの 8.3 形式のパスは `DropAsync` がワーカーで長い名前に戻す（5 秒。間に合わなければ中止）。
- UI スレッドの見張り（`UiWatchdog`）：専用のバックグラウンド スレッドが 1 秒ごとに `Dispatcher.BeginInvoke(DispatcherPriority.Send, …)` を 1 つだけ送り（返るまで次を送らない）、返った時刻との差で判断する。このスレッドが自分の間隔の 5 倍より長く止まっていた（スリープ・中断）ときは、まだ WARN を出していなければ数え直す（報告中は数え直さない：間が空いたあとも UI が止まっていることがある。戻ったかどうかは ping の応答の回数 `_answers` で判断し、終了の前にも一度確かめる）。UI スレッドからは `UiWatchdog.Note` で文字列を 1 つ書くだけ（ロックなし）。
- 遅い・切断されたネットワークドライブ対策：`Existence` のタイムアウト（登録フォルダ 2 秒、履歴 1 秒）、`VolumeThrottle`、5 秒で「応答がありません」（`HoverTimings.Slow`、`TabViewModel.IsSlow`）。 アドレス欄の判定（`GoToAddressAsync`、5 秒）、フォルダの識別子の取得（2 秒）と検索（`FolderIdentity.Locate`、5 秒。元の親の中は 2,000 個まで）も `Task.Run` + `WaitAsync` で待つのをやめるだけ。
- ドライブの確認（`DriveCatalog.Probe`）は中断できない呼び出しなので、`Task.Run` + `WaitAsync(2 秒)` で**待つのをやめるだけ**にする（スレッド プールのスレッドは、システムが諦めるまで数十秒つかまることがある）。積み上がらないよう、同じドライブの確認は前のものが戻るまで始めない（`DriveListViewModel.ProbeAsync`）。`DriveListViewModel` の状態（`_slots`、`Drives`）は UI スレッドだけが触る：`RefreshAsync` は UI スレッドから呼ぶ。
- メモリ：シェルの絵を縮める `ShrinkPicture` はシェル用ワーカーの上で動かす（UI スレッドで縮めない）。`FolderListingCache` の掃除・追い出しは `_gate` の中で、`Complete`（列挙の作業スレッド）からだけ。メモリの行（`AppServices.DescribeMemory`）は UI スレッドで書くので、数えてある値を読むだけにする（キャッシュをたどらない）。
- キャンセル：タブは `TabViewModel._loadCts`、カードは `Realize` / `Unrealize` の CTS、プレビューは `Preview.Cts`。`OperationCanceledException` は握りつぶして終わる。
- ストアは内部でロックしてスレッドセーフ。`SaveFailed` はワーカースレッドで発火するので、UI へは `Dispatcher.BeginInvoke`。

## 7. 守ること・落とし穴

- **登録フォルダとタブのパスを書き換えるのは `MainViewModel.ApplyRename` だけ**（`RegisteredFoldersStore.Repath` と `TabViewModel.MoveTo` を直接呼ばない：戻る・進むの履歴、行の差し替え、保存が揃わなくなる）。識別子で探した結果は、ごみ箱（`$Recycle.Bin`）とシステムのフォルダの中なら使わない（`FolderIdentity.IsUsable`：削除は移動ではない）。名前からの推測で広げる付け替え（`WidestRename`）は、ディスクで元が無く先があると確かめてから。識別子は作成日時まで比べる（WSL は inode 番号を使い回す。実測で別のフォルダに同じ番号が付いた）。WSL の共有は .NET のプロセスには 128 ビットの ID を返さない（エラー 50。PowerShell 5.1 からは取れる）ので、`FolderIdentity.TryRead` の 64 ビットの番号への切り替えを外さない。

- **入力欄と UI オートメーション（ファイルの多いフォルダで固まった原因）**：レイアウトの中にある `TextBox` は、フォーカスを失ったあとも TSF（IME）にレイアウトの変化を知らせ続け、IME（Google 日本語入力で確認）の問い合わせ（`GetTextExt`）に答えるため WPF がその場で `UpdateLayout` する。UI オートメーションのクライアントがイベントを購読していると、そのレイアウトの終わりに WPF が自動化の木全体をたどって（`AutomationPeer.UpdateSubtree`）変更を知らせ、その COM 呼び出しがメッセージを処理しない待ち（そのとき Dispatcher の処理が止められていて、`DispatcherSynchronizationContext.Wait` がメッセージを回さなかった）で戻らなかった（2026-11-25、ダンプで確認）。守ること：(1) メイン ウィンドウの使っていない入力欄は `Collapsed`（`Hidden` はレイアウトに残る）か木から外す（設定画面のページは高さを保つため Hidden のまま：小さなモーダルで、開いている間は自動更新も止まり、閉じれば入力欄ごと消える。数値の欄は IME を切ってある）。(2) 入力欄にキーボードを持たせたまま大きな一覧を読み込まない・入力欄の配置を動かさない（アドレス欄は Enter の `leaving`・F5 で先に閉じ、入力中は `CountPanel` の幅を固定して自動更新も待つ）。(3) 項目の数だけ増えるビュー（カード・詳細表示の行）に自動化の子を増やさない：`ItemViewAutomationPeer`（名前だけの 1 要素）と `CardRowItems` / `DetailsRowItems` を外さない、項目の中に要素を足しても木は増えない。項目の Name / ItemStatus に件数やサムネイルの状態など、表示中に変わるものを入れない（変わるたびにカードごとの通知になる）。外すと、購読するクライアントがいる PC では 2 万件のフォルダで UI が 0.5〜1 秒単位で止まる（実測、2 万 200 件・20 秒・4 回ずつ：変更前 最大 521〜1,076 ms・0.1 秒を超えて止まった合計 2.6〜6.4 秒、変更後 最大 102〜222 ms・合計 0.1〜0.65 秒）。なお、普段のレイアウトのあとの通知はメッセージを回しながら待つ（`fireAutomationEvents` は `DisableProcessing` の外）ので、それ自体では固まらない。固まるのは IME の要求の中のレイアウトで、通知が多いほどその窓が長くなる。
- **ファイルを完全に削除しない**（自分のデータファイルを除く）。消す経路は右クリックの「削除（ごみ箱へ移動）」（1 項目・選択全部）と Delete キー（選択だけ）だけで、どれも確認ダイアログのあと `RecycleBin` でごみ箱へ移す（ごみ箱に入らない項目があれば、その項目と残りは中止）。複数は 1 つの `IFileOperation` で扱い、項目ごとに別の呼び出しに分けない（シンクの拒否で残り全部が止まる、という不変条件が 1 回の `PerformOperations` に頼っているため）。Shift + Delete の完全削除は作らない。
- **エクスプローラーのメニューから delete / rename / cut / copy / paste / undo / redo / format を外す**（`ShellContextMenu.RemovedVerbs`。項目のメニューと背景メニューで共通）。シェルの削除はごみ箱に入らない場所では完全に削除する。undo / redo はエクスプローラーのセッション全体の履歴で、表示中のフォルダと関係ないコピー・移動・新規作成を取り消せる（＝消せる）。format は念のため（ルートの背景メニューには出ない想定）。外し損ねた項目（サブメニューの中、verb が後で読めた）も、選ばれたときに verb を見て実行しない（`Dismissed`）。親が 1 つの経路では verb が読めない項目は残る（外せない）ので、親が複数の経路と背景メニューで verb が 1 つも読めなければメニューを出さない（`Unavailable`）。ドライブの行には出さない（「フォーマット」が並ぶ）、`ShowAsync` もドライブそのもの（`IsTransferable` が false）を断る。`ShowBackgroundAsync` はルートを通す（フォーマット・取り出しはドライブの項目のメニューのもので、ルートの背景のものではない、という推定。実機で確かめる）。
- **「Windows のメニュー」のアプリの項目の ID はシェルの範囲の外に置く**（`AppFirstId` 0xE000 〜 `AppIdLimit` 0xF000。シェルに渡すのは 1〜0x7FFF で、ハンドラーには少しはみ出すものがある。0xF000 以上は `SC_*` のシステム コマンド）。選ばれた ID は、シェルの範囲の確認と `GetCommandString` より**先に**アプリの範囲かを見る（ハンドラーが配っていないオフセットで verb を聞かない・`InvokeCommand` しない）。並びの位置がそのまま `AppIndex` なので、`ShowEntries` に渡した並びと実行する並びを別々に作らない。
- **シェルの open を外すのは、「Windows のメニュー」で既定の項目（1 項目の「開く」）があるときだけ**。copyaspath もアプリの項目を載せたときだけ外す。どちらも `RemovedWithAppEntries` / その場の追加で外すだけで、`RemovedVerbs` に入れない（選んだあとに断る対象になり、「その他のメニュー（Windows）」のシェルの「開く」まで動かなくなる）。選択全部のメニューには既定の項目を付けない（アプリは複数を開けないので、シェルの open を残す）。
- **WPF のメニューの経路を消さない**。「Windows のメニュー」でも、ドライブの行・PC の見出し・表示中のフォルダがない空白・使えない項目・時間切れから 5 分以内の項目は WPF のメニューで、ネイティブのメニューが出なかったとき（`Unavailable`、表示前の `Failed`、`TimedOut`）も `OpenFallback` で同じ並びを出す。`OpenFallback` は結果を受けたらその場で開く（間に await を入れると、右クリックから遅れて関係ない場所に出る・カスケードの状態が変わる）。`TimedOut` のメニューは後から出ない（`TrackPopupMenuEx` の前で段階を取り消す）ので、代わりを出しても二重にならない。表示後の `Failed` には代わりを出さない（利用者は一度メニューを見ている）。
- **エクスプローラーのメニューのオーナーに WPF の `HwndSource` を使わない**（`ShellContextMenu.Session.CreateOwner` の素の Win32 ウィンドウのまま）。メニューのスレッドで `HwndSource` を作ると、WPF のスタイラス入力（UI スレッドと共有のペン スレッド）への登録と描画の初期化が 5 秒の用意の中で走り、カスケードの Popup の作成・破棄と重なって時間切れになりうる。ウィンドウ プロシージャ（`OwnerProc`）から例外を出さない（ネイティブのコールバックなのでプロセスが落ちる）、delegate を static のフィールドで持ち続ける（GC されるとクラスのプロシージャが消える）、`Run` の finally の `GiveForegroundBack` を外さない（前面が見えないオーナーに残ると、メイン ウィンドウにキーが届かない）。メニューのスレッドで WPF の要素やウィンドウを作らない（同じ理由）。
- 項目の領域の空白の右クリック（`OnContentRightUp`）を項目のメニューに回すのは、`ItemsViewHitTest.Find` が**位置で**見つけた、表示領域の中の実体化済みの項目だけ。ヒットテストには頼れない（読み込み中は項目のビューがヒットテストを止めている）。読み込み中に出したメニューの項目は、読み直しで置き換わる前の `CardViewModel` のパスを対象にする（残っているリスク）。空白のメニューの対象（表示中のフォルダ）は `ShownFolderItem`（= `TransferTargetPath`）から取り、`FolderTargetPath` を使わない（読み込み中・失敗したフォルダの背景メニューを出さない）。項目のメニューと背景メニューの時間切れの記憶（`_timedOut` / `_timedOutBackground`）を 1 つにまとめない（作る拡張機能が違う）。
- **範囲選択**：キャプチャは `PART_Scroll` に Element で（SubTree だとカード・行が MouseEnter を受けてカスケード・トラッカーが動く。ビュー自身だとホイールが届かない）。原点とピッチは実体化した行の位置と `ActualWidth` / `ActualHeight` から（ItemsPresenter の余白はスクロールしない。`Metrics.CardWidth` や `RowHeight` を使うと 125 % 以上で列・行の数だけずれる）。`ReleaseMouseCapture` は同期で `LostMouseCapture` を出す（`_done` で無視）。キャプチャ中の右ボタンの離しは `ContentHost` へ届く（`OnContentRightUp` で止める）。`Key.System`（Alt + F4）は処理済みにしない。自動スクロールのタイマーは並べ替えのもの（`_autoScrollTimer`）と別。
- **コピー・移動は `FileTransfer` だけ**（貼り付け：`MainViewModel.PasteAsync`、フォルダへのドロップ：`DropAsync`）。`IFileOperation` でシェルの衝突・確認のダイアログを必ず出し、`FOF_NOCONFIRMATION` などの確認を省くフラグを使わない。ドライブそのもの（`C:\`、`\\server\share`）は元にしない（`TransferRules`）。上書きするかはいつもシェルのダイアログで利用者が決める。ドラッグでは：Drop は移動のときも Copy を返す（Move を返すと元のアプリが元を消しうる。こちらの転送はまだ始まっておらず、衝突のダイアログでスキップもある）、`DoDragDrop` の戻り値で元を消さない、アプリ内のドラッグのパスは FileDrop（8.3 形式）ではなく `OutgoingDrag.Paths` を使う、Move を許可するのは全項目が切り取れるときだけ（最近の履歴の一覧のカード・登録フォルダの行はコピーかショートカット）、最上位の 1 枚の並べ替えのドラッグは一覧の中のフォルダに入らない（グリッドが処理済みにする）。アプリが切り取った項目をエクスプローラーで貼り付けたときの移動はエクスプローラーが行う。自分のデータのうち画像サムネイルのキャッシュ（`thumbs\`）は上限を超えると古いものを消すが、消すのは自分が付けた名前（`DiskCacheRules.IsCacheFileName`）のファイルだけ。
- **名前の変更・新しいフォルダーは `ShellFileOps` だけ**（`MainViewModel.RenameAsync` / `CreateFolderAsync`）。`File.Move` / `Directory.CreateDirectory` で書かない（エクスプローラーの元に戻すに載らない、UI スレッドで止まる）。
  - 名前は先に `ItemNames.Clean` / `Check` に通す。シェルは予約名（`CON`、`NUL.txt`、`COM¹`…）を普通のファイルとして作り、`: \ /` を含む名前では「フォルダーを作成しますか」と聞いてくる（Windows 11 26200 で確認）。末尾のピリオド・空白はディスクでは消えるのに、シェルは渡した名前のまま報告する。
  - 同じ名前は `ShellFileOps.Rename` が先に確かめて `NameTaken` にする。シェルに任せると、ファイルの衝突は「予期しないエラー 0x80070057」の画面になり、フォルダ同士は統合を勧められる。`FOF_NOCONFIRMATION` は既存のファイルを黙って上書きするので使わない。
  - 名前の入力欄（`RenameEditor`）を終わらせる経路を足すときは `End` を通す（1 回だけ・先に session を外す）。名前を変える処理は `Committed` から `Dispatcher.BeginInvoke` で後に回す（確認ダイアログをマウス・フォーカスのイベントの中で開くと、押下と離しの組がずれる）。入力欄は項目のビューの子ではないので、項目の祖先で押下に反応する処理は `TextBoxBase` も項目と同じに扱う（`IsOnItemOrControl`）。入力中に効くキーを足さない（`OnPreviewKeyDown` の先頭で返す）。入力中に一覧を読み直す処理を足さない（項目のビューが作り直されると入力途中の名前で確定される。ウィンドウのアクティブ化の読み直しは `_activationPending` で後に回している）。`ConfirmDialog` は押しっぱなしのキーの繰り返しを受けない（名前を確定した Enter の繰り返しが、拡張子の確認の既定のボタンを押さないため）。
- **自動更新**：タイマーから `Refresh` / `ReloadAfterFileChangeAsync` / `LoadAsync` を呼ばない（一覧が暗くなる、キャッシュ全体が消える、カスケードが閉じる。NotFound が 2 回続いたときの `LoadAsync` だけは例外）。読む前に `Listings.Invalidate` する（しないと TTL 60 秒のキャッシュが返る）。`Attributes` を比べない（オンライン専用のファイルはサムネイルを作るとクラウドの属性が変わり、自分で再読み込みを繰り返す）。名前の入力欄は一覧の差し替えで確定してしまうので、`IsNameBusy` の間は待つ。
- **UI スレッドで待たない**（[§4](#4-スレッドと非同期の規約)）。シェル呼び出しは必ず STA ワーカー経由でタイムアウトをつける。
- パスの比較は `PathTools.PathEquals` / `PathSet`（大文字小文字を区別せず正規化）。`==` で比べない。長いパスをシェルに渡すときは `PathTools.ForShell`。
- `SettingsStore.Current` を書き換えても保存されない（コピーのため）。`Update` を使う。
- 並び順は `_baseCards` を基準に `Ordered` で作る。`Cards` を直接並べ替えない。ピン・ドラッグ順の規則は Core の関数を使う。`Cards` はフィルターで項目が減っていることがあるので、位置（何番目か）を基準順と突き合わせる処理は `OrderedCards` を使う。
- タブは 1 つの種類に 1 つとは限らない（フォルダのタブは何個でも）。`TabKind` からタブを引かず、`TabViewModel` の参照（`SelectedTab`、`Tabs`）で扱う。全タブに効かせる処理は `MainViewModel.AllTabs`（固定タブ 2 つは閉じていても含む。`Tabs` は開いているタブだけ）。
- `SelectedTab` はタブなしの代役 `NoTab`（`TabKind.None`）のことがある。`Kind` の `switch` には `None` の腕を、表示中のタブを読み込む・動かす・設定を保存する処理には `HasTab` の確認を入れる。抜けると、空の `Root` のフォルダのタブができたり、代役のタブの並び方が `settings.json` に残ったりする。
- 一覧の行（`EntryListView` の `ListBox`）でマウスキャプチャを使って何かを待たない。`ListBox` は左ボタンを離すたびに自分のキャプチャを手放す（処理済みのイベントでも）。待ち状態は `RockerGesture` のようにフラグで持ち、取り消す条件を決める。
- サイドバーを隠すときは列の `MinWidth` を 0 にしてから幅を 0 にする（`MainWindow.ApplySidebarLayout`。`MinWidth` が残ると空の帯が残る）。隠している間は列の実幅（0）を `SidebarWidth` に書かない（`OnSplitterDragCompleted` のガード）。
- サイドバーのトグルはサイドバーの列の右にあり、押すと自分が横へ動く。ダブルクリックの 2 回目以降の押下が、その位置に来た節の見出しやタブに届かないよう、`MainWindow.OnPreviewMouseDown` が切り替え直後の `ClickCount > 1` の左押下を捨てる（`_sidebarJustToggled`。次の 1 回目の押下で解除）。トグルの位置を変えるとき・切り替えの経路を増やすときはこのガードを確かめる。
- サイドバーの行（`SidebarItemViewModel`）は登録フォルダとドライブの 2 種類ある。登録フォルダだけの処理（`FindRegistered`、`Unregister`、`MoveRegistered`、並べ替えドラッグ）にドライブの行を渡さない。行で分岐するときは `IsDrive`、`ItemRef` では `ItemContext.Drive` を見る。
- ドライブの一覧（`DriveCatalog.Enumerate`）で媒体に触らない。空のカード リーダー・眠っているディスク・届かないサーバーで一覧そのものが止まる。触るのは `Probe` だけで、呼ぶ側（`DriveListViewModel`）が 2 秒で待つのをやめる。
- ドライブの行は利用者の操作なしで消える。行の要素に何かを付けるとき（カスケードなど）は、`DriveListViewModel.RowRemoved` で片づける（消えた要素は `MouseLeave` を出さない。カスケードは `CascadeController.AnchorRemoved`）。
- パンくず（`BreadcrumbItem`）も場所の変更・タブの切り替えで操作なしに差し替わる。カスケードの起点なので、`MainWindow.WatchCrumbs` / `DropCrumbs` が古い項目ごとに `AnchorRemoved` を呼ぶ（購読を漏らすと、消えた要素の下に一覧が残る）。`UpdateBreadcrumbs` は同じパスなら項目を作り直さない（`SameAs`）：作り直すと読み込みのたび（F5・自動更新）に一覧が消える。
- `MenuAim`（`IsHeadingForChildOf`）は横に出る子しか扱わない（縦の辺への三角形）。下に出す一覧（`OpensBelow`）は `IsHeadingForChildOf(-1)` で除いている。下に出す階層を増やすときは判定も足す。
- カスケードを開く条件に `Window.IsActive` を戻さない（[§3.3](#33-カスケードcascadecontroller9)）。項目のビュー（カードグリッド・詳細表示）の都合で閉じるときは `CloseAll` ではなく `CloseCardCascade` を使う。
- 項目のビューは 2 つ（`CardGrid`、`DetailsListView`）あり、**隠れている側には `Items` を渡さない**（null）。両方に渡すと、見えていないカードが `Realize` してサムネイルを読み、隠れた一覧がコンテナーを抱え続ける。`MainWindow` からビューを触るときは `Grid` / `Details` を直接使わず `ActiveList` を通す（隠れた側のスクロール位置を読み書きしない）。スクロール位置はビューをまたいで使わない（`ResetScrollOffsets`）。隠れていた側は `Collapsed` のまま `Items` を受け取り（その時点の `ActualWidth` は 0）、前と同じ大きさで再表示されると `SizeChanged` は来ない。幅に依存する計算（`CardGrid.Rebuild` の列数、`DetailsListView.UpdateColumns`）は `IsVisibleChanged`（true）でもやり直す。`Details` はタブなし（`HasTab` が false）のときも隠す（列の見出しだけが残るため）。
- 詳細表示の行で `CardViewModel.Realize` を呼ばない（[§3.2](#32-カードの段階読み込み741)）。行のセルに足してよいのは、一覧を作った時点で分かる値と、拡張子ごとにキャッシュされる値だけ。
- 詳細表示の見出しと行の列は別々の `Grid` で、幅を `DetailsMetrics` で揃えているだけ。片方の列・余白だけを変えるとずれる（スクロール バーは常に表示して幅を見出し側で空けてある：`Auto` に戻すと、一覧が長くなった瞬間に列が動く）。どちらも 名前 / 更新日時 / 種類 / サイズ / `*`（空き）/ End の 6 列で、行の × は列 5、選択枠は `ColumnSpan` 6。見出しの `Grid` は `ClipToBounds`（狭い一覧で列がはみ出すため）。
- 詳細表示の列の幅は `DetailsColumns.Fit` の結果（表示用）を保存しない。ドラッグ中の `ColumnResize.Widths` も保存値から作る（表示幅で作ると、縮んで見えている名前の幅がそのまま保存される）。ドラッグで変えるのはその 1 列と右の空きだけで、ほかの列の保存幅は変えない。
- 階層なしのプレビュー（詳細表示のファイルの行。`Preview.ParentIndex` が -1）がある。`CascadeController` でアンカーの経路の「開いているか」は `IsOpen` で見る（`_levels.Count` ではない）。`_levels[ParentIndex]` を引く処理を足すときは `ParentIndex >= 0` を先に確かめる。行の強調は `MarkSource` で付け外しする（直接 `row.IsActive` を書くと、アンカーの `IsHoverHeld` が残る・付かない）。
- カード・詳細表示の行の普通の左押下は処理済みにならない（`ItemPointerTracker`。クリックは離したときに決まる）。ウィンドウや項目の親で左押下に反応する処理を足すときは、`e.OriginalSource` から項目（`CardView` / `DetailsRowView`）の上の押下かどうかを確かめる。確かめずに押下の時点で何かを変えると、離したときのクリック・ドラッグの判定より先に効いてしまう（例：`MainWindow.OnContentLeftDown` の選択の解除。無条件に外すと、選択した項目を押してドラッグしようとした時点で選択が消える）。
- 選択・切り取りの印はカード（`CardViewModel`）に持たせず、タブの `Selection` / `CutPaths`（パス）から写す。カードは読み込み・並べ替えで作り直されるので、カードの `IsSelected` を直接書き換えても次の表示で消える。
- 貼り付け先に `FolderTargetPath` をそのまま使わない。読み込み中・失敗したフォルダへ貼り付けないよう、項目なしの貼り付けは `TransferTargetPath` を使う。`TransferTargetPath` に `IsStale` の条件を足さない：`RecordUse` / `TogglePin` は表示中の最近の履歴・よく使う項目のタブ（中のフォルダを表示中）にも `IsStale` を付けるので、貼り付けが F5 まで止まる。
- Ctrl + C / X / V、Delete、Enter はキーの繰り返し（`e.IsRepeat`）で動かさず（押しっぱなしの Delete で確認が続けて出ない。押しっぱなしの Enter で同じファイルを何度も開かない）、テキスト ボックスの中では何もしない。Ctrl + C / X、Delete、Enter はポインターの下の項目を対象にしない（選択だけ）。Enter はメニューの表示中（`IsMenuOpen`・ContextMenu の中）には使わない（メニューの項目の Enter を奪わない）。`HandleKey` の Enter を KeyRow がなくても true にしない（ホバーで開いたカスケードの上で選択の Enter が消える）。
- カスケードの開閉判断を `CascadeController` の外に書かない。ドラッグ中にポップアップを破棄しない（`DoDragDrop` がボタンを離したことに気づかなくなる）。
- メニュー エイムの座標は画面の物理ピクセル（`GetCursorPos`、`ScreenRect` / `PointToScreen`）だけで比べる。DIP の値（`AimSlack` など）は DPI を掛けてから混ぜる。
- **カスケードの Popup（フライアウト・プレビュー）は `OpenOn` で開く**（`IsOpen = true` を直接書かない）。WPF の Popup は開くたびにウィンドウを作り直し、作った位置のモニターの DPI で描き続ける。開いている間の WM_DPICHANGED は `Popup.OnDpiChanged` が処理済みにして捨てるので、`Place` でウィンドウを別のモニターへ動かしても倍率は変わらない。
  - PlacementTarget がないと (0,0)、つまりプライマリ モニターに作られる。プライマリが 200 % の PC では、100 % のモニターの行から開いた一覧が 2 倍に描かれた。
  - `OpenOn` は行の要素を PlacementTarget にして、その左上のモニターでウィンドウを作らせ、作ったら外す（位置は offset で決まる。Placement は Absolute）。
  - `MonitorOf` は、WPF がウィンドウを作るモニター（行の左上を整数に切り捨てた点）と行の中心のモニターの DPI が同じなら中心のモニター（以前どおり）、違えば左上のモニターを返す。作業領域・概算の位置・`CardMaxHeight`・サムネイルの画素数の倍率は、これで Popup の DPI と一致する。違う DPI のモニターの作業領域に置くと、そこでは倍率が合わない。
  - Absolute の offset は Popup 自身の DPI の DIP（WPF は Popup の `TransformToDevice` で物理ピクセルに直す）。メイン ウィンドウの DPI で割らない。`Place` の寸法も Popup の `TransformToDevice` を使う。
  - PlacementTarget を付けると、WPF は前面のウィンドウにたどれるとき（メイン ウィンドウがアクティブなとき）target のウィンドウを Popup の所有者にする。`OpenOn` は作った直後に所有者を外す（`ShellInterop.ClearOwner`）。所有されたままだと、フライアウトの中の行から開いた WPF のメニューやツールチップがフライアウトの所有になり、フライアウトが先に閉じると一緒に破棄されて `Closed` が来ない（`_menuOpen` が戻らず、一覧が閉じなくなる）。
- WPF の ContextMenu も、PlacementTarget の左上のモニターの DPI で描かれる。ウィンドウが DPI の違うモニターにまたがっていると、右クリックした点のモニターと倍率が合わないことがある（未対応。またいだときだけ）。
- **画面構成の変化のあと（HDMI の差し替え、Win + P、解像度・拡大率の変更）**：「アプリを選んでも最前面に出ない」不具合の原因は未確認（推定の仮説：別の GPU に出力が移って WPF の描画先が止まる、古い配置の最前面の Popup が残る、ウィンドウが見えないモニターに残る、アクティブになっても z-order が上がらない）。`MainWindow.OnDisplayChanged` はまず `display:` の行を書いてから回復の処理をする。次に起きたときにその行で仮説を見分けるので、行を減らさない（[§8](#8-調べ方のショートカット)）。
  - 画面内へ戻すのは `WindowState.Normal` のウィンドウ（メイン ウィンドウと `OwnedWindows` の `ConfirmDialog` / `SettingsWindow`）で、タイトルバーの帯がどのモニターにも載らないときだけ（`IsTitleStripOnAnyMonitor`。起動時の `RestorePlacement` と同じ規則）。計算と移動は物理ピクセル（`GetWindowRect`、`GetMonitorArea`、`ShellInterop.MoveWindow`）。`Left` / `Top` はウィンドウのモニターの DPI の DIP、`SystemParameters.WorkArea` はプライマリの DIP で、拡大率の違うモニターでは混ぜられない。最大化・最小化のウィンドウは Windows に任せる（動かすと `RestoreBounds` が壊れ、保存する位置が狂う）。
  - カスケードは閉じるだけで、動かしたり作り直したりしない（`OpenOn` の DPI と所有者の約束）。エクスプローラーのメニュー・ドラッグの間は `CloseAll` が何もしない（それぞれが終わったときに閉じる）。強制的に閉じる経路を足さない。
  - `RefreshRendering` は `HwndTarget.RenderMode` を一度 SoftwareOnly にして Render 優先度で Default に戻す（描画先を作り直させる）。`RenderOptions.ProcessRenderMode` が SoftwareOnly のときは何もしない。
  - `RaiseToTop`（`SetWindowPos(HWND_TOP, NOMOVE | NOSIZE | NOACTIVATE)`）は変化から 2 分以内のアクティブ化で、前面が自分のときだけ。`SWP_NOOWNERZORDER` を付けない（所有するダイアログも一緒に上げる）。ウィンドウ プロシージャの中では呼ばない（`MainWindowHook.Activated` は後に回して出す）。前面を奪う細工（`AttachThreadInput`、アクティブ化での `Topmost` の切り替え）は足さない：Windows がアクティブ化を断った場合（タスク バーのボタンが点滅するだけ）は `WM_ACTIVATE` が来ず、ここでは何もできない。
- 文字の大きさ：`Size.*` のキーは `TextScale.cs` の定数と `Themes/Styles.xaml` の既定値の 2 か所にある。片方だけ変えると、起動直後（`Apply` の前）と後で見た目が変わる、または `Apply` が上書きして効かない。`DetailsListView.RowHeight` は定数ではなく `TextScale` に従う。行の高さは整数の DIP に丸めてあるが、レイアウトの丸めでデバイス ピクセルにそろうので（125 % で 30 DIP の行は 30.4 DIP）、行を順に数えて位置を出す処理（`DetailsListView.HitTestInsertion`）は実体化した行の `ActualHeight` を使う。カードの高さも一定ではない（フッターが文字とともに伸びる。`GridMetrics` は幅・サムネイル・アイコンだけを決め、位置は実際のレイアウトから取る）。
- **「オンラインのみ」のファイルを読むのは `ThumbnailService.DownloadAsync` だけ**（画像のサムネイル・プレビュー用。利用者の求め）。ほかに中身を読む処理（Office・テキスト・埋め込み縮小版など）を足すときは `FileContent.IsCloudOnly` で避ける（読むとダウンロードが始まる）。ダウンロードは画像だけ・カードとプレビューだけ（表紙はしない）・100 MB 以下に限る。ダウンロードに失敗・取り消し・大きすぎた画像のアイコンはキャッシュしない（`IsCloudOnlyIcon`）。
- **ビュー（コードビハインド）から VM のイベントを購読するのは、読み込まれている間だけ**（`CardView.Attach` / `Detach`：`Loaded` で購読して `UpdateAll` で取り戻し、`Unloaded` と `DataContextChanged` の先頭で外す）。`CardGrid.Rebuild`（タブの切り替え・並べ替え・列の数・カードの大きさや形の変更）は行（`RowsHost.ItemsSource`）を作り直し、捨てた `CardView` の DataContext を WPF は消さない。外さないと、長く生きる `CardViewModel`（隠れたタブのものも）が `PropertyChanged` 経由で捨てたカードを行の部分木ごと持ち続け、Rebuild のたびに増える（タブを複数開くとメモリが 700 MB 程度まで増えた原因の 1 つ）。VM と一緒に捨てるビュー（`PreviewView` と `PreviewViewModel`）や、ウィンドウと同じだけ生きる相手（`MainViewModel`、選択中のタブ）は対象外。
- **`FolderListingCache._cache` へは `Put` / `Drop` だけで書く**（項目の合計 `_totalWeight` / `_totalEntries` がずれると、追い出しが過剰・不足になる）。期限切れの一覧は二度と返さないので、`Trim` で消しても挙動は変わらない。入れたばかりの一覧（`keep`）は消さない。1 つの一覧の重さを予算の 1/4 で頭打ちにしているのは、表示中の巨大なフォルダ 1 つで、ほかの一覧を毎回すべて追い出さないため（巨大な一覧はタブの `_shownListing` が持ち続けるので、キャッシュから外してもメモリは減らない）。
- **シェル・Office の埋め込みから絵を取る経路を足すときは `ShrinkPicture`（`ImageDecoder.Shrink`）を通す**。通さないと要求より大きい段の絵（1 枚 数 MB）が LRU と実体化中のカードに残る。`HasOpaqueCorners` のような判定は縮める前の絵で行う。
- シェルが返すビットマップの上下と非乗算アルファの扱いは `ShellInterop` に閉じている（`docs/specification.md`「実装メモ」）。安易に反転しない。
- `tools/dev.ps1` は UTF-8（BOM 付き）、BAT は ASCII のみ。
- **csproj の `FolderDeckInvalidateR2ROnModeChange` を消さない**。self-contained（composite：`FolderDeck.r2r.dll` + 中身のない部品の dll）と framework-dependent（非 composite）は、ReadyToRun の中間出力 `obj\Release\net10.0-windows\win-x64\R2R` を共有する。SDK の `_CreateR2RImages` は IL より新しければ作り直さないので、このターゲットがないと `publish.bat` の直後の `publish.bat framework` が composite の部品だけを同梱し、起動直後に coreclr が fail fast する（0xc0000602、`app.log` は 1 行も出ない。`DOTNET_ReadyToRun=0` では起きないので、R2R を疑う）。ターゲットは SDK の内部名（`_CreateR2RImages`、`_ReadyToRunOutputPath`）に依存し、名前が変わると黙って動かなくなる。SDK を上げたら `publish.bat` → `publish.bat framework` の順に作り、2 回目のログに `ReadyToRun: mode changed` が出ること・その exe が起動することを確かめる。`-p:SelfContained` 以外で R2R の作り方を変える引数（`PublishReadyToRunComposite` など）を足すときは、モードの文字列（`_FolderDeckR2RMode`）にも入れる。
- コード中のコメントは英語、UI 文言は日本語の直書き。
- コメントの記号：`§n.n` = 旧仕様書の節、`R1`〜 = 旧仕様書 §20 のリスク、`P0` / `P1` / `P2` = 優先度、`AC-nn` = 旧仕様書 §18 の受け入れ基準。旧仕様書は削除済みで、読むときは [§0](#0-このドキュメントの位置づけ) の `git show` を使う。

## 9. 本書の更新ルール

次の変更をしたときは、同じコミット（または同じ PR）で本書を更新する。

- ファイル・クラスの追加 / 削除 / 改名、責務の移動（[§2](#2-ファイルマップ)）
- 処理の流れ・スレッド規約・永続化の方式の変更（[§3](#3-主要な処理の流れ)、[§4](#4-スレッドと非同期の規約)）
- 改修レシピの手順が変わる変更、新しく繰り返しそうな改修（[§5](#5-改修レシピ)に行を足す）
- テストファイル・テストクラスの追加（[§6](#6-テストビルド)）

見出しを追加・改名・番号替えしたら、冒頭の[目次](#目次)（節番号・見出し・1 行説明）も同じコミットで直す。別の目録（`_topics.yml` や front matter）は作らない。文書が増えたら、[§0](#0-このドキュメントの位置づけ) の表に行を足す。

本書以外の文書も同じコミットで直す：利用者から見える挙動・設定・データファイルを変えたら `docs/specification.md` の該当節（設定を足したら「settings.json」のキー表と「設定」の表）、機能を追加・削除したら README の「主な機能」、BAT・`tools/*.ps1`・発行の手順を変えたら `docs/development.md`。`docs/` の 2 つの文書も冒頭の目次を見出しと合わせる。
