## 1. 目的と背景

### 1.1 背景

imgtool の「登録フォルダ」タブでは、任意のフォルダを登録してカード形式で閲覧できる。カードにマウスを乗せるとサブフォルダ名の一覧が出て、さらに名前に乗せると、そのサブフォルダの中のフォルダ名（最大15件）と最初の画像をプレビュー表示する。

ただし、この仕組みは画像フォルダを前提にしている。実際に登録したいフォルダは、文書や資料など画像以外のファイルが多い。また WEB アプリのため、ファイルを開くまでの操作がブラウザとバックエンドの往復になっている。

### 1.2 目的

- 登録フォルダのカード表示とホバー一覧を、独立した Windows ネイティブアプリとして作り直す。
- ホバー時のプレビューを、画像から**ファイル一覧**に変える。
- サブフォルダの中にさらにサブフォルダがあれば、マウスを乗せていくだけで次の階層の一覧を次々に表示する（多段カスケード）。表示されたファイルはクリックで開ける。エクスプローラーで1階層ずつ開いて掘り下げる手間をなくすのが狙い。
- 「登録フォルダ」に加えて「最近の履歴」「よく使う項目」のタブを設ける。3つのタブはどれも同じカード表示にする。

| 用語 | 意味 |

| 項目 | フォルダまたはファイル。どちらも絶対パスで識別する |

| 利用記録 | このアプリで項目を開いたり、項目へ移動したりしたときの記録。「最近の履歴」と「よく使う項目」の元データになる |

| LRU | Least Recently Used。使われていないものから捨てるキャッシュ方式 |

| COM | Component Object Model。Windows のシェル機能（サムネイル、ショートカット）を呼ぶための仕組み |

| UNC | Universal Naming Convention。`\\server\share\...` 形式のネットワークパス |
| BOM | Byte Order Mark。UTF-8 ファイルの先頭に付くことがある3バイトの印 |
| MSIX | Windows のアプリパッケージ形式。このアプリでは使わない |

## 3. スコープ

### 3.1 対象（作るもの）

1. タブが3つあるメインウィンドウ（登録フォルダ／最近の履歴／よく使う項目）
2. 全タブで共通のカードグリッド（フォルダもファイルもカードで表示する）
3. カード上のオーバーレイと、何段でも続くフライアウト（カスケード）
4. ファイルを既定のアプリで開く機能、エクスプローラーで表示する機能
5. 登録フォルダの登録・登録解除・保存、imgtool の登録内容の取り込み
6. 利用記録と、Windows の「最近使った項目」の読み込み
7. 頻度と直近度による順位付けと、手動のピン留め
8. 設定の保存（ウィンドウ位置、カードサイズ、各タブの現在地など）

### 3.2 対象外（作らないもの）

- imgtool のダウンロード、マージ、作者別整理などの機能
- imgtool 本体（WEB アプリ）の変更
- ファイル操作（コピー、移動、削除、名前の変更、新規作成）
- ファイル名の検索、全文検索
- タスクトレイ常駐、グローバルホットキー、Windows 起動時の自動起動
- Windows シェルのコンテキストメニュー（エクスプローラーの右クリックメニュー）をそのまま出すこと。アプリ独自の右クリックメニューは作る（§11）
- インストーラー、MSIX パッケージ、自動更新
- 画像ビューアーなど、アプリ内でファイルの中身を表示する機能

## 4. 技術スタックとプロジェクト構成

### 4.1 技術スタック（必須）

| 区分 | 採用 | 備考 |
|---|---|---|
| UI | WPF | `net10.0-windows`、`UseWPF=true` |
| 言語 | C#（.NET 10 の既定バージョン） | Nullable を有効にする |
| MVVM | CommunityToolkit.Mvvm | `ObservableObject`、`RelayCommand` など |
| 仮想化 WrapPanel | NuGet パッケージ `VirtualizingWrapPanel` | 推奨。採用前にライセンス（MIT と推定）を確認する。合わなければ自作してよい |
| Win32 / COM 連携 | Microsoft.Windows.CsWin32 | ソースジェネレーター。`NativeMethods.txt` に API 名を並べる |
| JSON | System.Text.Json | |
| テスト | xUnit | Core だけを対象にする |

CsWin32 で生成する API の候補は次のとおり（必要に応じて増やす）。

- `SHCreateItemFromParsingName`、`IShellItem`、`IShellItemImageFactory`：サムネイルとアイコンの取得
- `IShellLinkW`、`IPersistFile`：`.lnk` のリンク先の解決
- `StrCmpLogicalW`：自然順の比較
- `SHGetFileInfo`：小さいアイコンの取得（`IShellItemImageFactory` で足りれば使わなくてよい）
- `MonitorFromPoint`、`GetMonitorInfo`：モニターの作業領域の取得
- `SHAddToRecentDocs`：P2 の設定で使う（§10.4）

### 4.2 プロジェクト構成（推奨）

```
FolderDeck/
  FolderDeck.sln
  Directory.Build.props        共通設定（Nullable、LangVersion、TreatWarningsAsErrors は任意）
  src/
    FolderDeck.App/            WPF。View、ViewModel、Popup の制御、シェル連携
      Views/                   MainWindow、CardGrid、Card、Overlay、Flyout、ダイアログ
      ViewModels/
      Shell/                   サムネイル、アイコン、.lnk の解決、開く、エクスプローラーで表示
      Themes/                  Light.xaml / Dark.xaml（§15）
      app.manifest
      NativeMethods.txt        シェル連携の API（サムネイル、.lnk、モニターなど）
    FolderDeck.Core/           UI に依存しないロジック（net10.0-windows）
      NativeMethods.txt        StrCmpLogicalW だけ（Core にも CsWin32 を入れる）
      Paths/                   入力の正規化、比較キー、表示名
      Listing/                 フォルダ列挙、フィルタ、並べ替え、カバー探索、キャッシュ
      Stores/                  JSON の保存（登録・利用記録・ピン・除外・設定）
      Ranking/                 最近の履歴のマージ、よく使う項目のスコア
  tests/
    FolderDeck.Core.Tests/     xUnit
  tools/
    make-fixture.ps1           検証用フォルダツリーを作るスクリプト（§19.3）
  README.md                    ビルド、起動、データの置き場所（日本語）
```

- Core は `net10.0-windows` を対象にしてよい（`StrCmpLogicalW` を使うため）。テストは Windows 上の `dotnet.exe test` で動かす。
- ファイルシステムと時刻は、インターフェース（`IFileSystem` や `IClock` など）越しに使う。テストで差し替えられるようにするため（推奨）。

### 4.3 アプリのマニフェスト（必須）

- `longPathAware` を `true` にする（260文字を超えるパスに対応するため）。
- DPI 認識を `PerMonitorV2` にする。

### 4.4 単一インスタンス（必須）

- 名前付き Mutex（例：`Local\FolderDeck.SingleInstance`）で、すでに起動しているかを確かめる。
- 2つ目を起動したときは、既存のウィンドウを前面に出し（最小化中なら元に戻す）、2つ目はすぐ終了する。既存のウィンドウへの通知方法は任意（名前付きパイプ、ウィンドウメッセージなど）。

### 4.5 配布（必須）

- 非パッケージ（MSIX にしない）で、self-contained の single-file exe（win-x64）として配布する。

```
dotnet.exe publish src/FolderDeck.App -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
```

- WPF のネイティブ DLL を exe に含めるため、`IncludeNativeLibrariesForSelfExtract=true` を付ける。これを付けても exe の横にファイルが残るかどうかは**未確認**（§20 U7）。残る場合は、出力フォルダごと配布してよい。

### 5.2 タブ（P0）

- 「登録フォルダ」「最近の履歴」「よく使う項目」の3つ。どのタブも、カードグリッドとナビゲーション（§8）の部品を共有する。
- 現在地はタブごとに持つ。タブを切り替えても、それぞれの現在地を覚えている。

### 5.3 ツールバー（P0）

| 要素 | 動作 |
|---|---|
| ↑ ボタン | 1つ上へ移動する（§8）。最上位では無効にする |
| パンくず | `タブ名 / 起点項目名 / サブフォルダ… / 現在地`。どこを押してもその場所へ移動する。起点項目のツールチップにはフルパスを出す。長いときは中央の要素を「…」で省略する |
| 件数 | 最上位では「登録 N」「履歴 N」「項目 N」。フォルダの中では「フォルダ N / ファイル M」 |
| サイズスライダー | カードの大きさ（§6.9）。ツールチップは「カードの大きさ（Ctrl + ホイールでも変更できます）」 |
| 更新ボタン | 現在の一覧とキャッシュを読み直す。F5 でも同じ。読み込み中はスピナーを出して無効にする |
| ⚙ ボタン | 設定ダイアログを開く（§14。P1） |

### 5.4 メッセージ行（P0）

- 種類は「成功」「情報」「エラー」の3つ。成功と情報は5秒後に自動で消し、エラーは次の操作まで残す。
- 文言は日本語にする。例外メッセージをそのまま出してよいのは「詳細」の部分だけ。

### 5.5 記憶する状態（P0）

次の状態を `settings.json`（§13）に保存し、次回の起動時に戻す。

- ウィンドウの位置・サイズ・最大化の状態。保存した位置が今の画面構成で見えなくなる場合は、主モニターの中央に出す。
- 最後に開いていたタブ
- タブごとの現在地（§8.1）。起動時にその場所がなければ、そのタブの最上位を出す。
- カードサイズ（全タブ共通）
- 設定項目（§14）

## 6. カード（全タブ共通）

### 6.1 グリッド（P0）

- カードを左から右へ並べ、端で折り返し、縦にスクロールする。項目が数千件あっても重くならないよう、UI を仮想化する（必須）。
- 列数と幅は次の式で決める（元アプリの CSS `repeat(auto-fill, minmax(size, 1fr))` と同じ考え方）。
  - 列数 = `max(1, floor((表示幅 + 12) / (カードサイズ + 12)))`
  - カード幅 = `(表示幅 − 12 × (列数 − 1)) / 列数`
  - カード同士の間隔は縦横とも 12px（DIP）にする。
- 読み込み中は前の一覧を不透明度 0.55 で残し、クリックできないようにする。
- 空のときは中央に文言を出す。
  - 登録フォルダの最上位：「登録フォルダはまだありません。上の入力欄にパスを貼り付けるか「参照…」で追加してください。」
  - 最近の履歴：「最近の履歴はありません。」（Windows 側の記録が無効なら §10.2 の注記も出す）
  - よく使う項目：「よく使う項目はまだありません。ファイルやフォルダを開くと、ここに並びます。右クリックの「ピン留め」でも追加できます。」
  - フォルダの中：「このフォルダは空です。」

### 6.2 カードの構成（P0）

```
┌─────────────────┐  ← 角丸 10px、枠 1px（--border）、背景 --surface-2
│                 │
│   サムネイル      │  ← 縦横比 3:4（幅 × 4/3 が高さ）、背景 --surface-3
│   （§6.4）       │     ホバーするとオーバーレイ（§9.2）がここに重なる
│                 │
├─────────────────┤
│ 名前は2行まで、    │  ← 12.5px、行間 1.35、最小で2行分の高さ。全幅を使い、超えたら「…」
│ はみ出したら…     │
│ E:\資料\2026      │  ← サブ行（11px、--muted、1行で省略）。最上位のカードだけ
│         📁 3 📄 12│  ← 件数バッジ（右寄せ、角丸の丸型、11.5px、太字、等幅数字）
└─────────────────┘
```

- 名前の折り返しは文字単位でよい。ただし行頭禁則（「。」「」」などを行頭に置かない）を守ることが望ましい（推奨。WPF の TextBlock で実現が難しければ、文字単位の折り返しでよい）。
- ツールチップには次の内容を出す。
  - 1行目：フルパス
  - 2行目：クリックしたときの動作（§6.8）
  - 最近の履歴とよく使う項目では、3行目に最終利用日時（`yyyy/MM/dd HH:mm`）
- 最近の履歴のサブ行は「相対時刻 · 親フォルダのパス」にする（例：`3時間前 · E:\資料\2026`）。相対時刻は「たった今」「N分前」「N時間前」「昨日」「N日前」、7日より前は `yyyy/MM/dd`。

### 6.3 カードの種類（P0）

| 種類 | 条件 | 見た目 |
|---|---|---|
| フォルダ | フォルダとして存在する | バッジをアクセント色にする（背景 --accent-soft、文字 --accent） |
| ファイル | ファイルとして存在する | バッジを通常色にする（背景 --surface-3、文字 --muted） |
| 見つからない | 登録フォルダのパスがない（移動した、ドライブを外したなど） | 名前に取り消し線を引き、バッジは「見つかりません」（--warn-soft / --warn）、サムネイルに ⚠ を出す。カード全体を無効にし（不透明度 0.6）、×（登録解除）は常に出す |
| 応答なし | 存在を確かめる処理が2秒以内に終わらない（ネットワークドライブなど） | 「見つからない」と同じ見た目にし、バッジを「応答がありません」にする。更新すると確かめ直す |

「見つからない」「応答なし」になるのは登録フォルダのカードだけ。最近の履歴とよく使う項目では、存在しない項目は表示しない（§10.2、§10.3）。

### 6.4 サムネイル（P0）

**フォルダ**
1. カバー画像を探す（元アプリと同じ規則）。
   - そのフォルダの直下で、自然順で最初の画像ファイルを使う。
   - 直下になければ、サブフォルダを自然順で深さ優先にたどり、最初に見つかった画像を使う。
   - 対象の拡張子：`.jpg .jpeg .png .gif .webp .bmp`（大文字小文字は区別しない）
   - 探索の深さは最大6階層まで。
   - 探索の上限は、1枚のカードにつき64フォルダまで（新規。画像のないツリーで延々と探さないため）。
   - リパースポイント（ジャンクションやシンボリックリンク）はたどらない（循環を防ぐため）。
   - 列挙のフィルタ（§7.2）に従う。
2. カバー画像が見つからなければ、フォルダのシェルサムネイル（`IShellItemImageFactory`。Windows のフォルダアイコンに中身が透けて見える表示）を使う。
3. それも取れなければ、フォルダのアイコンを中央に出す。

**ファイル**
1. ファイルのシェルサムネイル（`IShellItemImageFactory`。画像・動画・PDF など、Windows がサムネイルを作れる形式）を使う。
2. 取れなければ、ファイルのシェルアイコンを出す。

**表示のしかた**
- カバー画像が見つかったときは、その画像ファイルのシェルサムネイル（`IShellItemImageFactory`）を出す。
- サムネイル画像は、枠いっぱいに切り抜いて上を基準に揃える（CSS の `object-fit: cover; object-position: top` と同じ）。
- アイコンは引き伸ばさず、48〜96px で中央に置く。
- 読み込み中は背景色だけを出す。取得に失敗したらアイコン表示に切り替える。

**取得とキャッシュ**
- 要求サイズは、カード幅 × DPI 倍率を 256 / 512 のどちらかに切り上げて決める（キャッシュの効きをよくするため）。
- 取得はバックグラウンドで行う。同時に取得するのは最大4件まで（元アプリと同じ）。
- `IShellItemImageFactory` は STA（シングルスレッドアパートメント）の専用ワーカースレッドで呼ぶ（推奨。サムネイルを作る拡張機能の中には STA を前提にするものがあるため）。
- 画面外に出たカードの取得要求は取り消す。
- メモリ上に LRU キャッシュを置く（既定 512 件）。キーは `正規化パス | 更新日時 | サイズ | 要求サイズ`。ディスクのキャッシュは Windows の thumbcache に任せ、アプリでは持たない。
- カバー画像の探索結果は、フォルダの列挙キャッシュ（§7.4）と同じ TTL でキャッシュする。

### 6.5 件数バッジ（P0）

- フォルダのカード：`📁 フォルダ数` と `📄 ファイル数` を並べる。0 の方は出さない。両方 0 なら `📄 0` を出す。
  - **元アプリからの変更**：「画像の枚数」を「ファイル数（種類を問わない）」に置き換える。
  - 数えるのは直下の項目だけで、列挙のフィルタ（§7.2）を通したあとの件数にする。
- ファイルのカード：拡張子（大文字、例 `PDF`）と、読みやすい単位のサイズ（例 `1.2 MB`）。
- 絵文字の代わりに Segoe Fluent Icons や Segoe MDL2 Assets のグリフを使ってよい（推奨）。

### 6.6 ホバー時の見た目（P0）

- 枠線をアクセント色（--accent）にし、影を付け、カードを 1px 上へ動かす（120ms のアニメーション）。
- オーバーレイやフライアウトを表示している間は、カードのホバー状態を保つ。
- 無効なカードは見た目を変えない。

### 6.7 × ボタン（P0）

- カードにホバーすると右上（上 6px、右 6px、直径 26px の丸）に出す。ホバーすると --danger の色に変える。
- 動作はタブごとに違う。

| タブ | ツールチップ | 動作 |
|---|---|---|
| 登録フォルダ（最上位） | 登録を解除（フォルダ内のファイルは削除されません） | 確認ダイアログ（§10.1）のあと登録を解除する |
| 最近の履歴（最上位） | 履歴から外す（ファイルは削除されません） | 確認なしで除外する（§10.2） |
| よく使う項目（最上位） | ピン留めなら「ピン留めを外す」、そうでなければ「一覧から外す」 | 確認なしで実行する（§10.3） |
| フォルダの中（どのタブでも） | 出さない | ― |

### 6.8 クリック動作（P0）

| 対象 | 左クリック | 右クリック |
|---|---|---|
| フォルダのカード | アプリ内でそのフォルダへ移動する（§8） | 右クリックメニュー（§11） |
| ファイルのカード | 既定のアプリで開く（§12） | 右クリックメニュー |
| 見つからない・応答なし | 何もしない | 右クリックメニュー（登録解除だけ有効） |
| ダブルクリック | 左クリックと同じ（2回分を実行しない） | ― |

- **元アプリからの変更**：元アプリは「サブフォルダがあれば中に入り、画像だけなら最初の画像を開く」という動作だった。新アプリでは「フォルダは中に入る、ファイルは開く」の一律にする。空のフォルダにも入れる（「このフォルダは空です。」を出す）。
- 項目を開いている間は、そのカードの上に半透明の黒（不透明度 0.35）とスピナーを重ねる。

### 6.9 カードサイズ（P0）

- 範囲は 120〜400、20刻み、既定 200（DIP）。値は列の最小幅として使う（§6.1）。
- スライダーのほか、グリッド上で Ctrl + ホイールでも変えられる（上で大きく、下で小さく）。このときグリッドのスクロールはしない。
- 全タブで共有し、保存する。

## 7. フォルダ内容の列挙規則（全機能共通）

カードの件数、フォルダの中のカード一覧、オーバーレイ、フライアウトは、すべてこの規則で列挙する。

### 7.1 並べ方（必須）

- フォルダを先に、ファイルを後に並べる。
- それぞれの中は自然順にする。比較には `StrCmpLogicalW` を使う（エクスプローラーと同じ並び）。
  - 元アプリは独自の自然順（大文字小文字を区別せず、数字の並びを数値として比べる）だった。`StrCmpLogicalW` もおおむね同じ結果になる。

### 7.2 フィルタ（必須）

- 名前が `.` で始まる項目は除く（元アプリと同じ）。
- 隠し属性とシステム属性の項目は、既定で除く。設定（§14）の「隠しファイルを表示」が ON なら含める。
  - .NET の `EnumerationOptions.AttributesToSkip` を使えば簡単に実現できる（既定値は Hidden | System）。
- アクセスできない子項目は黙って飛ばす（`IgnoreInaccessible = true`）。ただし、フォルダそのものにアクセスできないときはエラー状態にする（§9.8）。

### 7.3 種類の判定

- ジャンクションとシンボリックリンクは、リンク先の種類（フォルダかファイルか）として扱う。1階層ずつ列挙するので循環しても問題はない（カバー探索だけはたどらない。§6.4）。
- `.lnk`（ショートカット）と `.url` はファイルとして扱う。開くと Windows がリンク先を開く。フォルダへのショートカットをカスケードで展開する機能は P2（§9.4）。

### 7.4 非同期処理とキャッシュ（必須）

- 列挙はすべてバックグラウンドのスレッドで行い、UI スレッドでは行わない。
- 列挙ごとに `CancellationToken` を渡し、要らなくなった列挙（ホバーが外れた、場所を移動したなど）は取り消す。
- 列挙の結果は、パスごとに TTL 60秒でキャッシュする（元アプリのホバープレビューのキャッシュと同じ値）。更新（F5）でキャッシュを捨てる。
- 同じパスの列挙が同時に複数要求されたら、1回の列挙にまとめる（推奨）。

### 7.4.1 段階的な読み込み（必須）

5,000 件のサブフォルダがあるフォルダでも、§16 の目標時間内に表示するため、次の2段階で読み込む。

1. **一覧の読み込み**
   - 現在地の直下を1回だけ列挙し、名前と種類（フォルダかファイルか）を得る。
   - それだけでカードの枠（名前とアイコン）を並べる。
2. **カードごとの詳細の読み込み**
   - フォルダのカードでは件数・子項目の一覧・カバー画像、ファイルのカードではサイズとサムネイルを読み込む。
   - 読み込むのは、画面に実体化した（仮想化で生成された）カードだけ。画面の外へスクロールしたら、要求を取り消す。
   - 同時に読み込むのは最大8件まで（推奨）。

- 詳細を読み込んでいる間、件数バッジは `…` を出す（`0` は出さない）。
- オーバーレイを出すかどうか（§9.2）は、件数を読み込んだあとに判定する。読み込む前にホバーした場合は、読み込みが終わった時点でまだホバーしていて、T_overlay を過ぎていれば出す。
- 元アプリの `list_folder` は、すべての子フォルダの件数とカバー画像を一度に求めていた。新アプリでは、この方式を**採らない**。

### 7.5 遅いドライブやエラー（必須）

- 列挙が5秒以内に終わらないときは「応答がありません（待機中…）」と表示する。列挙は続け、終わったら結果に切り替える。
- エラーの種類に応じて、次の文言を出す。
  - アクセス拒否：「アクセスが拒否されました」
  - パスがない：「見つかりません」
  - その他：「読み込めません：<詳細>」

### 7.6 長いパス（必須）

- 260文字を超えるパスでも、列挙、件数の取得、サムネイルの取得、開く操作ができること。
- .NET の `System.IO` は長いパスを扱えると推定している（**未確認**）。シェル API（`SHCreateItemFromParsingName` や ShellExecute）は MAX_PATH の制限を受けるおそれがある（**未確認**）。§19.3 の検証用フォルダで確かめる。シェル API で扱えない場合は、サムネイルをアイコンで代用する。開けなかった場合はエラーメッセージを出す。

## 8. ナビゲーション（元アプリから引き継ぐ）

### 8.1 現在地の表し方

- 現在地は `{ タブ, 起点, 相対パス }` で表す。
  - 登録フォルダでは、起点を登録 ID にする（登録フォルダのパスが変わっても追えるようにするため）。
  - 最近の履歴とよく使う項目では、起点を起点項目の正規化パスにする。
  - 相対パスは起点から下のパス。`""` は起点そのものを表す。起点が `""` ならタブの最上位。
- フォルダのカードやカスケード内のフォルダを押すと、起点はそのカードの起点項目のまま、相対パスだけを深くする。
  - 例：「最近の履歴」で `E:\資料` のカードのカスケードから `2026\見積\確定` を押す → 起点 `E:\資料`、相対パス `2026\見積\確定`

### 8.2 操作（P0）

| 操作 | 動作 |
|---|---|
| ↑ ボタン、Backspace | 1つ上へ移動する。起点そのものにいるときは、そのタブの最上位へ戻る。Backspace は、入力欄にフォーカスがあるときやダイアログを開いているときは効かない |
| パンくず | 押した場所へ移動する |
| マウスの戻る／進むボタン（XButton1 / XButton2）、Alt + ← / → | 移動の履歴をたどる |
| F5 | 更新する |

### 8.3 移動の履歴（P0）

- 移動するたびに `{ タブ, 起点, 相対パス }` を戻る用のスタックに積む（最大100件）。戻ったあとに新しく移動したら、進む用のスタックは捨てる。
- タブの切り替えは履歴に積まない。ただし、戻る・進むで復元するときは、その記録のタブに切り替える。
- 移動したらグリッドのスクロール位置を先頭に戻す。戻る・進むでは前のスクロール位置を戻すのが望ましい（任意）。

### 8.4 移動先がなくなっていたとき

- 移動先のフォルダがなくなっていたら、エラーの帯を出す。
  - 文言：「フォルダが見つかりません：<パス>」
  - 帯の中に「<タブ名>の一覧に戻る」ボタンを置く。

## 9. ホバー一覧とカスケード（新規・最重要）

### 9.1 全体像

```
 メインウィンドウ内                          別ウィンドウ（Popup）。メインウィンドウの外まで出てよい
┌──────────────┐
│ ┌──────────┐ │       ┌ フライアウト（第2階層）┐     ┌ フライアウト（第3階層）┐
│ │オーバーレイ │ │       │ 見積                │     │ 確定                │
│ │（第1階層）  │ │       │ 📁 2  📄 14         │     │ 📄 3               │
│ │📁 2025   ▶│ │       ├────────────────────┤     ├────────────────────┤
│ │📁 見積   ▶│─┼──────→│📁 確定           ▶ │────→│📄 A社_見積.pdf      │
│ │📄 メモ.txt │ │       │📁 下書き         ▶ │     │📄 B社_見積.xlsx     │
│ │📄 一覧.xlsx│ │       │📄 単価表.xlsx       │     │📄 送付状.docx       │
│ └──────────┘ │       │📄 …                 │     └────────────────────┘
│  資料          │       └────────────────────┘
│       📁2 📄2  │
└──────────────┘
```

- 第1階層（オーバーレイ）はカードの中に重ねて描く。第2階層からあと（フライアウト）は WPF の `Popup` で別ウィンドウとして出し、メインウィンドウの外まではみ出してよい。
- どの階層でも、ファイルを押すと開き、フォルダを押すとアプリ内でそのフォルダへ移動する。

### 9.2 第1階層：オーバーレイ（P0）

- **出す条件**：フォルダのカードで、子項目が1件以上あるとき。ファイルのカード、無効なカード、空のフォルダでは出さない。
- **出すタイミング**：カードにホバーして 300ms 後に、150ms かけてフェードインする（グリッドの上でポインタを動かしただけで一覧がちらつかないようにするため）。カードから離れたら 120ms でフェードアウトする。ただしカスケードを開いているときは §9.6 に従う。
- **位置と大きさ**：サムネイル部分（3:4 の領域）にちょうど重ねる。フッター（名前とバッジ）は覆わず、押せば従来どおりそのフォルダに入る。
- **見た目**
  - 背景は `rgba(12,15,20,0.86)`、文字は `#f3f5f8`、12px、行間 1.4。テーマにかかわらずこの色にする。
  - 内側の余白は上下 8px、左右 10px。上の角だけ丸める。
- **見出し**：`フォルダ N / ファイル M` を出す（11px、太字、`#b9c3d3`）。背景は不透明（`rgb(12,15,20)`）にし、スクロールしても上に固定する。
- **本体**：子項目の一覧（§9.4 の行）。長ければ縦にスクロールする（仮想化。細いスクロールバー）。
- **ホイール**：一覧の上でホイールを回したら一覧だけをスクロールし、グリッドにはスクロールを伝えない。一覧の端まで来ても伝えない。
- 一覧の内容は、カードの件数を出すために列挙した結果（キャッシュ。§7.4.1）を使う。
- 一覧の行がない余白や見出しをクリックしても何もしない（元アプリと同じ）。

### 9.3 第2階層以降：フライアウト（P0）

- **出す条件**：オーバーレイかフライアウトのフォルダ行に 150ms ポインタを止めたとき。そのフォルダを列挙して、行の横に出す。
- **階層の深さ**：上限は設けない。
- **大きさ**：幅は 280px（DIP）。高さは中身に合わせ、作業領域の高さ − 16px を上限とし、超えた分はスクロールさせる（仮想化）。
- **見た目**
  - 背景は `rgba(12,15,20,0.94)`、枠は `rgba(255,255,255,0.14)`、角丸 10px、影は `0 8px 24px rgba(0,0,0,0.35)` 相当、余白 10px。
  - 文字は `#f3f5f8`、12px。
  - 角丸と影を出すため `AllowsTransparency=True` にする。
- **構成**（上から順に）
  1. 見出し：フォルダ名（太字、3行まで）。押すとアプリ内でそのフォルダへ移動する。ツールチップにはフルパスを出す。
  2. 件数：`📁 N  📄 M`（11px、太字、`#b9c3d3`）
  3. 本体：子項目の一覧（§9.4）。空なら「空のフォルダ」と出す。
- 読み込み中・エラーのときの表示は §9.8 のとおり。

### 9.4 一覧の行（P0）

```
│ [icon] 名前（1行で、はみ出したら…）        ▶ │   ← フォルダ
│ [icon] 名前.拡張子                          │   ← ファイル
```

- 行の高さは 24px 前後。左に 16px のシェルアイコン（小）、その右に名前を置く。フォルダの行は右端に ▶ を付ける。
- 行の間には `rgba(255,255,255,0.12)` の区切り線を引く。
- ホバー中の行は、背景を `rgba(255,255,255,0.16)`、文字を `#fff` にする。
- 子のフライアウトを開いているフォルダ行は、そのフライアウトを開いている間、選択状態の背景のままにする。
- ツールチップ
  - フォルダ：名前と「クリックでこのフォルダに移動」
  - ファイル：名前、サイズ、更新日時、「クリックで開く」
- アイコンは拡張子ごとにキャッシュする（`.exe` `.lnk` `.ico` などファイルごとにアイコンが違うものは、パスごとにキャッシュする）。
- 任意（P2）：フォルダへのショートカット（`.lnk`）を、フォルダ行として展開できるようにする。

### 9.5 フライアウトの配置（P0）

- **基準**：開いた行の、画面上の矩形。モニターは、その行が載っているモニターの作業領域（タスクバーを除いた領域）を使う。
- **横方向**
  1. 第2階層は、カードの右端 + 8px に出す（元アプリと同じ。オーバーレイの行ではなくカードの右端を基準にする）。第3階層からあとは、親フライアウトの右端 + 4px に出す。
  2. 右に入りきらなければ、左（カードや親の左端 − 8px / − 4px − 幅）に出す。
  3. 一度左に出したら、その先の階層も左向きを続ける（Windows のメニューと同じ）。左に入りきらなくなったら右へ戻る。
  4. 左右どちらにも入りきらなければ、作業領域に収まるように、親の上に 24px ずらして重ねる。
- **縦方向**：フライアウトの上端を、開いた行の上端 − 10px に合わせる。作業領域からはみ出すなら、内側に押し戻す。
- **DPI**：モニターごとに拡大率が違ってもずれないようにする。WPF の `Popup` は、`Placement=Custom` と `CustomPopupPlacementCallback` を使って、候補を「優先する向き → 反対の向き」の順に返すことを推奨する。実際にどちらの向きに出たかは、表示後の画面座標で判定し、子の階層に引き継ぐ。座標の変換方法は実装者が決めてよいが、拡大率の違う2つのモニターにまたがって確かめること（**未確認**：Custom 配置で Per-Monitor DPI が正しく扱われるか）。

### 9.6 開閉のタイミング（ホバーインテント）（P0）

| 名前 | 値 | 意味 |
|---|---|---|
| T_overlay | 300ms | カードにホバーしてからオーバーレイを出すまで |
| T_open | 150ms | フォルダ行に止まってから子のフライアウトを開くまで（元アプリのプレビューと同じ値） |
| T_grace | 300ms | 子を開いた行から離れても、子を閉じずに待つ時間 |
| T_exit | 300ms | カードとすべてのフライアウトの外に出てから、全部を閉じるまで |

規則：
1. 第 N 階層のフォルダ行 A に T_open の間止まると、A の子（第 N+1 階層）を開く。その前に開いていた第 N+1 階層から先は閉じる。
2. 行 A から子のフライアウトへ向けて斜めにポインタを動かす途中で、同じ階層の別の行を横切ることがある。そのため、ほかの行に移ってもすぐには子を閉じない。
   - 別の**フォルダ**行 B に T_open の間止まったら、A の子を閉じて B の子を開く。
   - **ファイル**行や余白に T_grace の間いたら、A の子を閉じる。
   - その間にポインタが A の子のフライアウトに入ったら、何もしない（開いたまま）。
3. カード、オーバーレイ、すべてのフライアウトのどれにもポインタがない状態が T_exit 続いたら、すべて閉じる。
4. 別のカードにホバーしたら、前のカードのカスケードはすぐに閉じる。
5. 次のときは、すべてすぐに閉じる。
   - グリッドのスクロール
   - カードサイズの変更
   - ウィンドウのサイズ変更や移動
   - タブの切り替え
   - 移動
   - メインウィンドウが非アクティブになったとき
   - アプリが非アクティブになったとき
   - WPF の Popup は最前面の別ウィンドウなので、非アクティブ化で閉じないとほかのアプリの上に残る（必須）。
6. Esc を押すと、いちばん深い階層を1つだけ閉じる。
7. メインウィンドウが非アクティブのあいだは、オーバーレイもフライアウトも開かない。背面に見えているウィンドウの上をポインタが通っても開かない。ウィンドウをクリックしてアクティブにしたあと、改めてホバーすれば開く。
8. 右クリックメニューを開いている間は、カスケードを閉じない。メニューを閉じたら、規則3の判定に戻る。
9. 任意（P2）：ポインタの動く方向から子へ向かっているかを推定する「安全三角形」で、規則2を改善する。

### 9.7 クリック（P0）

| 対象 | 左クリック | 右クリック |
|---|---|---|
| ファイル行 | 既定のアプリで開き（§12）、カスケードをすべて閉じる | 右クリックメニュー（§11） |
| フォルダ行 | アプリ内でそのフォルダへ移動し（§8.1）、カスケードをすべて閉じる | 右クリックメニュー |
| フライアウトの見出し | そのフォルダへ移動する | 右クリックメニュー |

- `Popup` は `StaysOpen=True` で使う。`StaysOpen=False` にするとマウスがキャプチャされ、ホバーの判定が崩れるため。閉じる処理は §9.6 で自分で管理する。
- カードやオーバーレイから Popup にポインタが移ると、カードの `MouseLeave` が発生する。ホバーの判定は、要素ごとの Enter と Leave をタイマーでまとめて行う。

### 9.8 状態の表示（P0）

| 状態 | 表示 |
|---|---|
| 読み込み中 | スピナーと「読み込み中…」 |
| 読み込みに5秒以上かかる | 「応答がありません（待機中…）」 |
| 空 | 「空のフォルダ」 |
| アクセス拒否 | 「アクセスが拒否されました」（文字色 `#fca5a5`） |
| 見つからない | 「見つかりません」（文字色 `#fca5a5`） |
| その他のエラー | 「読み込めません：<詳細>」（文字色 `#fca5a5`） |

### 9.9 キーボード操作（P1）

- オーバーレイやフライアウトを開いているときは、↑ ↓ で行を選び、→ でフォルダの子を開いて最初の行を選ぶ。
- ← で今の階層を閉じて親の行に戻る。Enter はクリックと同じ動作をし、Esc は §9.6 の規則6と同じにする。
- カードにフォーカスがあるときは、→ またはメニューキーでオーバーレイを開いてもよい（任意）。

## 10. タブごとの仕様

### 10.1 登録フォルダ（P0）

**最上位の画面**
- 登録した順にカードを並べる。サブ行にはフルパスを出す。
- 入力欄（プレースホルダー「登録するフォルダのパス（例: E:\写真\画像）」）、［登録］、［参照…］を置く。

**登録の規則（元アプリと同じ）**
1. 入力を整える。
   - 前後の空白を除く。
   - 両端の引用符（`" ' “ ” ‘ ’`）を、なくなるまで繰り返し除く（エクスプローラーの「パスのコピー」で付く `"` に対応するため）。
   - `%VAR%` の環境変数を展開する（新規）。
2. 空なら「フォルダのパスを入力してください。」を出す。
3. 絶対パスでなければ「絶対パスで指定してください: <入力>」を出す（`Path.IsPathFullyQualified` で判定）。
4. `Path.GetFullPath` で正規化し、末尾の区切り文字を除く。ただし `E:\` のようなドライブのルートは、そのままにする。
5. フォルダがなければ「フォルダが見つかりません: <パス>」を出す。
6. 登録済みかどうかは、正規化したパスを大文字小文字を区別せずに比べて判定する（`StringComparer.OrdinalIgnoreCase`）。登録済みなら追加せず「登録済み」と数える。
7. 新しく登録したら、ID（ランダムな 12 桁の16進数）と `added_at`（UTC、ISO 8601、秒まで）を付けて、末尾に追加する。

**複数登録**
- ［参照…］では `Microsoft.Win32.OpenFolderDialog` を `Multiselect=true` で使い、複数のフォルダをまとめて登録できるようにする。
- 結果は「N 件登録しました。M 件は登録済みです。<エラー>」の形でまとめて出す。
- 何も選ばなかったら「フォルダは選択されませんでした。」を出す。

**ドラッグ＆ドロップ（P1）**
- エクスプローラーから最上位の画面へフォルダをドロップしたら登録する。ファイルが含まれていたら無視し、その件数をメッセージに出す。

**登録解除**
- ×か右クリックメニューから実行する。確認ダイアログを出す。
  - タイトル：「登録を解除しますか？」
  - 本文：「一覧から外すだけで、フォルダやファイルは削除されません。」
  - 対象のパス（等幅フォント）
  - ボタン：［登録を解除］［キャンセル］
- 解除したら「「<名前>」の登録を解除しました。」を出す。

**表示名**
- パスの最後の部分を表示名にする。ドライブのルートならパス全体にする（例 `E:\`）。

**並べ替え（P2）**
- ドラッグで並べ替えられるようにする。P0 では登録した順に並べる。

### 10.2 最近の履歴（P0）

**データ元（2つをマージする）**
1. **Windows の「最近使った項目」**
   - `%APPDATA%\Microsoft\Windows\Recent\*.lnk` を読む（サブフォルダの `AutomaticDestinations` などは読まない）。
   - `.lnk` を更新日時の新しい順に並べ、上位300件までを対象にする。
   - リンク先のパスは `IShellLinkW` と `IPersistFile` で取り出す。リンク先を探す処理（`Resolve`）は呼ばない（遅く、UI を出すことがあるため）。取り出したパスの環境変数は展開する。
   - ファイルシステムのパスにならないもの（シェルの仮想フォルダなど）は除く。
   - `.lnk` の更新日時を、最後に使った日時とみなす。
   - 設定（§14）の「Windows の最近使った項目を含める」が OFF なら読まない。
2. **アプリの利用記録**（§10.4）の各項目の `last_opened_at`

**マージの規則**
- キーは、正規化したパスを大文字小文字を区別せずに比べたもの。同じ項目が両方にあれば、新しい方の日時を採る。
- 除外リスト（下記）とクリア日時（下記）で絞り込む。
- 存在しない項目は除く。存在の確認はバックグラウンドで行い、1件あたり1秒で打ち切る（UNC パスやネットワークドライブ対策）。打ち切った項目は表示したままにする。
- 新しい順に並べ、上位を表示する（既定 100 件。設定で変更できる）。

**表示**
- カードはフォルダとファイルが混ざった状態で並ぶ。サブ行は §6.2 のとおり。
- 更新するのは、タブを表示したとき、F5 を押したとき、このアプリで何かを開いたとき。Recent フォルダを `FileSystemWatcher` で見張るのは任意。

**除外（×）**
- `excluded.json` に `{ path, excluded_at }` を追加し、その項目を一覧から消す。
- 除外した後、その項目の最後に使った日時（どちらのデータ元でも）が `excluded_at` より新しくなったら、再び表示する（もう一度使えば戻る）。
- Windows の `.lnk` は**削除しない**。アプリの利用記録も消さない（よく使う項目のスコアは残る）。

**履歴をクリア**
- 最上位のツールバーに［履歴をクリア］ボタンを置き、確認ダイアログを出す。
  - 本文：「この一覧を空にします。ファイルや Windows の履歴は削除されません。」
- 実行したら `settings.json` の `recent_cleared_at` を今の時刻にし、それより前に使った項目を表示しないようにする。Windows の `.lnk` もアプリの利用記録も消さない。

**Windows 側の記録が無効なとき**
- Windows の設定で「最近開いた項目を表示する」が OFF だと、Recent フォルダは更新されない。
- そのときは、一覧の上に「Windows の設定で最近使った項目の記録が無効になっているため、このアプリで開いた項目だけを表示しています。」と出す。
- 判定にはレジストリの `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced` の `Start_TrackDocs`（0 なら無効）を使う（**推定**。Windows 10 と 11 で確かめる）。

### 10.3 よく使う項目（P0）

**データ元**
- アプリの利用記録（§10.4）と、ピン留めの一覧（`pins.json`）

**スコア（必須。この式のとおりに実装する）**

```
w(経過日数) = 100  （ 4日以内）
            =  70  （14日以内）
            =  50  （31日以内）
            =  30  （90日以内）
            =  10  （それより前）

score = (open_count / len(recent_opens)) × Σ_{t ∈ recent_opens} w(now − t)
```

- `recent_opens` は、直近の利用日時（新しい順に最大10件）。`open_count` は、これまでの利用回数の合計。
- スコアが同じなら、`last_opened_at` が新しい方を先にする。それも同じなら、パスの自然順にする。
- 経過日数の比べ方：`now − t` を日単位の実数として比べる（境界は「以下」で判定する）。
- `recent_opens` が空のとき（データが壊れているなど）は、スコアを 0 にする（0 で割らない）。

**表示順**
1. ピン留めの項目を、ピン留めした順（`pinned_at` の古い順）に並べる。カードの左上に 📌 を出す。
2. 続けて、ピン留めしていない項目をスコアの高い順に、上位 50 件（設定で変更できる）並べる。
3. 存在しない項目は除く（ピン留めの項目も除く。ただしピンの記録は消さず、存在するようになれば再び表示する）。

**ピン留め**
- 全タブのカード、オーバーレイの行、フライアウトの行の右クリックメニューから、ピン留めと解除ができる。
- 登録フォルダとは別の機能である。登録フォルダは「たどる起点」で、ピン留めは「よく使う項目の先頭に固定するもの」。

**×**
- ピン留めの項目なら、ピン留めを外す（スコアが十分高ければ、ランキングの方に残る）。
- ピン留めしていない項目なら、その項目の利用記録（`history.json` のエントリ）を削除し、一覧から外す。最近の履歴からも、アプリ由来の分は消える。Windows 由来の分は残る。

**統計のリセット**
- 設定（§14）の［よく使う項目の統計をリセット］で、確認のうえ `history.json` の利用記録をすべて削除する。ピン留めは残す。

### 10.4 利用記録（P0）

**記録するとき**
- ファイルを開いたとき（ShellExecute が成功したとき）
- カード、オーバーレイの行、フライアウトの行、フライアウトの見出しからフォルダへ移動したとき（移動先のフォルダを記録する）
- 右クリックメニューの「エクスプローラーで表示」を実行したとき（対象の項目を記録する）

**記録しないとき**
- パンくず、↑、Backspace、戻る・進むでの移動
- アプリの起動時に前回の場所を戻したとき
- 登録フォルダのタブの最上位を表示しただけのとき

**記録する内容**
- `path`（正規化したパス）、`kind`（`file` か `folder`）
- `open_count` を +1 する。
- `last_opened_at` を今の時刻にする。
- `recent_opens` の先頭に今の時刻を加え、10件を超えたら古い方を捨てる。

**件数の上限**
- 利用記録は最大 2000 件。超えたら `last_opened_at` の古い順に捨てる。

**任意（P2）**
- 設定「開いたファイルを Windows の最近使った項目にも追加する」（既定 OFF）が ON なら、ファイルを開いたときに `SHAddToRecentDocs` を呼ぶ。

## 12. ファイルを開く・安全策

### 12.1 開く処理（P0）

- `Process.Start(new ProcessStartInfo(path) { UseShellExecute = true })` で開く（エクスプローラーでダブルクリックしたのと同じ動作）。作業フォルダは、そのファイルの親フォルダにする。
- 開いたら「<ファイル名> を開きました。」を出し、利用記録（§10.4）を更新する。
- 失敗したら、エラーを出す。
  - 関連付けがない（Win32 エラー 1155）：「このファイルを開くアプリが関連付けられていません。」
  - その他：「開けませんでした：<詳細>」
- 任意（P2）：関連付けがないときに「プログラムから開く」ダイアログを出す。

### 12.2 実行形式の確認（P0）

- ホバーからクリックするだけでプログラムが動いてしまわないよう、次の拡張子を開くときは確認ダイアログを出す（設定で OFF にできる。既定 ON）。
  - 対象：`.exe .com .bat .cmd .ps1 .vbs .vbe .js .jse .wsf .wsh .msi .msp .scr .cpl .hta`
  - 本文：「プログラムを実行しようとしています。<ファイル名> を実行しますか？」
  - ボタン：［実行］［キャンセル］
- このアプリは、ファイルの削除、移動、上書きを一切しない（§3.2）。

## 13. データの保存

### 13.1 保存場所（必須）

- `%LOCALAPPDATA%\FolderDeck\` に置く。

| ファイル | 内容 |
|---|---|
| `registered_folders.json` | 登録フォルダ |
| `history.json` | 利用記録 |
| `pins.json` | ピン留め |
| `excluded.json` | 最近の履歴の除外リスト |
| `settings.json` | 設定とウィンドウ・現在地などの状態 |
| `logs\app.log` | ログ。5MB を超えたら `app.log.1` に切り替える（1世代だけ残す） |

### 13.2 形式（必須）

文字コードは UTF-8（BOM なし）にする。読み込むときは BOM 付きも受け付ける。日時は ISO 8601（UTC、秒まで。例 `2026-11-21T01:23:45+00:00`）で書く。

**registered_folders.json**（imgtool と同じ形式）
```json
{
  "version": 1,
  "folders": [
    { "id": "3f9a1c0b7d2e", "path": "E:\\資料", "added_at": "2026-11-21T01:23:45+00:00" }
  ]
}
```

**history.json**
```json
{
  "version": 1,
  "items": [
    {
      "path": "E:\\資料\\2026\\見積\\A社_見積.pdf",
      "kind": "file",
      "open_count": 12,
      "last_opened_at": "2026-11-21T01:23:45+00:00",
      "recent_opens": ["2026-11-21T01:23:45+00:00", "2026-11-20T08:00:00+00:00"]
    }
  ]
}
```

**pins.json**
```json
{ "version": 1, "pins": [ { "path": "E:\\資料\\2026", "kind": "folder", "pinned_at": "2026-11-21T01:23:45+00:00" } ] }
```

**excluded.json**
```json
{ "version": 1, "excluded": [ { "path": "C:\\Users\\me\\Downloads\\a.zip", "excluded_at": "2026-11-21T01:23:45+00:00" } ] }
```

**settings.json**（主なキー。足りないキーは既定値で補う）
```json
{
  "version": 1,
  "window": { "left": 100, "top": 100, "width": 1280, "height": 800, "maximized": false },
  "last_tab": "registered",
  "locations": {
    "registered": { "root": "3f9a1c0b7d2e", "path": "2026" },
    "recent": { "root": "", "path": "" },
    "frequent": { "root": "", "path": "" }
  },
  "card_size": 200,
  "show_hidden": false,
  "confirm_executables": true,
  "include_windows_recent": true,
  "recent_limit": 100,
  "frequent_limit": 50,
  "recent_cleared_at": null,
  "add_to_windows_recent": false
}
```

### 13.3 書き込み方式（必須。元アプリと同じ）

- 同じフォルダの一時ファイル（`<名前>.<ランダム>.tmp`）に書いてから `File.Move(tmp, dest, overwrite: true)` で置き換える。失敗しても一時ファイルを残さない。
- 読み込みに失敗した（JSON が壊れている、形式が違う）ときは、元のファイルを `<名前>.broken-<UNIX秒>.json` に名前を変えて退避し、空のデータで続ける。そのことをメッセージ行に警告として出す。退避すらできないときは、そのファイルを使う機能を無効にしてエラーを出す（上書きして消さない）。
- 書き込みはスレッドセーフにする。アプリは単一インスタンス（§4.4）なので、別のプロセスとの競合は考えなくてよい。

### 13.4 imgtool からの取り込み（P1）

- 設定（§14）の［imgtool の登録フォルダを取り込む…］で、ファイル選択ダイアログから `registered_folders.json` を選ぶ。
  - imgtool の既定の場所は `<imgtool のリポジトリ>\app\backend\data\registered_folders.json`。
- 各パスを §10.1 の規則で登録する（ID は新しく振る）。
- 結果は「N 件取り込みました。M 件は登録済み、K 件は見つかりません。」の形で出す。
- 見つからないパスは登録しない。

## 15. テーマと見た目

### 15.1 ライトとダーク（P0）

- Windows の「アプリのモード」に合わせる。判定にはレジストリの `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize` の `AppsUseLightTheme` を使う。変更は `SystemEvents.UserPreferenceChanged` で受け取り、その場で切り替える。

- WPF の Fluent テーマ（`Application.ThemeMode`）は、.NET 10 で正式に使えるかが**未確認**。正式に使え、上の色と合わせられる場合だけ使ってよい（任意）。
- タイトルバーをダークにする処理（`DwmSetWindowAttribute` の `DWMWA_USE_IMMERSIVE_DARK_MODE`）は任意。

## 16. 非機能要件

| 区分 | 要件 |
|---|---|
| 応答性 | UI スレッドを 50ms 以上止めない（必須）。列挙、サムネイルの取得、存在の確認、`.lnk` の解決、JSON の読み書きはすべて UI スレッドの外で行う |
| 起動 | 起動してから最初の画面が出るまで 1.5 秒以内（ローカル SSD、登録 20 件）。サムネイルはあとから順に出てよい |
| 一覧の表示 | 1000 件の子項目があるフォルダに移動してから、カードの枠（サムネイルを除く）が出るまで 500ms 以内（ローカル SSD） |
| カスケード | 10,000 件のファイルがあるフォルダのフライアウトが、T_open の後 1 秒以内に出て、スクロールで引っかからない |
| メモリ | 1000 枚のカードを表示してスクロールし続けても、作業セットが 500MB を超えない（目安） |
| 耐障害性 | アクセスできないフォルダ、切断されたネットワークドライブ、壊れた `.lnk`、壊れた画像があっても落ちない。未処理の例外はログに書き、「予期しないエラーが発生しました」ダイアログを出す（`DispatcherUnhandledException`、`TaskScheduler.UnobservedTaskException`、`AppDomain.UnhandledException`） |
| ログ | 例外、起動と終了、データファイルの退避をログに書く。ファイルのパスは書いてよいが、ファイルの中身は書かない |
| 対応 OS | Windows 10 22H2 と Windows 11（x64） |
| 文言 | UI の文言はすべて日本語にする |

## 18. 受け入れ基準

### 18.1 登録フォルダとカード（Phase 1）
- **AC-01** `"E:\資料"`（両端に引用符あり）を貼り付けて登録すると、引用符が除かれて登録され、カードが末尾に出る。
- **AC-02** 同じフォルダを `e:\資料\` で登録しようとすると「登録済み」になり、2件目はできない。
- **AC-03** 相対パス、存在しないパス、空の入力は、それぞれ §10.1 の文言で拒否される。
- **AC-04** ［参照…］で3つのフォルダを選ぶと、3件まとめて登録され、結果がまとめて出る。
- **AC-05** 登録したフォルダの名前を変えると、そのカードは「見つかりません」になって開けない。登録解除はできる。
- **AC-06** 登録解除の確認で［登録を解除］を押すと一覧から消え、フォルダの中身はそのまま残る。
- **AC-07** アプリを再起動しても、登録内容、登録順、カードサイズ、タブ、現在地、ウィンドウの位置が戻る。
- **AC-08** `registered_folders.json` を壊した状態で起動すると `.broken-<UNIX秒>.json` に退避され、警告が出て、アプリは空の一覧で動く。
- **AC-09** フォルダのカードにフォルダ数とファイル数（画像以外も含む）が出る。隠しファイルと `.` で始まる名前は数えない。
- **AC-10** 画像を含むフォルダのカードには、深さ優先で最初の画像がサムネイルとして出る。画像がなければシェルのフォルダサムネイルかアイコン、ファイルのカードにはシェルのサムネイルかアイコンが出る。
- **AC-11** フォルダのカードを押すとアプリ内でその中に入り、フォルダのカードの後にファイルのカードが自然順で並ぶ（`2.txt` が `10.txt` より前）。
- **AC-12** ファイルのカードを押すと既定のアプリで開く。`.bat` は確認ダイアログが出て、［キャンセル］なら何も起きない。
- **AC-13** パンくず、↑、Backspace、マウスの戻る／進むボタン、Alt + ← / → で、§8 のとおりに移動する。
- **AC-14** スライダーと Ctrl + ホイールで、カードサイズが 120〜400 の範囲で 20 刻みに変わり、全タブに反映される。
- **AC-15** 5000 件のフォルダを表示しても、スクロールが引っかからない（仮想化が効いている）。

### 18.2 オーバーレイとカスケード（Phase 2）
- **AC-20** フォルダのカードにホバーして約 300ms 後に、サムネイル部分へ子項目の一覧（フォルダが先、ファイルが後、自然順）が重なって出る。フッターを押すとそのフォルダに入る。
- **AC-21** オーバーレイの上でホイールを回すと一覧だけがスクロールし、グリッドは動かない。
- **AC-22** オーバーレイのフォルダ行に止まると、約 150ms 後にカードの右へフライアウトが出て、そのフォルダの子項目が出る。
- **AC-23** 8階層の入れ子フォルダで、ホバーを続けるだけで8階層目のファイルまでたどり着け、押すと開く。
- **AC-24** 行からその子のフライアウトへ斜めにポインタを動かし、途中でファイル行を一瞬横切っても、子のフライアウトは閉じない。
- **AC-25** 画面の右端近くのカードでは、フライアウトが左に出る。一度左に出たら、その先の階層も左に出る。
- **AC-26** 拡大率の違う2つのモニター（例 100% と 150%）の境目付近で、フライアウトが作業領域の中に正しく出る。
- **AC-27** カードとすべてのフライアウトの外へポインタを出すと、約 300ms 後に全部閉じる。Esc を押すと、いちばん深い階層が1つずつ閉じる。
- **AC-28** 別のアプリへ Alt + Tab で切り替えると、フライアウトがすべて閉じ、ほかのアプリの上に残らない。
- **AC-29** フライアウトのフォルダ行を押すと、アプリ内でそのフォルダへ移動し（起点はカードの項目、相対パスは押した位置まで）、パンくずに反映される。
- **AC-30** アクセス拒否のフォルダ、空のフォルダ、10,000 件のフォルダ、260文字を超えるパスのフォルダで、§9.8 のとおりに表示され、固まらない。
- **AC-31** 右クリックメニューの「エクスプローラーで表示」「パスをコピー」が、カード、オーバーレイの行、フライアウトの行のどこからでも動く。

### 18.3 最近の履歴とよく使う項目（Phase 3）
- **AC-32** エクスプローラーでファイルを開くと、更新したあとの「最近の履歴」に出る（Windows の記録が有効な場合）。
- **AC-33** このアプリでファイルを開いたりフォルダへ移動したりすると、「最近の履歴」の先頭に出る。同じ項目が Windows 側の記録にもあっても、重複して出ない。
- **AC-34** 「最近の履歴」の×で項目が消え、その項目をもう一度開くと再び出る。Windows の Recent フォルダの `.lnk` は消えない。
- **AC-35** ［履歴をクリア］で一覧が空になり、そのあとに開いたものだけが出る。「よく使う項目」の順位は変わらない。
- **AC-36** 「よく使う項目」の並びが §10.3 の式どおりになる（Core のユニットテストで、時刻を固定して確かめる）。
- **AC-37** ピン留めした項目が、ピン留めした順に先頭へ 📌 付きで出る。どのタブの右クリックメニューからでもピン留めと解除ができる。
- **AC-38** 「よく使う項目」の×で、ピン留めの項目はピンだけが外れ、ピン留めしていない項目は統計が消えて一覧から外れる。
- **AC-39** パンくず、↑、戻る・進むでの移動は、利用記録に残らない。

### 18.4 共通・非機能（AC-42 は Phase 4、それ以外は Phase 1）
- **AC-40** exe を2回起動すると、2つ目は起動せず、既存のウィンドウが前面に出る。
- **AC-41** 切断されたネットワークドライブのフォルダを登録していても、起動と操作が固まらない（カードは「応答がありません」になる）。
- **AC-42** Windows のダーク／ライトを切り替えると、アプリの配色がその場で切り替わる。
- **AC-43** `dotnet.exe test` で Core のテストがすべて通る。
- **AC-44** `dotnet.exe publish`（§4.5）で single-file の exe が作られ、.NET を入れていない環境でも起動する。

### 18.5 仕上げ（Phase 4）
- **AC-45** キーボード操作（§9.9）だけで、カスケードをたどってファイルを開ける。
- **AC-46** 設定ダイアログの各項目が §14 のとおりに働き、保存される。
- **AC-47** imgtool の `registered_folders.json` を取り込むと、§13.4 の形式で結果が出る。
- **AC-48** エクスプローラーからフォルダをドロップすると登録される。
- **AC-49** 隠しファイルを表示する設定を ON にすると、カードの件数、一覧、フライアウトに隠しファイルが出る。

## 19. ビルド・テスト・検証の手順

### 19.1 前提となる環境（確認済み）

- 開発は WSL（Ubuntu 24.04）の bash から行う。
- Windows 側に次のものが入っている。
  - .NET SDK 10.0.112（`C:\Program Files\dotnet\sdk`）
  - Visual Studio Build Tools 2022
- WSL 側に .NET SDK は入っていない。`dotnet.exe`（Windows 側）を使う。

### 19.2 コマンド

- リポジトリは **Windows 側のドライブ**（例 `E:\dev\FolderDeck`）に置く。WSL の ext4 上（`\\wsl$\...`）では、dotnet.exe のビルドが失敗したり遅くなったりするため。
- WSL からは `/mnt/e/dev/FolderDeck` で操作する。

```bash
cd /mnt/e/dev/FolderDeck
dotnet.exe build FolderDeck.sln -c Debug
dotnet.exe test tests/FolderDeck.Core.Tests -c Debug
dotnet.exe run --project src/FolderDeck.App          # 起動（Windows のデスクトップに出る）
dotnet.exe publish src/FolderDeck.App -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

### 19.3 検証用のフォルダツリー（`tools/make-fixture.ps1`、Phase 1）

引数で出力先を受け取り、次のものを作る（既存のフォルダは消さず、出力先がすでにあれば止める）。

- 8階層の入れ子フォルダ。各階層にフォルダ2つとファイル3つ（`.txt`、`.pdf` 風のダミー、`.xlsx` 風のダミー）を置く。
- 子項目が 10,000 件のフォルダ（ファイル名は `file_1.txt` 〜 `file_10000.txt`。自然順の確認用）
- 子フォルダが 5,000 件のフォルダ
- 260文字を超えるパスになる入れ子フォルダ
- 日本語、空白、絵文字、`&`、`%` を含む名前
- 隠し属性のファイル、システム属性のファイル、`.` で始まるファイル
- 自分自身の親を指すジャンクション（循環の確認用）
- 画像を含むフォルダ、画像を含まないフォルダ、6階層より深い所にだけ画像があるフォルダ（画像は小さな PNG を作る）
- 実行形式の確認用 `test.bat`（中身は `echo test` だけ）
- アクセス拒否のフォルダ（`icacls` で自分の読み取りを拒否する。解除するコマンドも出力する）

### 19.4 ユニットテスト（Core。必須）

- 入力の正規化（引用符を繰り返し除く、空白、環境変数、ドライブのルート、末尾の区切り）
- 登録済みの判定（大文字小文字、末尾の区切り、`.` や `..` を含むパス）
- 自然順の並べ方とフィルタ（隠し、システム、`.` で始まる名前）
- カバー探索（深さの上限、64フォルダの上限、リパースポイントを飛ばす）
- JSON の保存（読み書きの往復、BOM 付き、壊れたファイルの退避、一時ファイルを残さない）
- 最近の履歴のマージ（重複、除外と再表示、クリア日時、上限の件数）
- よく使う項目のスコア（重みの境界：4 / 14 / 31 / 90 日、同点のときの順、ピン留めの順、存在しない項目の除外）
- 利用記録（`recent_opens` は最大10件、全体は最大 2000 件）

### 19.5 GUI の検証

- GUI は、ユーザーが手で確かめるのが基本。フェーズごとに、§18 の受け入れ基準を手順にしたチェックリストを報告に付ける。
- `agent-desktop`（WSL から Windows のデスクトップを操作する CLI）で GUI を操作して確かめてよいのは、**ユーザーが明示的に許可したときだけ**。

## 付録B　元アプリからの変更点

| 項目 | 元アプリ | 新アプリ |
|---|---|---|
| 形態 | FastAPI + React（ブラウザで使う） | WPF のネイティブアプリ（バックエンドなし） |
| タブ | プレビュー（outputs）／登録フォルダ ほか | 登録フォルダ／最近の履歴／よく使う項目 |
| カードの件数 | フォルダ数と画像の枚数 | フォルダ数とファイル数（種類を問わない） |
| フォルダの中に並ぶもの | サブフォルダのカードと「このフォルダの画像」カード | サブフォルダのカード、続けてファイルのカード（「このフォルダの画像」カードは廃止） |
| カードのクリック | サブフォルダがあれば入る、画像だけなら最初の画像を開く、空なら無効 | フォルダなら入る（空でも入れる）、ファイルなら開く |
| ホバー（第1階層） | サブフォルダ名だけの一覧（最大 500 件） | フォルダとファイルの一覧（件数の上限なし、仮想化） |
| ホバー（第2階層） | フォルダ名（最大 15 件）と最初の画像のプレビュー（操作できない） | 操作できるフライアウト。ファイルの一覧を出し、何階層でもたどれる |
| サムネイル | Pillow で WebP を作り、ディスクにキャッシュ | Windows のシェルサムネイル（thumbcache）とメモリ上の LRU |
| カバーがないとき | 📁 / 🖼 の絵文字 | シェルのフォルダサムネイルかアイコン |
| ファイルを開く | バックエンドの `os.startfile`（画像だけ） | ShellExecute（すべてのファイル。実行形式は確認する） |
| 保存場所 | `app/backend/data/registered_folders.json` | `%LOCALAPPDATA%\FolderDeck\registered_folders.json`（同じ形式。取り込める） |
| 状態の保存 | ブラウザの localStorage | `settings.json` |
| 新機能 | ― | 最近の履歴、よく使う項目、ピン留め、右クリックメニュー、エクスプローラーで表示、単一インスタンス |
